## 第一阶段：找到核心数据真实权威与现有备份（优先读证，不重复开发）

1. 从已核验的生产运行配置、SQL 表清单、安装态 `PublicationStore`/Source Reader、已存在的备份作业及恢复清单识别当前**实际启用**的数据权威；只记录类别、来源、数据量、文件/表数量、最近备份时间、备份验证记录，不在公开报告输出用户目录、成绩正文、凭据、数据库口令。
2. 必须覆盖的恢复域（按实际存在与依赖裁决）：Viewer 账户与会话/授权撤销状态、账号绑定及来源与 QQ 映射、当前已提交成绩及 Publication manifest（sequence/commitId）和被引用的 immutable objects、full/delta 历史、实际启用的 Growth 观察/事实/历史 measurement、Goal 及其模型或修订身份。其他真实活跃的 Source/Bot 数据权威若是恢复所必需，也应登记；不能因路径不在 Viewer 工作目录就漏掉。
3. 通过实际部署证据确认上述数据是在 MySQL、Publication 文件/对象库还是两者；不得假设所有业务行在单个 `userdata` JSON，也不能仅按用户目录拷贝“最新 JSON”。
4. 检查是否存在**其他有效的已加密备份**，若已有包含上述数据且能在隔离环境恢复，则直接复用，跳过新建备份系统。否则进入第二阶段。先估算备份净数据大小、临时空间和恢复目标空间；不要污染 `/var/tmp`，也不要因备份耗尽系统盘。保留本次 0.81.12 原始 release 完整性。

## 第二阶段：最小但一致的生产恢复点

1. 优先利用现成的 DB 一致性备份工具及 Source/Publication 已审计的快照机制，不另建 Writer 或“恢复平台”。备份包括实际 SQL schema、索引、必要业务行与权限撤销状态，以及对应的 Publication 完整代际向量和对象引用；带 UTC 检查点、各源 identity、commitId/sequence、对象 hash 与备份清单版本。
2. **跨 MySQL 与文件源必须有一致性保证。** 使用现有经验证的写入锁/安全维护短窗口（含自动释放及异常恢复）协调所有可影响这些域的 Writer，等待读写事务结束后采集 SQL 一致快照与 Publication 向量；或使用已经证明等价的跨源检查点协议。禁止“一边不停写，一边独立 mysqldump + cp”然后宣称同点恢复。若无法建立安全检查点，停止并只报告这一具体技术障碍。
3. 现有 `taiko_viewer/server/infrastructure/taiko-publication/client.ts` 的 `backup(backupKey)` 可能在 legacy sequence=0 时收编旧字节并更新 lease 的 view，**不能假设它是纯只读全站备份接口**；先确认其适用范围、副作用与独占锁语义，必要时使用更合适的已批准快照/备份路径，禁止直接对生产所有身份盲调用。
4. 将备份写入权限隔离的独立目的地（`0700`、原子完成标记、逐项 SHA-256、受控密钥加密），尽量使用不同磁盘/异机，不把含私有成绩、凭据、SQL 行的明文备份存进 Git、公开报告或 QA 证据库。失败/中断的备份不能覆盖上一份已验证恢复点；旧数据和旧生产服务保持不变。
5. 只要求当前 P-A 可执行的**一个真实、足够新的、一致且可恢复的业务检查点**。额外的持续 PITR、RPO≤15分钟/RTO≤120分钟全规模证明、四张新 Grant 表和外部 API 撤销连续性仍属后续生产可靠性/P-C，不因为未完成而自动阻断旧模式代码更新。若既有业务本身要求更严格的备份频率，继续保留该要求，不用一次性备份取代正常备份制度。

## 第三阶段：真实恢复，而不是检查文件是否存在

在**新建独立**的恢复数据库与文件/对象根执行，不连接生产 Writer，不让恢复实例暴露公网：

- 恢复 SQL schema、账户/绑定及关键权限状态，恢复至少一个有当前成绩＋full/delta 历史＋冻结 measurement/Goal 的有代表性账号；对大型来源按可恢复的完整检查点证明其余对象/文件闭包及 hash，不需要重算 Annual。
- 重新打开恢复后的 Publication ReadView，核对 sequence/commitId、current/history、引用对象 hash、正确来源和 binding；对缺对象、混代、错误 owner/source 强制失败。禁止使用旧生产数据目录做测试或“演练后回写”。
- 验证合法 Session/owner 可读取、跨账户不可读取，已撤销或禁用的原有 Token/授权不会从旧快照意外复活。若恢复点后存在无法完整重放的撤销事件，恢复路径必须 fail closed 并要求重新认证，不声称保留旧授权。
- 记录备份点时间、完成时间、恢复耗时、文件数/字节数/hash 校验、采样业务场景结果、校验异常和处理结果；这些记录可脱敏公开，不得包含用户正文或密钥。
- 验证备份作业后续可持续执行、保留最新成功点且不会因为一次失败清掉旧恢复点。单次实际恢复 PASS 是 P-A 的最低证据，不得冒充异地容灾/PITR/RPO/RTO 全面达标。
