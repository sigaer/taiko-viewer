# Dan Strength Model V2 Audit（只读：未改 generator / locale / schema / 45-key model / Viewer，未部署）

## 0. Canonical mark semantics 与上一轮报告更正

| mark | 语义 | 是否 achievement |
|---|---|---|
| 0 | 未合格 | 否 |
| 1 | 赤合格 | **是** |
| 2 | 赤合格+全连（金粹） | 是 |
| 3 | 赤合格+全良 | 是 |
| 4 | 金合格 | 是 |
| 5 | 金合格+全连（金粹） | 是 |
| 6 | 金合格+全良 | 是 |

**read_dan_state 没有误读。** `_COMPLETION_TABLE` 只把 `mark0` 判为 none/未合格，`passed = [dan_id for dan_id, mark in marks.items() if mark >= 1]`、`attained_dan = max(passed)`、`best_mark` 同样 `mark >= 1` —— 生成器一直把 mark1（赤合格）当作有效 achievement。

**错的是上一轮审计脚本**：V1 自行加了 `mark >= 2` 过滤，才得出「932 人 best 变成未合格」「population = 822」等结论，这些数字**全部废弃**。V2 改为 `mark >= 1` 后实测：1259 个有段位记录的账号中，含 mark≥1 记录者 **1259**，仅有 mark0 者 **0**。

另外两处更正：

1. 上一轮「A/B 在玄人以上相同」是错的（BASE_A 达人 3.26 vs BASE_B 2.90，七段起就不同）。V2 改为**同一 danBase + 两条 completion bonus 曲线**，两方案差异只来自 bonus。
2. 上一轮「九段 mark4 = 1.89 > 八段 mark6 = 1.76 却标记 FAIL」是**断言渲染错误**（lhs/rhs 套错并混用了 A 方案数值），不是模型错误。V2 的约束检查直接由脚本比较数值。

## 1~5. 新模型结构

### completionBonus：两条非等距曲线（含全部 mark 间增量）

| mark | Curve X | X 增量 | Curve Y | Y 增量 |
|---|---|---|---|---|
| 1 赤合格 | 0.05 | — | 0.04 | — |
| 2 | 0.09 | +0.04 | 0.08 | +0.04 |
| 3 | 0.13 | +0.04 | 0.12 | +0.04 |
| 4 | 0.29 | +0.16 | 0.20 | +0.08 |
| 5 | 0.34 | +0.05 | 0.25 | +0.05 |
| 6 | 0.37 | +0.03 | 0.29 | +0.04 |

- **Curve X（gold-pass jump）**：`4-3 = +0.16` 远大于 `5-4 = +0.05`，`6-5 = +0.03` 保持很小 —— 金合格本身是跃升，金粹/全良只是加成。
- **Curve Y（平滑）**：0.04/0.04/0.08/0.05/0.04，金合格跃升被压平，各 mark 接近等距。
- 两者都满足同段位 `mark6>5>4>3>2>1`，且金系恒高于对应赤系（4>1、5>2、6>3）。

**不再使用「completion spread < 最小 dan step」作为全局硬约束**：V1 那条会推出「higher dan red pass 必然 > lower dan gold full good」，产品未确认，V2 只保留九段起的产品硬约束，red-pass 那一族单独列出（6.3 节）。
