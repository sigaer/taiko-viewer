## 2. 两个概念（本次审计采用的区分）

- **ObservedDanEvent**：快照能证明 before→after 变化的事件（`dan_mark_progress` / grade 晋升）。
  受快照覆盖率与 window 起点限制，存在 left-censoring。
- **CurrentVersionDanAchievement**：当前版本 `levelList` 中实际存在的完成结果
  （dan + mark，`source=dojo`）。因为段位成绩随版本更新重置，这**不能**自动等同于
  archive/history，但也不应被当作「无 achievement」丢弃。

### 3.1 是否存在明显的 snapshot left-censoring

**存在，而且量级明显。** 仅靠 observed event 只能识别 26 人（占 1405 的 1.85%），
而当前版本 standing 达到同一 0.55 门槛的有 134 人（9.54%）——**约 5 倍差距**，其中 108 人
在现有规则下完全没有强段位呈现。原因有两类：

1. **分数早于 window 就已完成**：段位成绩随版本重置，但这些账号的 dan 成绩是在年度 window
   开始前（或快照覆盖开始前）就取得的，window 内快照只反映 already-standing；
   例如 `49557999`（Viewer user 598）：3 个在 window 内的快照，最强 ten-dan mark5 自第一个
   快照起就存在，因此没有任何 before→after 证据，现有规则下 event=false。
2. **快照采样不足**：mark 提升发生在两次快照之间时，`mark_events` 看不到 before 状态。

反向也有一例（不是 censoring，而是「事件弱于 standing」）：`40500773` 的事件是 window 内真实发生的
十段 4→5，但 standing 已经到 达人 mark6，事件严重度反而更低。

### 3.2 新规则会影响多少用户

- 门槛（strongDan = observed 事件达标 OR 当前版本 best severity ≥ 0.55）本身：**26 → 134 人**（+108）
- 呈现选择改为「severity 更高者胜」后：**111 人**的最终 presentation 会变化
  - 其中 108 人是从「无强段位呈现」变成有（`dan_standing_*` 走强段位呈现）
  - 其中 3 人是从较弱事件切换为更强的当前版本成绩
- 其余 23 位 event=true 的账号（版本 best == 事件）presentation 不变

### 3.3 文案资源检查（只读）

134 位达标账号所需的呈现文案**都已存在**（zh/ja 键集合一致，无缺口）：

- 标题：`danPresentation.{dan_kanzui_gold,dan_kanzui_red,dan_fullgood_gold,dan_fullgood_red,dan_gold_pass,dan_major_progress}.title`
- 证据行：`finalEvidence.templates.{同名}`，例如 `{dan} · 金合格全良`
- 现有 `dan_standing_*` 模板带「**已有段位成果**」字样——按本轮规则，version standing 胜出时应改用
  纯事实模板（`{dan} · {完成档}`），即复用同名强段位模板；这会移除「已有段位成果」措辞，
  且不新增「今年取得 / 年内达成」这类需要 window 证据的说法。
