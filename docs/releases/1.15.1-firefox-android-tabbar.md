# Android Firefox TabBar 兼容候选（1.15.1）

状态：本机代码 / 自动化验证通过，PR 候选；**Android Firefox 真机 Gate 待验收，不合并 main、不创建 Release、不部署生产**。

## 基线和范围

从最新 `origin/main` 的 `7ad6c69006ed2e437b31d0eb101708739ea3c565`（生产 Viewer 1.15.0）创建 `fix/firefox-android-bottom-nav-jitter`，使用独立 worktree，原工作区的 `docs/random-dan/`、`scripts/dojo/` 未改动。package / lock 的补丁候选版本均为 1.15.1；生产仍是 1.15.0。每日称号、活动图片/配置/中日文文案及历史撤回审计未修改。

用户确认：Android Firefox，顶部地址栏自动收起/展开的过程中，底部 TabBar 上下抖动。Mozilla 在 [1797964](https://bugzilla.mozilla.org/show_bug.cgi?id=1797964) 和 [1921331](https://bugzilla.mozilla.org/show_bug.cgi?id=1921331) 描述了同类问题：顶部动态工具栏移动整个 GeckoView，网页合成与原生视图的位移不同步。本站原先的 `position: fixed; bottom: 0` 与这一触发条件匹配；这是有上游证据支持的原因推断，**本机未重现真实 GeckoView 的合成过程**。

本候选按负责人指定方案改变 Android Firefox 手机 Shell 的滚动所有权，不宣称修好了 Firefox 引擎。没有修改业务 API、数据库契约、账号、成绩或同步行为。社区及图片查看器的改动仅替换滚动位置读取、恢复与锁定对象。

## 实现

- `utils/firefox-android.mjs`：独立 UA 检测（Android + Firefox，排除 iOS Firefox / Edge 等），以及可测的键盘视口计算。
- `plugins/firefox-android.ts`：SSR 输出共享的同步 head bootstrap，在 SSR body 绘制前添加 `html.firefox-android`；客户端使用相同检测并让 Unhead 管理该 class。Vue 的 SSR / hydration 组件树相同，没有按客户端 UA 改写初始 VNode。滚动恢复在 Nuxt 初始路由安装完成后挂载。
- `assets/css/ds/firefox-android.css`：所有规则限制于 `html.firefox-android` 且宽度不超过 767px。Shell 为固定视口 Flex Column，顶部栏 / 二级导航在布局中，主内容区 `flex:1; min-height:0; overflow-y:auto`，TabBar 为 `position:static; flex:0 0 auto`。
- `components/rework/Shell.vue`：标记默认 Shell 的根节点所有权，并提供主内容区与 TabBar 之间的 composer dock。根文档的 overflow 锁只在该 Shell 存在时生效；独立 story 布局不继承该根锁。
- 保留底栏现有 `env(safe-area-inset-bottom)` padding；移除 Firefox 主内容区原本为 fixed TabBar 预留的额外空间，以及 thread 页为 fixed 回复框保留的重复留白。歌曲详情 sticky 难度栏改为贴合内部滚动区。
- `composables/useFirefoxAndroidShell.ts`、`components/rework/community/ReplyBox.vue`：只在 hydration 完成后的 Firefox 手机模式下，将回复框 Teleport 到 Shell dock，处于 TabBar 上方。离开 KeepAlive thread 时移回缓存树，避免旧回复框留在其他页面；其他浏览器保持原 DOM 位置。
- `layouts/default.vue`：普通浏览器继续原有键盘检测。Firefox 手机模式额外兼容 layout viewport 也缩小的情况，防止普通地址栏尺寸变化和 pinch zoom 被当作键盘；只有确认键盘打开时才用 VisualViewport 高度 / offsetTop 调整 Shell 可见区域。**不在滚动中改 TabBar bottom，不增加固定像素补偿。**
- `utils/viewer-scroll.ts`：Firefox 手机 Shell 使用 `.rework-main`，其他浏览器使用原有 window；`pages/forum/index.vue`、`pages/forum/thread/[id].vue`、`components/forum/ForumMediaViewer.vue` 使用该桥接读取、保存、恢复 / 锁定滚动。
- `utils/firefox-scroll-restoration.ts`：保留 Nuxt 原 scrollBehavior 的页面加载 / 过渡等待；只在 Firefox 手机 Shell 内消费其结果。按 history position + fullPath 保存最多 60 个条目，覆盖 push / pop / refresh / hash；异步内容恢复等待最多 2 秒，用户交互立即取消。sessionStorage 拒绝或损坏时不阻断导航；有清理逻辑。
- Element Plus：body 的 popup lock 同时锁住 Firefox 主滚动区；仅 Firefox 手机模式约束长称号 select popper 宽度。原生搜索 Dialog 和成绩编辑 Dialog / Select 的定位、关闭与恢复纳入专项验收。现有 Drawer 用于独立 story 页面，原布局不修改；真实设备弹层与软键盘交互仍需验收。
- `nuxt.config.ts` 仅添加兼容 CSS；`package.json` / `package-lock.json` 同步 1.15.1，增加专项单元测试命令。现有 GitHub CI 增加专项单元测试文件，没有新建基础设施流水线。
- `tests/firefoxAndroidShell.test.mjs`、`scripts/rework/firefox-android-scenarios.mjs`：专项单元 / DOM / CSS / 浏览器导航测试；复用现有 Stage 账号、成绩与社区 fixture。`shell-check.mjs` / `shell-sql.mjs` 只增加 `--check=firefox` 分支，复用原有 Nitro、隔离数据库、TLS、浏览器和 finally 清理。
- `tests/communityReadingSurface.test.mjs`：仅把图片查看器的 window 滚动断言更新为滚动桥接断言，不删除断言。

## 真机 Gate（合并前）

准备 Android Firefox 与同一设备上的 Chrome。记录机型、Android 版本、浏览器完整版本、工具栏布局、字号 / 缩放、普通标签页还是 PWA。仅使用专用测试环境 / 账号；不在生产做重复的成绩、同步或社区写入。

1. Firefox 顶部地址栏完全展开后打开候选首页，检查首次渲染无错位、底栏贴底和安全区域；分别测短页与长页。
2. 首页、曲库、歌曲详情、个人档案、社区各连续上滑 / 下滑 10 次；记录顶部地址栏是否仍会自动收起 / 展开、底栏是否抖动、是否出现空隙或点按错位。录屏必须包含地址栏及底部系统导航区域。
3. **独立记录地址栏行为变化**：根文档不再滚动可能改变自动收放。不能将“地址栏不再收放”默认当作体验完全相同；真实行为及是否可接受须在 Gate 结果中写明。
4. 在长曲库页滚动，进入歌曲详情，再浏览器后退 / 前进；检查滚动位置、筛选 query、sticky 难度栏。刷新后位置正确。重复访问同一 URL 的不同历史条目也要恢复各自位置。
5. 个人档案点击目录跳转，确认标题不被遮挡；打开长称号 Select、成绩编辑 Dialog、已有 Drawer / Popover 入口，确认弹层在视口内、滚动锁和关闭后位置正确。
6. 社区打开长 thread：回复框始终在 TabBar 上方；聚焦输入框，弹出实际软键盘，输入中日文、换行、切换输入法，展开和关闭附件预览，收起键盘。确认 TabBar 仅在合适状态隐藏 / 恢复，回复框 / 发送按钮可达且无重复留白。切换另一个输入框、旋转屏幕、退出 thread 后再返回。
7. 验证长列表 / 图片惰性加载、末尾内容可达、没有 body 与内部主内容区双重滚动；搜索 Dialog 打开 / 关闭、浏览器返回和路由切换均不留旧回复框或滚动锁。
8. 同一 Android 设备以 Chrome 重复上述核心步骤，确认原来的整页滚动、固定底栏及地址栏行为保持；iOS Safari / 桌面 Firefox 做基本对照，不能用 UA 模拟代替。

必须等待真机的结论：原抖动是否消失、GeckoView 自动收放行为是否改变、真实 IME / VisualViewport / 触摸坐标、安全区、缩放和旋转，以及同设备 Chrome 对照。真机 Gate 未通过之前保持 PR 待验收，不合并、不发布。
