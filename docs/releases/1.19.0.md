# 1.19.0 — 后台称号条件管理与登录等待优化

后台新增“称号条件”，可搜索官方称号、只看条件未知的条目，查看对应底板及来源，编辑获取条件。条件保存在现有称号服务：仅补丁更新本地行的 condition，保持名称、底板、关联歌曲和本地 ID；缺失资料时按官方名称和底板补建本地行，绝不将官方 ID 当成本地行 ID。留空恢复官方条件，保存前检查当前条件和身份，阻止重名歧义、旧版本覆盖和本进程同条记录并发保存。写入无自动重试，保存后读回核对并记录审计；审计失败会说明条件已经保存，避免误认为已回滚。现有每日同步仅合并歌曲 ID，保留人工条件。

名称及底板用于区分官方目录的同名称号。前端保存期禁用重复操作，冲突后保留未保存文字。没有内容变化时不写入、不新增冗余本地记录。外部称号服务不提供版本比较写入，来自其他实例/独立写入端的检查后并发窗口仍取决于该服务；本次未更改其接口或数据库。

封闭测试、年度报告管理从后台导航撤下，旧管理页及其子路径在管理员鉴权后返回工作台。保留历史数据、审计以及既有服务接口；普通用户年度报告不受影响。

登录等待调查：发布前一次完整实测，点击到统计画面约 1132ms，POST 登录约 136ms，随后重复身份查询约 35ms，工作台接口约 660ms。登录接口内部依次换取上游 token、远端验证身份、设置 HttpOnly 会话并记审计。工作台还加载访问统计、用户/绑定、上传目录、备份和近期审计，原页面数据等待阻塞进入后台界面。

登录页现在复用 POST 返回的已验证身份，移除随后的 /auth/me；工作台和称号管理页在客户端异步加载数据，后台框架及导航先可用。服务端仍在每个管理请求验证上游身份，不缓存/解码 token 代替验证。上游登录和身份核验设 8 秒超时且不自动重试；客户端身份查询设 10 秒超时。新增 Server-Timing，登录细分 credentials/identity/audit/total，工作台细分 identity/statistics/audit；不包含凭据、token 或身份数据。

验证：20 项登录/条件管理/既有目录与时间回归，26 项每日称号关联/同步测试通过。真实 Vue 管理页与编辑服务的本地 HTTP 测试在 1440/375 像素下覆盖编辑、恢复官方条件、缺失资料补建、冲突保留输入、歌曲不变、审计、旧入口撤下和无页面横向溢出。临时服务与浏览器已关闭。发布后再执行真实后台登录、界面提前可用及原条件无改动保存验收，不用虚构条件修改生产资料。
