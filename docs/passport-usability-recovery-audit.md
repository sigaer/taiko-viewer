# Passport usability recovery — scoped audit

Opened 2026-10-08 (Asia/Shanghai), source `1dcf9c3`, package 0.80.0. Nuxt reads package version into `runtimeConfig.public.appVersion`; `/more` renders that value without a numbered fallback. Public canonical `/more` also reports v0.80.0. Worktree: `feat/passport-usability-recovery`.

1. `getSkillPassport` calls current Growth Overview once (normally one existing Growth Python), then reads persisted measurements for the requested range and all-time measurement coverage; one `getGrowthHistory(passportHistoryRange(...), includeMeasurements:false)` loads/replays canonical history bounded to 90 days. Overview also calls the existing evidence loader for its current/Daily projection: the existing initial chain has two loader call sites, one canonical 90-day History replay and the current Daily projection. The public History validator remains <=90 and the existing evidence loader retains its file/byte bounds. Range navigation currently repeats this whole chain.
2. `buildSkillPassportMilestones` deduplicates factKeys, groups score facts by day/song/difficulty, matches Goals through the shared Weekly matcher, keeps unmatched Goals observed-only, then sorts newest day first and slices eight. Group identity omits binding/precision. The PB flood fixture confirms all eight selected nodes are October 6 PBs, losing July FC, August matched Goal/NG and September rank/NG. The replacement belongs in an independent presentation selector; canonical outputs stay intact.
3. `passportRangeChoices` returns nothing below 30 days of measurement span; other short spans expose a subset and relabel the last choice “all records”. `route.query.range` defaults to 90 but `useAsyncData` watches it and reissues the heavy GET. Planned shared private DTO supplies four bounded views from one <=365 daily measurement read and one <=90 fact replay. Range navigation selects a local view.
4. Measurement segments already split on consecutive `measurementVersion + algorithmVersion + modelRevision`, including A→B→A. The SVG renders each segment independently, but its x-axis scales to actual points, its generic break explanation is detached from boundaries, and both point aria-label and tooltip contain focus. Preserve the segment builder; use selected calendar bounds, boundary controls and metric-only tooltips, with focus separately labelled.
