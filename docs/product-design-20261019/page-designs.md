# 核心页面完整设计方案

本方案使用现有功能及其字段。原型采用真实公开曲名、曲绘和谱面元数据，加上明确标注的合成玩家成绩；谱面横向鼓点是布局示意，不是从 TJA 解析出的真实音符序列。所有模拟成功只属于原型。

## 全局信息架构与路由

| 导航领域 | 现有路由与职责 | 设计变化 |
| --- | --- | --- |
| 首页 | `/`：访客搜歌，已登录接续身份、目标、变化 | 复用现有四态与个人成长面；减少长篇介绍和大 banner |
| 曲库与谱面 | `/songs/available`、`removed`、`other`、`v2-constants`、`/songs/[id]`、`/ourtaikoview/[id]/[difficulty]` | 搜索／筛选／详情／播放器连续，保留列表与难度返回上下文 |
| 练习与成长 | `/tools/recommend`、`/my/growth`、`/my/weekly`、`/tools/progress` | 同一领域内的“练习 / 成长档案 / 这一周 / 歌曲进度图”子导航 |
| 我的太鼓 | `/my`：个人任务入口，`/account/songs`、`/tools/b30`、`/account/profile`、`/account/sync` | `/my` 复用首页个人面，不再维护第二套统计首页；账号设置与成绩工具渐进进入 |
| 社区 | `/forum/*`、歌曲相关讨论与谱面 UGC | 全站上下文导航一致，发帖保留歌曲／难度关联 |
| 年度报告 | `/annual`、`/account/version-summary`、已有分享路由 | 手机按现有访问策略进入；桌面提示要求，保留返回位置 |
| 文档／设置 | `/account/developer`、`/docs/score-token`、`/settings`、`/support` | 文档清楚区分公开曲库、Developer API、用户授权和旧成绩 token；不新增后端能力 |

手机底部：首页、曲库、练习、社区、我的，共5项。成长属于练习领域中的子导航，可在首页变化区直接进入。桌面侧栏是相同领域，不把全部账户配置常驻展开。

本阶段不新增真实路由。未来可在现有 `/tools/recommend` 上承接训练布局；是否另设前端别名由实施前评审决定，旧链接必须继续有效。

## A 首页与 My Taiko

### 页面任务与内容顺序

让访客迅速找到歌曲，让已有数据的玩家认出自己的账号、接续已经选定的目标，再看到最近真实变化与下一首推荐。首页不承担展示全部统计的职责。

**桌面布局：** 224px 导航；顶部全局搜索与账号按钮；内容首先是身份行（显示名、来源／当前绑定、Rating 单一文本数据、切换），然后一句欢迎语。当前目标占主任务面，曲绘辅助识别；其下8/4分区呈现推荐行式列表与最近变化。曲库更新、当前活动和年度回顾放在后续区块。活动 banner 不再凌驾个人任务。

**手机布局：** 紧凑应用栏，身份行与欢迎语；目标面右侧80px曲绘，文字和操作主导。推荐列表在下一段，变化接续其后；不压成横向三列 KPI。新曲采用两列或可访问的曲绘列表；活动和年报不抢占首屏。底部为5项导航和安全区。

```text
桌面                                  手机
身份 / 当前绑定 / Rating / 切换          应用栏 + 搜索
欢迎语                                 身份行 + 欢迎语
当前目标 + 具体基线           曲绘        当前目标     小曲绘
看谱面 / 更新成绩                      主操作 / 更新成绩
推荐列表               最近变化         推荐列表
曲库更新 / 活动 / 年报                  最近变化 / 周报
                                      曲库更新 / 活动 / 年报
```

### 关键状态

| 状态 | 内容与主操作 |
| --- | --- |
| 访客 | 简短“查谱面、看成绩”价值说明与歌曲搜索；展示真实曲库；登录作为次要接续动作 |
| 登录未绑定 | 显示身份，不显示假成绩；“绑定鼓众 ID”；公开曲库仍在下方 |
| 已绑定无成绩 | 显示绑定，“更新成绩”；不把缺值当0 |
| 有成绩，无活动目标 | 以已有能力和可用推荐为主；“选一首练习”；不伪造正在进行的任务 |
| 有活动目标 | 曲名、难度、目标类型、设定时基线、查看谱面、更新成绩；更换／取消到训练上下文 |
| 已完成目标 | 同一位置替换为明确完成证据与前后变化；选择下一首；目标／最近变化／今日证据继续去重 |
| 部分记录 | 显示已知变化及范围，不说“今天没玩”；可进入成长与同步 |
| 初次读取失败 | 身份状态未知时公共搜歌可用；已登录数据失败就地恢复 |

原型默认展示活动目标；可切换访客、未绑定、无成绩、无目标、完成、加载与失败。没有用假的全站用户数、打歌次数或排行做装饰。

### 操作衔接与数据

`useHomeState` 决定访客／未绑定／已绑定无成绩／Ready；`usePlayerGrowth` 和 `useRecentGrowth` 继续提供 overview、目标、今日变化及最近观察。`composeGrowthFeedback` 继续负责事实去重。首页不再额外拉另一套 Recommendation 或自行计算六维。

点击推荐保留 `songId + difficulty + recommendation token`；确认仍经过现有 `RecommendationGoalAction` 或 Goal 选择器。切换账号／绑定时旧请求、弹窗和提示失效；沿用当前 generation 与 AbortController 机制，不新增平行状态实现。

## B 歌曲详情

### 布局与信息层级

**桌面：** 返回列表／查询上下文；144px曲绘、完整主曲名、原名、分类、BPM、上架状态。一个难度条统领全页。8列为所选谱面的预览与练习操作，4列为我的该谱面成绩、练习目标与关联讨论。六项谱面分析、完整歌曲资料和下载放到按需展开区。

**手机：** 84px曲绘加可自然换行曲名；难度条保持44px以上触控区，320px时采用短标签加次行星级。所选谱面及“打开练习播放器 / 完整谱面”先出现；随后我的成绩与目标，再看攻略与讨论。完整作曲／演唱名单、各分支音轨详情、下载不挤占首屏。

```text
桌面                                  手机
曲绘 + 曲名 / 原名 / BPM / 状态          小曲绘 + 曲名 / BPM
简单 / 普通 / 困难 / 魔王 / 里谱        同一难度选择
所选谱面与播放器          我的成绩       所选谱面 + 练习 / 完整图片
试听音轨                 设为目标       试听 / 分支音轨
谱面特征（展开）          攻略交流       我的成绩 + 目标动作
歌曲资料与下载（展开）                  攻略 / 讨论 / 可展开资料
```

原型曲目为真实公开歌曲1455：魔王★7、最大物量503，里谱★9、最大物量766；简单／普通／困难分别★3／★5／★5和87／168／320。个人成绩980,000及其判定是合成数据，不是生产玩家记录。

### 关键行为与状态

| 场景 | 设计与保留约束 |
| --- | --- |
| 切换难度 | 更新谱面、试听分支、成绩、UGC、相关讨论与目标资格；URL保留 difficulty；没有该难度不虚构按钮 |
| 推荐进入 | 保留 token 与推荐来源；同一难度仍有效时提供目标确认；切换难度不沿用另一谱面的资格 |
| 直接访问详情 | 可看谱面、试听、讨论；是否可创建Goal由现有服务与goalOptions决定，不能仅因已登录就放行 |
| 无个人成绩 | 显示“这张谱面还没有成绩记录”，而不是0分；公共信息可继续看 |
| 成绩读取失败 | 局部错误和重试，谱面／公开资料继续展示；不把所有区域切成同一错误页 |
| 分析或谱面资源缺失 | 名称和难度保持可见；缺失区有明确说明，关闭无效入口，不画假雷达或假谱面 |
| 音频不兼容／缺失 | 保留现有音频降级、分支选择和错误说明；用户触发播放，不自动出声 |
| 设目标 | 明确目标类型与基线，确认、取消、替换均可；确认中防重入；失败保留选择 |
| UGC／讨论 | 保留难度投票、标签、提示、反馈及发帖能力，表述清楚；未登录只在需要写入时引导 |
| 返回 | 回到原列表搜索条件或推荐模式／滚动位置，而不是丢到通用曲库首页 |

图中“谱面预览示意”只验证空间和操作顺序；实施复用现有完整谱面图片／播放器，不新增TJA解析器或时间轴算法。不能用原型的示意音符验收音乐同步。

### 可复用的数据与组件

保留 `pages/songs/[id].vue` 的公开元数据、选定难度、音轨、TJA包与账号成绩链；`SongCoverImage` 负责曲绘和降级；`AccountSongScores`、`ChartUgcSection`、`ForumSongRelatedDiscussions`、`RecommendationGoalAction` 保持事件和权限语义。原型中的“设为练习目标”是合成可用态，正式版必须检查现有资格。

## C Training 与 Progress

### 职责区分

练习回答“下一首练什么，以及我选的目标怎样了”；成长回答“已有记录里，发生了什么变化”。歌曲进度图是成绩覆盖可视化，不能被长期成长折线替代。周报继续提供有限时间范围的叙事。

### 练习布局

**桌面：** 页面标题与更新成绩；同领域子导航；当前目标、设定时基线、检查／更换／取消在主列顶部。下方保留普通推荐和目标推荐两个模式、必要筛选与完整结果列表。辅助列放已有能力焦点与成绩工具入口，不放新排行榜和假训练时长。

**手机：** 当前目标→必要操作→推荐模式→常用筛选→列表。高级参数与导出折叠，保留进入方法。推荐行显示曲绘、曲名、难度、当前记录和前往谱面的动作，完整列表可继续加载；不改成首页单张随机推荐。

普通推荐保留数量1–50、综合及全部六维、可选图片输出；目标推荐保留极、紫雅、粉雅、金雅、全连、全良及星级筛选。目标推荐指标不等于可创建Goal的类型，只有服务端 `canCreateGoal/goalOptions` 允许时才显示对应动作。

### Goal 状态设计

| 状态 | 主要信息／动作 |
| --- | --- |
| 无目标 | 先展示可用推荐；确认前不给“正在练习”标签 |
| 选择中 | 曲名、难度、可用目标类型与设定时成绩；单次明确确认 |
| 替换中 | 显示正在替换的旧目标及新选择，保留现有 expectedActiveGoalId／冲突语义 |
| 保存中 | 锁定本次提交；关闭／切换身份按现有策略处理；旧结果不能污染新目标 |
| 活动目标 | 固定基线和具体成功条件；“更新成绩”与“检查目标”分开 |
| 无新进步 | 保持目标，表达“还没有确认新的进步”，可继续练习或同步 |
| 无法确认 | 显示记录／来源限制，不擅自判失败或完成 |
| 完成 | 展示严格完成证据，选择下一首或进入成长档案；同事实不重复讲三遍 |
| 失效／不可用 | 解释谱面或来源变化与可行下一步，不默默换成另一目标 |

“不可1→0”使用严格少于基线；“刷新最好成绩”严格大于基线。UI 不改变 Goal 类型、判断阈值、来源资格、历史归因或完成时间语义。原型的同步／检查只用于体验演示，不能用于业务验收。

### 成长布局

**桌面：** 一条有证据的变化叙事，8列趋势、4列具体里程碑；下方完整六项能力与练习接续。**手机：** 叙事→范围→趋势→记录范围→里程碑→六维→下一首。六维不再成为挡在趋势前的巨大首页统计面。

保留30／90／180／365天、Rating与六维切换、图表点选择与前后点操作、里程碑、焦点历史和下一步。使用现有 shared views 时继续本地切换，不要求每个范围重新请求。短历史明确实际有记录的时间，不把90天选择解释为已有90天完整事实。

当前实现展示冻结 daily measurement。UI迁移必须复用 `passportMetricRuns` 和现有曲线语义：不重算历史、不增加按模型版本切断曲线的新规则；空数值按现有逻辑断开。能力轴继续0–15.5，Rating保留适配范围；不因视觉平滑而插值出不存在的记录。

| 数据状态 | 成长页表现 |
| --- | --- |
| 无记录 | 同步入口，无空坐标／0值六维 |
| 单点 | 显示单点和“还在积累”，不画趋势箭头 |
| 稳定 | 展示当前值与时间，不强行写“持续提升” |
| 缺失日期／范围不足 | 明确覆盖；未知不等于没玩；可读取部分仍保留 |
| 长期测量、有近期事实限制 | 测量图与最多90天事实各自说明，不假造全年成绩事件 |
| 请求失败 | 同身份已有数据保留，错误靠近刷新；首次失败提供重试 |

原型包含范围切换、七指标、数值表、记录稀疏提示和返回歌曲；没有接入真实API，不覆盖生产多来源、授权或历史计算正确性。

## 原型评审和实施验收

重点评审身份与任务是否清楚、谱面动作是否容易找到、推荐到Goal的衔接是否完整、手机是否按任务重排、日语长文本是否舒适，以及红／青是否形成适度的太鼓辨识度。

原型浏览器检查见 `prototype-validation.json`。实施后再以真实组件、隔离合成业务数据、中日文／深浅主题／设备矩阵执行回归；原型截图不替代功能回归或发布验收。
