# 歌曲页外壳与内容整合

评审入口：[同浏览器对照](index.html)。预览启动后也可直接打开 `http://127.0.0.1:3208/__song-review/index.html`；真实组件页面仍为 `/songs/1455?previewState=scores`。

修改前为本分支 `12aabc4`，原截图和设计资料均保留。本轮没有部署、改版本或推广其他页面。

## 看哪些变化

- 手机将菜单、面包屑、返回列表三层合为一行：返回歌曲列表、My Taiko、原有菜单。五个底栏目的地和菜单内的语言切换保留，底栏改用同一组红青色和无阴影表面。桌面仍有侧栏和面包屑。
- 完整曲绘使用 contain，手机为 80px；题名与曲绘成组，另一语言的副标题另起整行。没有加大 Hero；414 下歌曲身份区的高度仍约 161px，但起点从 166px 提前到 84px。
- 练习播放器为主要操作，完整谱面用文字入口，下载放在次级位置。原 PNG 默认展示明确标注的节选：手机 148px、桌面 280px，可展开到 560px，也可打开原有完整图片。没有滤镜、重绘、改色或删除音符；默认节选横向浏览，展开后可纵向阅读。鼓点／混音／纯音乐及分支仍在原组件中，通过“试听”展开。
- 成绩的难度、分数、状态与良／可／不可直接可读；最大连击、连打、次数、日期放进“成绩明细”。全部成绩入口并入标题行。空讨论收成两行，保留发帖与全部讨论入口。用一个轻成绩表面区分个人记录，不再以连续浅青底和横线串成纵向报表。

## 字体核实

使用同一 `/usr/bin/chromium`（113.0.5672.126），DPR 1，通过 CDP `CSS.getPlatformFontsForNode` 读取实际字形来源，另记录 CSS 字重、字号、行高；不是仅检查字体声明。原始记录：[修改前](before-fonts.json)、[修改后](after-fonts.json)。

| 角色 | 本机实际渲染与调整 |
| --- | --- |
| 中文题名、正文、数字、按钮 | 原本已使用 Microsoft YaHei UI，没有“缺中文字体”的证据；继续使用现有系统字体 |
| 日文题名、正文、数字、按钮 | 使用现有 Hiragino Sans |
| 日语页中的中文副标题 | 修改前为 Hiragino Sans 与 WenQuanYi Zen Hei 混排；明确 `lang` 和中文字体栈后，实际统一为 Microsoft YaHei UI |
| 中文页中的日文副标题 | 明确日语字体栈，实际使用 Hiragino Sans |

题名、选中难度和分数的强调字重收敛到 600，与主要按钮一致；正文 400，普通底栏文字用 400。没有新增字体文件。谱面内的字形属于原始 PNG，不属于网页字体，保持原样。

这些结果证明的是这台 Linux Chromium 的实际渲染。当前交付上下文没有可核验的用户实拍原件、设备系统或字体诊断，因此不把本机结论冒称为用户手机字体实测；手机尺寸截图也是同一 Chromium 的视口模拟。
