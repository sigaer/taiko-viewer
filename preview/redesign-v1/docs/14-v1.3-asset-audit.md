审计对象是生产 `origin/main`（`f9b39e6`，「1.14.2 同步Bot评级王冠与难度图标到Viewer公共资源」），用 `git show` / `git grep` / `git ls-tree` 读取。工作区里的 `taiko_viewer/` 是旧基线 `71e73f5`，没有 `public/icons/diff`、`crown`、`rank`，本文不以它为准。下文 `main:` 前缀表示 `origin/main` 中 `taiko_viewer/` 下的路径；行号取自该提交。

图片尺寸由 PNG 文件头读出；「主题」一列是看图后的判断；「状态」一列：
- **已验证**：映射在生产代码或映射文件里能找到；
- **待验证**：资源存在，但映射只能从文件名、图形或仓库外的代码推断；
- **无对应资源**：业务值存在，但 Viewer 公共资源里没有图。

## 1. 结论摘要

1. **1.14.2 新增的三组图标（`icons/diff`、`icons/crown`、`icons/rank`）目前没有任何 Viewer 前端代码引用。** 生产 Viewer 的王冠与评价至今只显示文字（`AccountSongScores.vue` 的 `crownLabel`、`utils/scoreRank.ts` 的 `formatScoreRank`）；唯一用难度图标的地方（曲库列表）引用的是旧路径 `icons/difficulty/`。
2. **难度图标有三套路径、两种内容**：`icons/diff/1–5` 与 `icons/difficulty/1–5` 字节相同；根目录的 `kantan/futsuu/muzukashii.png` 与 diff 1–3 字节相同，`oni.png` 是魔王 + 里两张脸拼成的 172×86 图，`inner_oni.png` 是另一款「裏」字圆标，都不同于 diff 4、5。
3. **王冠的生产规则已确认**：全良计数 > 0 → 全良；否则全连计数 > 0 → 全连；否则通关计数 > 0 → 通关；有记录但都为 0 → 已游玩；没有记录 → 不显示。
4. **评价值 0–8 的定义两边一致**（原型 `RANKS` 与生产 `SCORE_RANK_DEFINITIONS` 同值同名）。但「`rank/N.png` ↔ 评价值 N」只能由图形顺序推断：选图的函数在 Bot 仓库（`_rank_icon_path`，本仓库只有函数名），所以记为待验证。`rank/1.png` 全透明。
5. **称号牌不是一种东西**，生产里有三类，Viewer 页面本身都只显示文字：
   - 绑定时记录的游戏称号（`verifiedTitle` + `verifiedTitleplateId`）；
   - 站内称号（`AccountTitle`，目前只有一个，style `rainbow`）；
   - 「我的小咚」展示称号（官方称号或自定义称号，由 Bot 渲染进 PNG）。

   9 张称号牌切片只给「我的小咚」展示与年度报告用；生产里没有「稀有称号」的概念。
6. **头像默认值在生产内部不一致**：服务端默认是 `https://viewer.sakura-bot.cn/miku.png`，`/my` 页前端缺省是 `/default-avatar.svg`。
7. **原型的精选曲里，只有一部分 ID 能确认是真实曲目**：
   - 12 个与仓库测试数据中的曲名一致，16 个只证明封面存在或曲名不一致（待验证），12 个按封面检查不存在（`1000xx` 与 278）；
   - 702 在仓库里对应「懐中庭園を持つ少女」，不是原型的「紅蓮華」；
   - 幽玄ノ乱在生产验收脚本里是 463，原型用 960；
   - **原型生成曲的 ID 从 1 起占用，与真实曲目 ID 空间重叠。** 接真实封面前必须先处理。

## 3. 分类说明

### 3.1 封面

**生产规则**
- `main:utils/songCover.ts`：缩略图 `cover/thumb/{200|400}/{id}.webp?v=0841`，原图 `cover/{id}.png`，跳转接口 `/api/content/covers/{id}`。
- `main:components/SongCoverImage.vue`：
  - props 默认值为 `sizes: "200px"`、`fit: "cover"`、`fallbackSongId: 1384`（第 13–22 行）；
  - `IntersectionObserver` 的 `rootMargin: "320px 0px"`（第 72 行）；
  - 失败顺序：webp → 原图 png（带 5 分钟粒度的重试版本号，绕过之前的负缓存）→ 1384 → 占位底色（`handleError`，第 45 行起）。

### 3.2 难度图标

**生产规则**
- 难度序号 1–5 对应 `difficulty.1–5`：简单 / 普通 / 困难 / 魔王 / 魔王（里）。来源是 `main:locales/zh.json` 第 587–593 行，以及 `main:utils/difficulty.ts` 的 `DifficultyType = 1|2|3|4|5`。
- 星级取 `SongCatalogItem.level_{n}`；`SongTrackKey` 是 `EASY | NORMAL | HARD | ONI | EDIT`。
- 使用图标的只有曲库列表：`SongListContent.vue` 第 107–111 行引用 `/icons/difficulty/{n}.png`，按 20×20 显示。原图不是正方形（94×78 等），在 20×20 框里会被拉伸，组件没有设 `object-fit`。
- 攻略页另用根目录的 `kantan/futsuu/muzukashii/oni.png`（`main:utils/guide.ts` 第 4–7 行，只有 4 档，第 4 档是魔王 + 里的拼图）。

**应统一到哪个路径：建议 `/icons/diff/`。**
- 它是 1.14.2 从 Bot 同步进来的那一套，与 Bot 生成图片时用的 `assets/icons/diff/{level}.png` 同名同序。证据：`main:tests/fixtures/installedImageRoot.py` 第 11、16 行，仓库根 `scripts/readiness/build-o1-synthetic-assets.py` 第 15 行，Bot 图片基准清单中的 `icons/diff/1–5.png`。

- 目前前端引用次数：`icons/difficulty` 5 处（全在 `SongListContent.vue`），`icons/diff` 0 处。因为两者逐字节相同，迁移只需改路径；`icons/difficulty` 可以保留为旧别名，等引用清零后再删。

### 3.3 王冠

**生产规则**：`main:components/account/AccountSongScores.vue` 第 63–68 行。

```
dondafulComboCnt > 0 → 全良；否则 fullComboCnt > 0 → 全连；否则 clearCnt > 0 → 通关；否则 → 已游玩
```

- 只有存在成绩记录时才会走到这条规则。没打过的谱面没有 `AccountSongScore`，歌曲详情显示「这首歌还没有同步到成绩记录」，不显示王冠。
- 同样的优先级也出现在目标判定里：`main:utils/goalEvaluation.ts` 第 36 行，`main:utils/playerGoal.ts` 第 15–18 行。
- `icons/crown/*` 没有前端引用；与之逐字节相同的 `annual/milestones/crown/*` 由年度报告 `components/account/version-summary/slides/MilestonesSlide.vue` 第 17–19 行使用，键名为 `clear`、`full_combo`、`dondaful`。

**原型**：`CROWNS`（`catalog.js` 第 39–44 行）与 `Crown.vue`。
