# 15 · Design V1.3 品牌体系（Fumen × Viewer Teal）

日期：2026-11-16　基线：V1.2 提交 `cb8fb5aa`　阶段：Phase A（三版本对照，尚未选定方向）

这份文档定义对照版本 C 的配色与使用规则。它不改信息架构、布局、字体和组件尺寸。A、B 两个版本的颜色保持 V1.2 不变。

---

## B1 · 诊断：V1.2 没有品牌色

V1.2 的交互颜色分散在三处，没有一个颜色代表 Viewer 自己：

| 角色 | V1.2 用的颜色 | 这个颜色原本的含义 |
|---|---|---|
| 主按钮 | 朱（`--don-solid`） | 咚音符、判定「良」 |
| 链接、焦点环、选中的筛选 | 浅葱（`--ka-ink`、`--asagi-700`） | 咔音符 |
| 导航选中 | 藍墨（`--ink`） | 正文颜色 |

游戏语义色同时在当交互色用，所以一屏里红色既可能是按钮，也可能是音符、判定或难度。

正式站现在的 `tokens.css`（`--viewer-*`）已经是青绿体系：页面底 `#eaf6f5`、表面 `#f9fdfc`、文字 `#203f43`、链接 `#006c76`、选中底 `#d7ece9`，深色对应 `#10282b` 一组。你给的候选值与它一致。正式站的主按钮仍是红色（`--viewer-primary: #bd352f`），C 版本把主按钮也并入青绿。

## B2 · 三个版本用两个开关表示

| 版本 | 素材 `data-assets` | 品牌 `data-brand` |
|---|---|---|
| A · V1.2 基线 | `generated` | `fumen` |
| B · 真实素材 | `authentic` | `fumen` |
| C · Viewer Teal | `authentic` | `teal` |

- 两个属性写在根元素上。默认是 A，V1.2 已验收的状态不变。
- 地址参数 `?variant=a|b|c`（写在 `#` 之前）只对当前页面生效，不写入存储；对照页和截图脚本用它。原型面板里可以切换并记住。
- B 与 C 之间只允许颜色不同：布局、字体、尺寸、数据、素材对应关系必须逐像素一致。

## B3 · Token 结构

在 Semantic 层加两组 token。

**品牌 token**（只在 `teal` 下有独立的值）：

| Token | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--brand-primary` | `#006C76` | `#86D9DC` | 主按钮底、链接、选中指示、导航选中 |
| `--brand-hover` | `#005860` | `#A0E3E5` | 悬停与按下 |
| `--brand-soft` | `#D7ECE9` | `#244B4E` | 选中的筛选、当前行、提示条的浅底 |
| `--brand-on-primary` | `#FFFFFF` | `#0B2A2D` | 品牌实色上的文字与图标 |
| `--brand-focus` | `#006C76` | `#86D9DC` | 焦点环 |

**角色 token**（两套品牌都有；组件只引用角色，不直接引用音符色来表示交互）：

| 角色 token | `fumen`（保持 V1.2 的实际值） | `teal` |
|---|---|---|
| `--action-bg` / `--action-bg-hover` / `--action-ink` | V1.2 主按钮的值 | `--brand-primary` / `--brand-hover` / `--brand-on-primary` |
| `--link` | `--ka-ink` | `--brand-primary` |
| `--selected-bg` / `--selected-ink` / `--selected-line` | V1.2 选中胶囊、分段的值 | `--brand-soft` / `--brand-primary` / `--brand-primary` |
| `--nav-active-bg` / `--nav-active-ink` | V1.2 导航选中的值 | `--brand-primary` / `--brand-on-primary` |
| `--focus-ring` | `--asagi-700` / `--asagi-400` | `--brand-focus` |

实现时角色 token 比上表多：分段选中、页签指示线、提示条、标志、两种标签、强调数字、单序列图表、点赞按下、输入框焦点线、文字选区各有一组，原则相同。完整清单在 `src/styles/tokens.css`。

规则：

- A、B 两个版本在换成角色 token 之后，计算出的颜色必须与 V1.2 完全相同。
- `--don*`、`--ka*`、`--roll*`、`--diff-*`、`--crown-*`、`--rank-*`、`--judge-*` 只表示游戏数据，不再表示按钮、链接、选中或焦点。
- 不对任何真实素材使用 CSS 滤镜、混合模式或遮罩来改色。

## B5 · 品牌色与「咔」撞色

品牌青绿（色相约 185°）和咔音符的浅葱（约 190°）几乎同色相。深色主题下尤其明显：`#86D9DC` 与 `#4CC6D8` 放在一起分不开。这是选青绿做品牌色的直接代价，处理如下：

1. C 版本里咔的颜色向蓝偏移到约 198°：浅色 `--ka: #2B9BCF`、`--ka-ink: #0F6A96`、`--ka-wash: #DDEFF8`；深色 `--ka: #5CC4EF`、`--ka-ink: #8AD4F4`、`--ka-wash: #16344A`；谱面带上 `--lane-ka: #56C1EE`。游戏里的咔本来就偏蓝，这个方向与素材一致。
2. 咔只以音符的形状出现（圆形、带白环和深色轮廓），不出现在文字、链接、按钮、选中状态上。
3. A、B 不改，仍是浅葱。

这是 B 与 C 之间唯一一处游戏语义色的差异，对照文档里要单独指出来。

## B6 · 颜色使用规则（C）

**中性色做主体。** 背景、表面、文字、分隔线占一屏的绝大部分。真实曲绘本身颜色丰富，周围的界面不再加高饱和底色。

**品牌青绿只用于：**
- 一级导航的选中项（桌面窄轨为实色胶囊，手机底栏为图标与文字变色）；
- 主按钮；
- 链接；
- 选中的筛选、分段、页签指示线；
- 输入框焦点与焦点环；
- 单一序列的图表（Rating 走势线、六维雷达的描边与 12% 填充）；
- 标志的鼓缘。

**按钮分三级。** 主按钮（品牌实色）、次要按钮（中性描边）、文字按钮。一个区域只有一个主按钮。V1.2 有两种实色按钮（朱色与藍墨），C 里两种都按品牌主按钮显示；同一个区域里原本两种并排的地方，把其中一个降为次要按钮。歌曲详情的操作条：「想练这首」是主按钮，「游玩练习」是次要按钮，顺序和尺寸不变。

（第一版曾规定藍墨实色按钮在 C 里一律降为次要按钮，结果成绩页的「补录一条」等区域失去了唯一的主按钮。已改为上面的规则。）

**游戏语义色只在数据需要时出现：**
- 咚、咔、连打：谱面带、谱面图、音符。
- 判定色：成绩条的良、可、不可。
- 朱色：每小节密度图里的难点、新纪录与达成标记、通知角标、手机底栏中间的「咚」键（它本身是一个咚音符）。
- 难度、王冠、评价：由真实素材自己带颜色，容器是中性的。
- 流派：只作 6px 色点。

**在 C 里改为中性的：**
- Rating 等大数字用 `--ink`，不用朱色。
- 社区版块的色点改为 `--ink-3`，版块靠名称区分。
- 标签默认中性（`--bg-sunk` 底、`--ink-2` 字）。只有带状态含义的保留颜色：精华（连打色浅底）、官方与版主（品牌浅底）。
- 提示条、信息条的浅底用 `--brand-soft`，不用咔的浅底。

**状态色不变：** 成功、警告、危险各一种，破坏性按钮仍是危险色描边。

## B7 · 深色主题

- 与浅色是同一套品牌体系：底色是深青，不是藍墨。
- 颜色种类不多于浅色。深色下品牌色是浅青绿 `#86D9DC`，实色按钮上的文字是深青 `#0B2A2D`。
- 谱面带用比页面更深的 `--bg-sunk`，靠 1px `--lane-line` 与页面分开；音符颜色不变。
- 真实素材不调色。王冠、评价、难度图标自带黑色描边，在深色底上描边会融进背景，填充色仍然清楚；素材盘点里逐个记录深色下的识别情况。
- 首屏主题脚本、减少动效的处理沿用 V1.2。首屏脚本要同时读取品牌开关，C 的深色首屏不能先闪一下藍墨。

## B8 · 标志

Phase A 沿用 V1.2 的鼓面标志，C 里鼓缘改用 `--brand-primary`，鼓面仍是朱色。正式站现在的图标是游戏角色的脸，是否继续使用由你决定，见 `18`。

## B9 · 内容宽度

旧版的三档宽度（标准 1000、密集 1180、阅读 800）与 V1.2 的宽屏数据布局冲突：曲库、成绩表、今日页在 1440 宽下用的是 1480 上限的多栏布局，压到 1180 会丢掉右侧栏。Phase A 不改宽度。帖子详情的阅读栏已经接近 800，保持。

## B10 · 性能预算

沿用 V1.2 的预算，其中搜索首键 p95 按你这次给的数字改为 ≤ 50ms（V1.2 我定的是 100ms，实测最高 23.7ms，改后仍然通过）。真实图片的加载指标单独记录，见 `16` 的 A7。
