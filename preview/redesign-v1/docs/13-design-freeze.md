## 3. 不冻结什么

- **原型的代码。** 它是 Vite + Vue 的单页应用，用来验证设计，不是要搬进 Nuxt 的实现。正式实现照规格重写。
- **模拟数据的形状。** 原型里的数据字段有几处与正式数据模型对不上（见第 6 节），以正式模型为准。
- **`03` 里标为 ◐ 的功能**（词云、图片回复、审批台等）：原型只有入口或静态样子，对应阶段开始前要补成完整设计。
- **年度回顾与管理后台。** 不在本次改版范围内。
- **设计评审页**（`#/review/*`）与原型面板：只是评审工具，不进产品。

## 5. 剩余问题

**阻塞：无。**

**非阻塞：**

1. 快速切换时的最长任务在本机为 141–191ms，离 200ms 的预算很近。正式实现要在目标设备上重测。
2. 回复框跟随软键盘没有在真机上验证。
3. 设计评审页 `/review/system` 首次渲染有 300–600ms 的长任务，手机上有两个小于 44px 的控件。它不是产品页。
4. 原型面板的悬浮按钮在平板和桌面的帖子页会压住「回复」按钮。它是原型自带的控件，不进产品。

5. `AppShell.vue` 里留有一条不会生效的样式（手机宽度下账号菜单的位置，而账号菜单只在平板和桌面出现）。没有可见影响，原型代码不进产品，没有再动。

完整的风险登记与验收项见 `12-risks-and-integration-acceptance.md`：风险 44 项（高 12、中 27、低 5），验收项 74 条。

## 6. 需要你决定的事

**批准前，一项：**

- **搜索面板首键预算 100ms。** 你要求把首键与热态分开测；「首键 p95 ≤ 100ms」这个数字是本轮我定的，原先只有一个 50ms。实测首键 p95 最高 23.7ms，定成 50ms 也能通过。请确认用 100ms，还是与热态一样用 50ms。

**进入实现前，不影响冻结：**

这些是原型的数据假设与正式数据模型的差异，每项需要「后端补数据」或「设计降级」二选一。依据都在 `12` 的风险表里。

| 事项 | 差异 | 风险编号 |
|---|---|---|
| 目标卡的尝试轨迹 | 正式的目标数据没有每次尝试的记录 | RK-08 |
| 个人主页 `/u/:name` | 新增提案，没有公开资料接口 | RK-11 |
| 原生 Rating / 进度页 | 正式站目前是服务端生成的图片，没有 JSON | RK-12 |
| Rating 与段位类里程碑 | 正式库没有来源 | RK-07 |
| 头像、段位、稀有称号 | 正式的用户徽标只有头像地址、认证称号、角色 | RK-10 |
| 别名、谱面图、试听是否可用 | 正式的曲目条目没有这三个字段 | RK-09 |
| 曲库：全量放前端，还是服务端分页 | 两种方案的筛选、排序、滚动还原实现不同 | RK-25 |
| 字体：自托管汉字字体，还是只自托管数字与拉丁字母 | 实际传输体积没有测 | RK-34 |

`06-migration-plan.md` 第 4 节里的顺序与命名两项也还等你的决定。

## 7. 批准意味着什么

**批准后可以做：**

- 按 `06-migration-plan.md` 从阶段 0（地基，不产生用户可见变化）开始正式实现。
- 以 `12` 的验收清单作为每个阶段的验收依据。

**批准不代表：**

- 生产验收通过。每个阶段接入真实接口后要按 `12` 重新验收。
- 可以合并 `main` 或部署。这一分支只含 `preview/redesign-v1/`，与正式业务隔离；合并与部署按仓库规则另行进行。
- 第 6 节的事项已经决定。

## 8. 冻结之后怎么改

- 实现中发现规格做不到或与真实数据冲突：写一条变更裁定（编号接 F 之后），说明原因、改什么、影响哪些页面，再改 Design System 与原型。不在实现代码里悄悄偏离。
- 只影响单个页面的文案、间距微调：实现时直接改，在阶段验收记录里注明。
- 新增功能或新页面：不属于变更，另起一轮设计。
