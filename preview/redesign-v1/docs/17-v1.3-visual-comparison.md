# 17 · Design V1.3 三版本视觉对照

日期：2026-11-16　基线：V1.2 提交 `cb8fb5aa`　阶段：Phase A

> 全部结果基于原型与模拟数据，不是生产验收。曲绘来自正式站的静态资源域名，是真实的网络请求；成绩、帖子、玩家都是模拟的。

## 1. 三个版本

| 版本 | 素材 | 配色 | 说明 |
|---|---|---|---|
| A · V1.2 基线 | 生成式封面、自绘难度块、王冠、评价圈、文字称号牌、彩色鼓面头像 | Fumen（藍墨 + 朱 + 浅葱 + 山吹） | 固定的比较基准 |
| B · 真实素材 | 真实曲绘、难度图标、王冠、评价、称号牌；中性默认头像 | 与 A 相同 | 只看「换回游戏素材」这一步的效果 |
| C · Viewer Teal | 与 B 相同 | 青绿品牌体系（`15`） | 在 B 上只改颜色 |

三个版本用同一套数据（`real`，50 首有 ID 与曲名依据的曲目）、同一套布局、字体和组件尺寸。

**核对过的两件事：**
- A 没有被动到。改造前后四个页面 × 两个视口 × 深浅色共 16 张截图逐像素比较，差异为 0（成绩页有一处 2 像素的抖动，两次基准截图之间本来就有）。
- B 与 C 的布局相同。20 组页面 × 视口 × 主题里，元素的位置和尺寸完全一致，差别只在颜色。

## 3. 颜色与素材密度

48 张截图逐像素统计。口径：色度低于 0.12 算中性；170°–200° 算品牌色相带；0°–20° 与 345°–360° 算朱色带；其余有色度的算其他饱和色。

| 版本 | 朱色 | 其他饱和色 | 品牌色相带 | 三项合计 | 其中非品牌 |
|---|---|---|---|---|---|
| A | 2.3% | 2.8% | 0.3% | 5.4% | 5.1% |
| B | 1.6% | 2.6% | 0.3% | 4.5% | 4.2% |
| C | 0.8% | 1.4% | 2.3% | 4.5% | 2.2% |

怎么读这张表：
- **A → B**：朱色少了约三成。减掉的是生成式封面和难度色块。其他饱和色基本没变，因为真实曲绘自己带颜色。
- **B → C**：有颜色的面积合计没变，都是 4.5%，但分布变了。品牌色从几乎没有变成占一半，朱色与其他杂色各减半。C 不是「颜色更少」，是「颜色集中到一个色相上」。
- **不要用「中性占比」比较深色主题。** 表里没有列它：深青的页面底色度刚好低于 0.12、藍墨的卡片刚好高于 0.12，所以 A 深色算出来 60% 中性、C 深色 89%，这个差距是阈值造成的，不代表观感差这么多。逐张数据在 `analysis.md`。

**首屏素材数量（1440，B 与 C 相同）：**

| 页面 | 真实曲绘 | 难度图标 | 王冠 | 评价 | 称号牌 |
|---|---|---|---|---|---|
| 今日 | 5 | 5 | 1 | 2 | 0 |
| 歌曲详情 | 1 | 5 | 2 | 1 | 0 |
| 全部成绩 | 12（另有 1 张缺失占位） | 13 | 16 | 13 | 0 |
| 社区 | 4 | 3 | 0 | 0 | 1 |

A 的首屏这些位置全部是 CSS 画的。

## 4. 逐页观察

**今日**
- B：五处曲绘换成真实封面后，「这次想练」和今天的进展列表一眼能认出是哪首歌。评价升级的两个图标（原评价 → 新评价）比 A 的两个小圆圈显眼得多。
- C：Rating 圆环、六维雷达、导航选中、主按钮都是青绿，朱色只剩谱面带里的音符、「试试全连」的目标类型和通知角标。谱面带换成深青后，音符的对比没有下降。
- 代价：六维雷达从朱色变成青绿后，和页面底色是同一色相，比 A 里的红色雷达弱。

**歌曲详情**
- B：难度页签用真实图标后，四个难度靠形状就能分开（梅花、竹、松、鬼面），不必再读颜色。选中的页签是难度色边框加浅底。
- C：选中改为青绿边框。主封面是真实曲绘，页面上部的主体就是曲绘本身。「设为这次想练」是唯一的主按钮。
- 代价：每小节密度图里的朱色难点、成绩条的朱色在青绿底上比在 A 里更跳。这符合「朱色只表示游戏数据」的规则，但这两处现在是整屏最抢眼的东西。

**全部成绩**
- B：这一页变化最大。每一行有真实曲绘、难度图标、王冠、评价图标。
- 评价是这一页的难点。28px 的真实评价图里汉字认不清，三种粹、三种雅只剩颜色不同，单看图标比 A 的字形圆圈更难读。已改为图标后面跟评价名文字（紫雅、金雅、极），改完比 A 清楚；手机列表行放不下文字，仍然只有图标。
- C：「补录一条」是页面里唯一的实色按钮。选中的筛选是青绿浅底。表格本身几乎没有品牌色，颜色都在素材上。
- 默认数据下（`*-full.jpg`）首屏 13 行都是示例占位。这是模拟数据的状态：合成曲没有真实曲绘，不代表正式站的样子。

**社区**
- B：关联曲目显示真实曲绘；头条作者区出现金色称号牌。所有玩家头像都是同一种中性鼓面。
- C：版块色点变成中性，置顶与公告标签变成中性，只有「发布新帖」和页签指示线是青绿。阅读区比 A、B 都安静。
- 代价与局限：
  - 达人榜八个头像一模一样，比 A 的彩色鼓面平。这是原型的局限：不能导入真实玩家的头像，所以「有头像」的状态只在素材页演示。正式站有上传头像的玩家会带来颜色，这里看不到。
  - 称号牌在 220px 宽时高 18px，字约 12px，压在有纹理的色带上，偏小。

## 5. 按评价维度

| 维度 | A | B | C |
|---|---|---|---|
| 品牌识别是否明确 | 没有品牌色；按钮是音符的朱色，链接是咔的浅葱 | 与 A 相同 | 青绿是唯一的交互色，导航、主按钮、链接、选中、图表一致 |
| 太鼓游戏特色是否恢复 | 靠谱面带和自绘图形 | 曲绘、难度、王冠、评价、称号牌都是游戏原图 | 与 B 相同 |
| 信息层级是否清晰 | 清晰 | 清晰；评价加文字后比 A 好读 | 与 B 相同；主按钮每个区域只有一个 |
| 单屏色彩是否分散 | 红、青、黄、紫、粉、绿同时当底色用 | 生成封面和难度色块没有了；界面自己的颜色没变 | 界面颜色收成一个色相，其余颜色都来自素材和数据 |
| 重要成绩能否自然突出 | 靠朱色数字和色块 | 靠王冠、评价的原图 | 与 B 相同；Rating 等大数字改为中性色后不如 A 醒目 |
| 长列表是否舒适 | 每行一个高饱和首字块 | 每行一张真实曲绘，信息量更大，也更花 | 与 B 相同；底色是淡青，比 B 的灰白更柔 |
| 深色主题是否协调 | 夜藍，层次分明 | 与 A 相同；银色王冠的黑描边融进背景 | 深青，与浅色是同一体系；页面与卡片的明度差比 A 小，偏平 |
| 长期使用是否疲劳 | 主按钮、音符、判定都是红色，红色出现频率高 | 略好 | 红色只在数据里出现，最不累 |
| 是否丢失数据效率 | 基准 | 没有丢：列宽、行高、首屏行数相同；评价列加文字后变宽 | 与 B 相同 |

## 6. 判断

**B 单独解决了多少。** 游戏辨识度这一半问题，B 就解决了：曲绘、难度、王冠、评价、称号牌回来之后，这些页面不会再被当成普通的数据后台。朱色面积也少了三成。

**B 没有解决的。** 品牌识别没有变化。主按钮仍是音符的朱色，链接仍是咔的浅葱，一屏里红色既是按钮又是数据。这一半只有 C 解决。

**C 的代价，如实列出：**
1. **咔的颜色改了。** 品牌青绿与咔几乎同色相，C 里把咔向蓝偏移（`15` 的 B5）。这是 B 与 C 之间唯一一处游戏语义色的差别。
2. **深色偏平。** 深青的页面与卡片明度接近，层次不如夜藍。
3. **朱色的数据更跳。** 密度图的难点、成绩条在青绿底上比以前显眼。
4. **大数字不如 A 醒目。** Rating 改为中性色后，首页的第一视觉点从红色数字变成了曲绘。
5. **蓝色系的小徽章靠近品牌色。** 段位徽章的中档颜色看起来像品牌色的近亲。
6. **路由切换 p95 从 61ms 升到 86ms**（预算 200ms）。只测了一轮，可能是波动，Phase B 要多轮复测。

**B、C 共有的问题：**
- 密集表格里的评价图标必须配文字才好读。
- 默认头像全部相同，社区显得平（原型局限）。
- 称号牌只能放在宽的位置，列表行里是文字。
- 「真实曲目集」里有 6 首歌的缩略图在正式站返回 404，显示为缺失占位。

**我的建议是 C。** 理由是它同时解决两个问题，而且它的代价都是可以在 Phase B 里处理的细节，不是方向性的问题。如果你不接受咔改色，或者觉得深色太平，可以选 B，再单独决定品牌色。完整的建议与待裁定事项在 `18`。

## 7. 性能与真实图片

**搜索与路由（生产构建，1440×900）：**

| 指标 | 预算 | A | C |
|---|---|---|---|
| 搜索首键 p95 | ≤ 50ms | 15.4ms | 16.3ms |
| 搜索热态 p95 | ≤ 50ms | 14.0ms | 14.7ms |
| 路由切换 p95 | ≤ 200ms | 61.4ms | 85.8ms |

其余预算（筛选、排序、挂载行数、长任务）在版本 A 的完整运行里全部通过。

**真实图片（B 与 C，冷缓存，`real` 数据）：**

| 页面 · 视口 | 曲绘请求（KB） | 本地图标请求（KB） | 首屏最后一张图加载完成，B / C | 失败 |
|---|---|---|---|---|
| 今日 1440 | 12（138） | 5（103） | 1312 / 1535ms | 0 |
| 今日 390 | 1（7） | 5（103） | 2830 / 1510ms | 0 |
| 歌曲详情 1440 | 1（7） | 6（77） | 1270 / 1319ms | 0 |
| 歌曲详情 390 | 1（7） | 6（77） | 1322 / 2177ms | 0 |
| 全部成绩 1440 | 21（142） | 9（191） | 1961 / 2406ms | 6 / 30（正式站没有这些缩略图） |
| 全部成绩 390 | 9（79） | 9（191） | 1235 / 2205ms | 0 |
| 社区 1440 | 3（33） | 3（19） | 1368 / 1366ms | 0 |
| 社区 390 | 2（27） | 3（19） | 1025 / 1024ms | 0 |

- **本地图标比曲绘还重。** 评价图是 200×200 的 PNG，每张 19–42 KB，成绩页首屏光图标就有 191 KB。正式实现应该给评价、王冠准备小尺寸版本。
- **布局偏移**：每个页面都与 A 相同（CLS ≤ 0.0008）。图片有固定的宽高。
- **屏蔽曲绘域名**：所有曲绘变成缺失占位，布局与正常加载时相同，没有页面错误；控制台只有资源加载失败的记录。
- **快速滚动**（2 秒内滚 60 次）：成绩页发出 57 个请求、其中 14 个在行被回收时取消；曲库 48 个、取消 10 个。3 秒后没有残留请求，请求数不超过列表长度。
- 加载时间取决于这台机器到静态域名的网络，只能作参考。原型的图标是本地文件，正式站经过 CDN。

## 8. 验证程度

**已通过实际浏览器验证**（Chrome 151，生产构建）
- 64 张对照截图与 20 张三联图；A 的逐像素一致；B 与 C 的布局一致。
- B、C 在四个页面上的定向检查：96 个用例（5 种视口 × 深浅色 × B / C，加日文），0 错误、0 警告。检查项包括对比度、横向溢出、固定栏遮挡、触控目标、行内链接、可访问名称、文字相撞。
- 真实图片的加载指标、屏蔽域名、快速滚动。
- 版本 A 的完整运行：378 个用例（比 V1.2 多的 10 个是两个新的评审页）、18 条流程。出现过 5 个错误，都是新的对照页缺少主要内容区的标记，修正后重跑这 5 个用例为 0 错误。
- 设计负责人看过的图：今日 1440 浅色三联图与 B、C 单张；成绩 1440 浅色的 A、C 与深色的 B、C；歌曲详情与社区 1440 的 C（深浅色）；今日 390 深色、成绩 390 浅色、社区 390 浅色、歌曲详情 360 深色的三联图；素材页浅色整页。其余截图由执行方逐张看过并报告，我没有逐张看。

**仅源码或静态检查**
- 对比度脚本：Fumen 与青绿、深浅各一套，共 562 对，全部达标。为了达标，青绿下有 12 个游戏数据的文字色在同一色相内调了明度；`15` 里列的品牌与表面色没有改。
- 搜索 42 项、同步 19 项、模拟数据自检、生产构建。
- 评价图 2–8 与评价值的对应：看图确认，选图的代码在 Bot 仓库。

**尚未验证**

- 有真实上传头像时社区的观感。
- 真机、Safari、Firefox、读屏软件，以及 V1.2 报告里列的其他未验证项。
