## 1. 阶段 0 做什么、不做什么

### 1.1 范围

阶段 0 只做四件事：

1. **设计系统**：V1.3 的 token（品牌、语义、角色、领域）、对比度检查、Element Plus 变量映射、字体方案。
2. **工程基础**：素材映射与校验、小尺寸素材的生成、共享的换算工具、目录与命名约定、几条自动检查。
3. **组件样张**：业务原子组件与图表组件，各自在样张页上展示全部状态。
4. **兼容性**：确认上面这些在 Nuxt 的 SSR、i18n、PWA、主题机制下工作正常，并且现有页面没有任何变化。

### 1.2 不做什么

- 不替换、不改动任何现有页面的外观和行为，包括 `layouts/default.vue`、`SongCoverImage`、`PassportMetricChart`、`ForumUserBadge`、`TitleBadges` 等现有组件。
- 不全局切换 Element Plus 的主色，不让旧的 `--viewer-*` token 指向新 token（见 1.4）。
- 不移植原型的路由、`store`、同步状态机、搜索、`useQueryState`、模拟数据和评审页。
- 不改业务逻辑：Rating、成长事实、目标判定、同步、成绩换算的现有实现都不动。新的换算工具只给新组件用，并用测试证明与现有逻辑结果一致。
- 不新增或修改后端接口、数据库结构，不连接生产数据库。
- 不做 `12` A7 里任何一项数据模型差异所需要的功能。
- 不做软键盘避让本身（属于社区阶段），只做防止同类样式错误的检查。
- 不部署。是否以及如何发布见决定 D0-8。

### 1.4 与 `06` 阶段 0 旧写法的差异

`06` 在本文写作期间已经按 V1.3 更新，下表左列是更新前（V1）的写法，留在这里说明为什么不按它做。更新后的 `06` 与本文一致。起草时发现的两处差异已经对齐：Element Plus 的 info 色在 `06` 里改为中性色（仍待你在 D0-3 确认）；「跟随系统」主题不放在阶段 0，移到 `06` 的待决定事项（见第 7 节）。

| `06` 旧写法 | 阶段 0 实际怎么做 | 原因 |
|---|---|---|
| `--el-color-primary: var(--don)` | 映射到 `--brand-primary`，而且只在样张页范围内生效 | C2；生产现在的 `--el-color-primary` 指向朱色 `--viewer-primary`，全局改成青绿会改变现有页面的主按钮、焦点环（见 2.2），违反 C1 |
| 旧 token 暂时作为别名指向新 token | 阶段 0 不做别名，只产出一张新旧对照表（P0-05）；别名在阶段 1 换框架时做 | 别名一旦生效，深色主题的底色、主按钮颜色都会变（见 2.1），违反 C1 |
| 把 `tokens.css` / `base.css` / `domain.css` 迁入 `assets/css/` | token 迁入；`base.css` 与 `domain.css` 只按组件需要重写，并限定在新组件和样张页范围内，不进入全局入口 | 原型的 `base.css` 会重设 `body`、链接、按钮等全局样式，会改变现有页面 |
| `PassportMetricChart` 等现有 SVG 图表并入 | 不并入，留到阶段 2 | 并入就是替换现有页面里的组件 |
| 统一断点为 767 / 1099 / 1239 | 只对新代码生效；现有页面里的 720、960 等断点不动 | C1 |
| 业务原子组件含 `SongCell` | 保留，作为组合样张（P0-24） | — |

## 2. 生产现状

本节只写在 `origin/main` 上读到的事实。读不到或不能确定的，写在 2.10。

### 2.1 Token 与全局样式

- 全局样式入口只有一个：`nuxt.config.ts` 的 `css: ["~/assets/css/main.css"]`，`main.css` 第一行 `@import "./tokens.css"`。
- `assets/css/tokens.css` 定义 `--viewer-*` 一套语义色（`html:root` 与 `html[data-theme="dark"]` 两块），以及 Element Plus 变量映射（见 2.2）、字体栈、圆角、间距、内容宽度。
- **浅色的大部分值已经和 V1.3 的语义 token 相同**：`--viewer-bg` `#eaf6f5` = `--bg`；`--viewer-surface` `#f9fdfc` = `--surface`；`--viewer-surface-subtle` `#def0ee` = `--bg-sunk`；`--viewer-text` `#203f43` = `--ink`；`--viewer-text-muted` `#4d696c` = `--ink-3`；`--viewer-border` `#ccdfdc` = `--line`；`--viewer-control-border` `#6e8c8e` = `--ctl-border`；`--viewer-link` `#006c76` = `--brand-primary`；`--viewer-selected` `#d7ece9` = `--brand-soft`；`--viewer-success` `#26724e` = `--ok`。
- **不同的地方**：主色 `--viewer-primary` 是朱色 `#bd352f`（深色 `#ff9a8e`），主按钮用它；深色主题的值是 V1.3 之前的一版（例如 `--viewer-bg` `#10282b`、`--viewer-surface` `#193338`，V1.3 是 `#0c2023`、`#1a383d`）；没有 `--overlay-bg`、`--brand-*`、角色 token、领域 token；难度色 `--viewer-difficulty-*` 是另一组值。
- `nuxt.config.ts` 在构建时读取 `tokens.css`，用正则取第一个 `--viewer-bg:` 的值作为 `theme-color` 与 PWA 清单的 `theme_color`、`background_color`。改 `tokens.css` 的结构可能改变这两个值。
- `main.css` 里有全局元素样式：`body` 15px、`font-variant-numeric: tabular-nums`；`a` 的颜色；`:focus-visible` 3px 描边；外壳 `.app-shell`、`.app-sidebar`；Element Plus 控件的高度与颜色覆盖。断点主要是 960px。
- 现有组件里，与 V1.3 token 同名的自定义属性：`--accent`（`components/forum/ForumThreadCard.vue` 与 `pages/forum/thread/[id].vue` 在元素上内联设置并读取）、`--stage-ink`（年度回顾的 `AnnualProfileStageFrame.vue` 局部定义）。`server/services/reverse-oidc/interaction.ts` 输出的是独立 HTML 页面，自带 `--bg`、`--line`、`--accent`，与站内样式表无关。
- 全仓库的断点：`max-width: 720px` 约 32 处、`960px` 13 处、`980px`、`860px` 各 5 处；767 / 1099 / 1239 一共 5 处。

### 2.2 Element Plus

- 依赖：`element-plus` `^2.9.0`（锁定 2.13.2），通过 `@element-plus/nuxt` 引入，`elementPlus.importStyle: "css"`。
- 主题全部靠 CSS 变量：`tokens.css` 里 `--el-color-primary: var(--viewer-primary)`（朱色），`light-3/5/7/8` 用 `color-mix()` 与 `--viewer-surface` 混合，`light-9` 用 `--viewer-primary-surface`；success、warning、danger、error、info 各自映射；背景、填充、文字、边框、圆角（8 / 6px）、阴影、遮罩、菜单高度 44px、字号 15px 也都映射了。
- `main.css` 另有一批覆盖：`.el-button` 最小高度 44px，主按钮悬停色，输入框聚焦边框用 `--viewer-link`，下拉选中项，表格，深色 Tooltip 等。
- 现有代码直接读 `--el-color-primary` 的有 6 个文件、11 处（例如 `components/home/PlayerGrowthSurface.vue` 的焦点环、`pages/account/sync.vue`、`pages/alias-log.vue`）。`type="primary"` 的按钮约 79 处。所以全局改主色会立刻改变现有页面。
- Element Plus 的弹层（对话框、下拉、Tooltip、消息）默认挂到 `body`，不在页面容器里。

### 2.3 字体

- 正文用系统字体栈：`--viewer-font-zh`（PingFang SC、Microsoft YaHei 等）、`--viewer-font-ja`（Hiragino Sans、Yu Gothic 等），按 `:lang(ja)` 切换。站内没有自托管的中日文网页字体。

### 2.9 现有代码里已经有同一类 scoped 样式错误

`pages/admin/taiko/chart-ugc.vue` 第 212 行写的是 `:global(body.theme-dark) .ugc-admin-panel { ... }`。用 Vue 编译器（原型目录里的 `@vue/compiler-sfc` 3.5.45；生产锁定的是 3.5.43）实测：

| 源码 | 编译结果 |
|---|---|
| `:global(:root[data-kb]) .composer{bottom:0}`（原型 `Thread.vue`） | `:root[data-kb]{bottom:0}` |
| `:global(body.theme-dark) .ugc-admin-panel{background:red}` | `body.theme-dark{background:red}` |
| `:global(body.theme-dark .x){color:red}` | `body.theme-dark .x{color:red}` |
| `:root[data-kb] .composer{bottom:0}` | `:root[data-kb] .composer[data-v-abc]{bottom:0}` |

所以这个后台页面在深色下的那组规则很可能落到了 `body` 上。它不在阶段 0 范围内，阶段 0 不修，只在检查结果里列出来，由你决定是否另开修复。生产里其余 `:global(...)` 都是把整个选择器包在括号里的写法，编译结果正确。

### D0-1 样张页放在哪里、谁能看到（阶段 0 开始前）

| 选项 | 说明 | 代价 |
|---|---|---|
| A. 只在开发与测试构建里存在 | 页面不放在 `pages/` 下，用 `pages:extend` 钩子在开发模式或显式环境变量（例如 `TAIKO_DS_SAMPLES=1`）时注册；生产构建没有这个路由 | 你要看样张，需要在服务器上用 `scripts/memory/run_dev.sh` 起开发服务器，或用开启变量的测试构建；手机上看要能访问那台服务器 |
| B. 生产里的后台页面 | 例如 `/admin/taiko/design-system`，沿用 `admin-auth` 与 `noindex`，只有管理员能进 | 样张页的代码进入生产构建；会被流量统计扫描到；后台布局的外框不是新设计 |
| C. 生产里的隐藏公开页 | 不进站点地图，加 `noindex` | 任何人知道地址都能打开，看到未发布的设计；不建议 |

**建议 A。** 阶段 0 的目标是「生产上没有变化」，A 最干净：构建产物里连代码都没有。真机看字体、头像这类需要时，在服务器上开测试构建。如果你希望在正式站上用自己的账号看，再加 B，C 不做。

### D0-2 新旧 token 怎么并存（阶段 0 开始前）

| 选项 | 说明 | 代价 |
|---|---|---|
| A. 新 token 用规格里的名字（`--bg`、`--ink`、`--brand-primary` 等），声明在 `:root` 与 `html[data-theme="dark"]`，放在单独的文件里；阶段 0 只由样张页加载；旧的 `--viewer-*` 不动 | 自定义属性本身不影响渲染，只有被读取时才起作用 | 要检查同名冲突（2.1 列的 `--accent`、`--stage-ink`）；客户端从样张页跳到别的页面后，样式表仍然留在页面里，所以 token 文件里只能有自定义属性，不能有元素样式 |
| B. 新 token 全部加前缀（例如 `--ds-bg`） | 不会和任何现有名字冲突 | 与 `04`、原型的名字对不上，查规格要多一层换算；阶段 1 还要再改名一次 |
| C. 按 `06` 原文，旧 token 作为别名指向新 token | 现有页面立刻换上新色 | 现有页面可见变化（主按钮、深色层次），违反 C1 |

**建议 A**，加一条自动检查（P0-04）：新 token 文件里声明的名字，在现有代码里如果被读取而没有就近定义，就报出来。别名在阶段 1 做，阶段 0 先产出对照表（P0-05）。现有 `tokens.css` 不改，避免影响 `theme-color` 的读取。

### D0-3 Element Plus 映射的生效范围，以及 info 色映射到哪里（阶段 0 开始前定范围；P0-08 之前定 info）

范围：

| 选项 | 说明 |
|---|---|
| A. 只在样张页生效 | 样张页在 `<html>` 上加一个类（例如 `ds-preview`），映射写在 `html.ds-preview` 下，这样挂到 `body` 的弹层也能拿到；离开页面类被移除 |
| B. 在样张页的容器上生效 | 弹层挂在 `body`，拿不到映射，要给每个弹层设 `teleported: false` 或 `append-to`，样张就不能代表真实用法 |
| C. 全局生效 | 现有页面的主按钮从朱色变青绿，违反 C1 |

**建议 A**，全局切换放到阶段 1。要实测 `keepalive` 下类会不会残留（2.10）。

info 色：V1.2 的提案把 `--el-color-info` 映射到咔色（`--ka-ink`），V1.3 规定音符色不表示交互，这条作废；V1.3 的 `04` 没有重写 Element Plus 映射（`12` RK-31、B2.7 引用的 `04` §14 只在 V1.2 版本里有）。Element Plus 的 info 用于中性的标签、按钮和消息。选项：映射到品牌（`--link` / `--info-*`），或映射到中性（`--ink-2` / `--bg-sunk`）。**建议中性**：品牌色只留给主按钮、链接和选中，info 标签、info 按钮如果也是青绿，一个区域里会出现多处品牌色（`04` §5 的自查清单）。设计负责人同意用中性，`06` 第 1 节已经按中性写；你如果选品牌，`06` 那一句要改回去。

### D0-4 字体（阶段 0 期间，P0-10 实测之后）

| 选项 | 说明 | 代价 |
|---|---|---|
| A. 全部自托管：Noto Sans SC / JP（按 unicode-range 分片）+ Barlow + Barlow Condensed | 与原型一致 | 汉字字体分片多、请求多；体积待实测（原型的文件总量 SC 约 4.6 MB、JP 约 5.6 MB，实际传输量取决于页面用到的字） |
| B. 只自托管 Barlow 与 Barlow Condensed（拉丁字母与数字），中日文用系统字体 | 数字与英文的观感与原型一致；中日文与现在的生产一样 | 中日文的字形在不同系统上不一致（与现在相同）；规格里的字体栈已经把系统字体写在 Noto 后面，不需要改 token |
| C. 不用网页字体 | 零增量 | 数字层级（`04` §4）依赖窄体数字字体，观感会偏离原型 |

**建议先按 B 落地，同时在样张页实测 A。** 只有实测的首屏字体字节数和 FOUT 在你定的预算以内，才在后续阶段改成 A。这是 `12` B1.3 要求的决定，需要写明首屏字体字节预算。字体文件只在样张页加载，现有页面不请求任何新字体。

### D0-5 小尺寸素材在哪里生成、放在哪里、用什么编码（P0-12 之前）

| 选项 | 说明 |
|---|---|
| A. 在生产仓库里用 `sharp` 重新生成，WebP 用无损编码，同尺寸 PNG 作回退；产物提交到 `public/icons/crown/{36,60,96}/`、`public/icons/rank/{56,80}/`，原图不动 | `sharp` 已经是依赖；能做无损 WebP，解决 `22` §7「小尺寸素材的编码」那一项；脚本可重复运行，带 `--check` |
| B. 直接复制原型 `public/game/` 里的产物（有损 0.92） | 最快；但编码是有损的（`12` RK-52），生成脚本依赖系统 Chrome，不适合放进生产仓库 |
| C. 构建时生成，不提交产物 | 构建依赖图片处理，部署脚本的构建时间和失败面都变大 |

**建议 A。** 注意 `sharp` 的缩放核（默认 lanczos3）与原型的「逐级减半 + 高质量重采样」不同，可能出现振铃，要按 `19` G5 在 1× / 2× 下与原图并排看，确认图形没有走样。尺寸目录与原型相同，组件的选图规则（`smallSrc`）照用。

### D0-6 王冠不靠颜色区分的具体形式（阶段 2 的正式成绩组件之前；阶段 0 只预留接口）

`04` §7.5 与 `19` G4 的规定是列表里王冠旁不加文字，三档只靠颜色区分，记为已知局限。你的 P1 要求正式成绩组件改为看得见的区分，同时保留原素材。这一项改变了 `04` 的写法，按 `22` 第 9 节需要一条变更裁定。可选的形式：

| 选项 | 说明 | 问题 |
|---|---|---|
| A. 王冠旁加文字：桌面全名（通关 / 全连 / 全良），手机短名 | 与评价的做法一致（`19` G4） | 手机成绩行 375 宽以下已经为评价名让出了判定数的位置，再加文字可能放不下，需要重新排 |
| B. 王冠旁加一个小的文字标记（单字或缩写），不压在素材上 | 占位小 | 单字要选不会和判定「良」混淆的写法；需要可读性确认 |
| C. 只在正式成绩组件的表头或分组里写明，行内不加 | 改动最小 | 行内仍然只靠颜色，可能不满足 P1 |

**建议 A**，在阶段 2 设计成绩组件时按真实宽度试排，放不下的宽度再讨论 B。不建议在素材上叠加任何东西（违反 `16` A0 与 `12` B12.2）。阶段 0 的 `Crown` 组件预留一个控制可见文字的属性（不显示 / 短名 / 全名），默认不显示，与 `04` 现行规定一致。

### D0-7 服务端的默认头像怎么处理（P0-20 之前定组件行为；服务端的改动在社区阶段）

| 选项 | 说明 |

## 6. 阶段 0 的风险，以及什么情况下停下来

| 风险 | 表现 | 应对 | 停止条件 |
|---|---|---|---|
| 新样式漏到现有页面 | 客户端从样张页跳走后，`ds-preview` 类或 Element Plus 映射残留；token 同名 | P0-04、P0-26 的残留检查、P0-34 | P0-34 有任何解释不了的差异：停，查清再继续 |
| 预缓存或入口体积变大 | 新字体、素材、样张代码进了 Service Worker 清单或入口 CSS | P0-33、P0-35 | 现有用户需要多下载东西：停，先改排除规则 |
| `keepalive` 下 `useHead` 的行为与预期不同 | 离开样张页后 `<html>` 上的类不消失 | P0-26 的两种退路 | 两种退路都不行：回到 D0-3，改为容器范围 + 逐个弹层处理，并把对样张代表性的影响告诉你 |
| 小尺寸素材用 `sharp` 生成后走样 | 振铃、描边变细或变色 | 换缩放核，或按原型的逐级减半做法 | 对照图仍能看出变化：停，回到 D0-5 |
| 字体体积超出预算 | 汉字分片请求多、FOUT 明显 | D0-4 先按 B | 不影响阶段 0 完成；只影响后续阶段是否改用 A |
| 规格与生产数据或机制冲突 | 例如 info 色、`Cover` 的缓存绕过、服务端默认头像 | 第 3 节列出的决定；新发现的写变更裁定 | 需要改 `04` / `16` / `19` / `22` 里任何一条裁定：停，先写变更裁定等你批 |
| 有人顺手修现有代码 | 例如修 `chart-ugc.vue` 的样式、改 `SongCoverImage` 的回落、把 `SongListContent` 的旧路径换掉 | 4.0 的「允许改动的现有文件」清单；评审时逐个文件核对 | 发现越界的改动：撤回，另开任务 |
| 浏览器 QA 只能在服务器上跑 | Windows 工作区跑不了内存隔离脚本 | 所有浏览器检查在服务器上通过包装脚本运行 | 包装脚本拒绝运行（锁被占用、内存不足）：等，不绕过 |
| 需要真实数据才能验的项 | B2.6 真实成绩比对、B12.4 Bot 选图、上传头像的各种比例 | 阶段 0 只做能离线验的部分，其余记为未验证 | 不阻塞阶段 0；必须在对应功能的阶段之前完成 |
| 测试意外连到数据库 | 跑现有 `test:*` 时触发连库 | 只跑不连库的；连库的确认 `SELECT DATABASE()` 以 `_test` 结尾并显式开启写入 | 任何对生产库的连接：立即停，这是阻塞问题 |
