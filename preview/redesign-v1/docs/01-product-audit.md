# 01 · 现有产品审计

审计对象：`taiko_viewer/`（Nuxt 3.21 + Element Plus，版本 1.14.0，76 个页面、122 个组件）。
审计目的是理解产品，不是继承设计。结论直接决定了 Design V1 的信息架构（见 `03-ia-mapping.md`）。

## 1. Viewer 是什么

一句话：**太鼓达人玩家的数据与社区平台**。README 的说法是 "My Taiko, in one place."，1.0 收口了四条主线：My Viewer、Community、Training、Progress。

把 76 个页面按「玩家想做的事」重新归类，实际上是六件事：

| 玩家想做的事 | 现有功能 | 频率 |
|---|---|---|
| 查一首歌 | 歌曲列表（实装 / 未上架 / 其他）、歌曲详情、V2 定数、谱面图、试听、练习播放器 | 高 |
| 看自己打得怎样 | 歌曲数据（成绩管理）、B30 表、Rating 走势、歌曲进度、词云 | 高 |
| 知道接下来练什么 | 推荐歌曲、目标（这次想练）、今日计划 | 高 |
| 看见自己在变强 | 首页成长面、每日进展、最近成长、这一周、成长档案、年度回顾 | 中高 |
| 和别人交流 | 社区九个版块、帖子、通知、谱面 UGC（体感投票 / 标签 / 提示） | 中 |
| 把数据接进来、管好账号 | 绑定（鼓众广场 / Donder Hiroba / 手动 / QQ）、多端同步、成绩 token、OIDC、开发者、工单 | 低频但关键 |

另有查询型工具（查配置、查物量、RT 计算器、TJA 定数与谱面图）、参考内容（段位道场、谱面攻略、称号、别名日志）和独立的管理后台。

## 2. 主要用户流程

1. **查歌**：首页搜索或「实装歌曲」→ 歌曲详情 → 选难度 → 看谱面图 / 试听 / 定数 → 练习播放器、RT 计算器、投票打标签、看相关讨论。
2. **入门**：注册 → 个人档案里绑定鼓众广场 ID（改游戏内称号验证）→ 多端同步 → 首页出现成长面。
3. **练习闭环**：首页成长面或推荐页选歌和目标类型 → 去机厅打 → 同步 → 在首页或同步页「确认进展」→ 结果进入每周回顾和成长档案。
4. **社区**：社区首页 → 版块或帖子 → 回复 / 点赞 → 发帖（可关联歌曲与难度）→ 通知。
5. **年度回顾**：首页横幅 → `/annual`（邀请码、登录、绑定、同步）→ 故事 → 海报 / 分享。仅限手机。
6. **开发者**：申请 → 审批 → token；第三方应用授权；成绩 token 在同步页签发。

**四种登录态**决定了几乎所有个人页面的呈现：游客、已登录未绑定、已绑定无成绩、已就绪。

## 3. 信息架构的问题

### 3.1 入口重复，枢纽过多
同步、开发者、社区、工单的入口同时出现在侧栏、`/more`、`/my` 和 `/settings`。`/settings` 的大部分内容是链接而不是设置。桌面侧栏和手机的两个枢纽页（`/my`、`/more`）是三套并行的导航。

### 3.2 「工具」这个桶装了两类东西
`/tools/*` 里既有个人数据视图（B30、走势、推荐、进度、词云；面包屑写「我的太鼓」），又有公共查谱工具（面包屑写「更多」）。`/tools` 本身重定向到 `/more`。

### 3.3 个人数据散落在三个路径下
成绩在 `/account/songs`，成长在 `/my/*`，Rating 相关在 `/tools/*`。同一个页面在三处有三个名字：侧栏叫「歌曲数据」，`/my` 叫「成绩管理」，页面标题是「本地歌曲数据」。

### 3.4 命名不一致
| 概念 | 出现过的叫法 |
|---|---|
| 每周回顾 | 每周回顾 / 这一周 |
| 曲库 | 发现 / 歌曲列表 / 歌曲 |
| 工具 | 工具 / 查谱工具 |
| 账号区 | 账号系统 / 账户与设置 |
| 年度回顾 | 虹2025太鼓回顾 / 虹2025版本总结 / 2026 太鼓故事 |
| 游戏账号 | 鼓众 ID / 鼓众广场 ID / 太鼓账号 |
| 难度 | 普通 vs 一般；魔王（里）vs 里谱 |

### 3.5 层级过深
- 谱面攻略在侧栏里展开成「难度 → 星级」约 50 个叶子。
- 段位是三级重定向：`/grade` → `/grade/2026` → `/grade/2026/五級`；2023 / 2024 是另一套实现。

### 3.6 关键流程被埋住
- **绑定**是入门最关键的一步，却是 2,200 行、18 张卡片的 `/account/profile` 中的一段。
- **目标**没有自己的页面：在首页、推荐页、歌曲详情创建，进展要去同步页或首页看。
- 歌曲详情里的分析（V2 定数、六维雷达）和歌曲信息默认折叠。

### 3.7 权限引导不一致
有的页面中间件硬跳登录页，有的页面内联提示（`AccountToolGate`），文案各不相同。

### 3.8 缺失
没有全局搜索（搜索只存在于各列表内部）；没有对外的玩家主页；没有法律 / 隐私页面。

## 4. 视觉与设计系统的问题

1. **Token 很少，硬编码很多**。全站圆角只有 `--viewer-radius: 14px` 一个值，而组件里出现了约 30 种圆角、约 30 种字号；没有字阶和间距阶梯。
2. **游戏语义没有被表达**。王冠和评价（粹 / 雅 / 极）是纯文字；流派色被计算出来又被样式覆盖；难度色存在两套互相矛盾的定义。
3. **换过色，没换过设计**。自动化的 token 替换留下了单色「渐变」、两半同色的鼓面图标等痕迹。
4. **实际上有两套设计系统**。主站约 24 个十六进制色值；年度回顾与后台有 387 种色值、223 处渐变，并有独立的 `--annual-*` 规范。
5. **卡片套卡片**。成绩「泳道」同时有 7px 左边框、渐变、阴影和 290px 最小列宽，再放进已经是卡片的页面里，手机上很重。
6. **三套图表实现**。后台用 ECharts，成长与年度用手写 SVG，B30 / 走势 / 进度 / 词云是服务端渲染的 PNG —— 后者不能跟随深色模式，也不能交互。
7. **断点零散**。主断点 960px，组件里另有 15 个以上的临时断点。
8. **深色模式有盲区**。服务端 PNG、练习播放器、年度场景不跟随主题；没有「跟随系统」。
9. **65 个组件绕过 i18n**，用内联的 `locale === 'ja' ? … : …`。

## 5. 桌面与手机的差异（现状）

- 同一套布局，960px 以下侧栏变成抽屉，出现底部五格（首页 / 歌曲 / 社区 / 我的 / 更多）。
- 没有为手机单独设计的页面；表格、设置页基本是等比缩放。
- 年度回顾反过来只支持手机，桌面会被重定向回首页。

## 6. 对重新设计的要求（由审计推出）

| 发现 | 设计要求 |
|---|---|
| 查歌最高频，却没有全局搜索 | 全局搜索是一级入口，任何页面一步可达 |
| 个人数据散在三处 | 按「成绩 / 成长」两个目的地重组，路径和命名统一 |
| 同步是成长的前提，但入口很深 | 同步状态常驻顶栏，一键触发 |
| 绑定被埋在档案页 | 绑定成为独立的三步流程 |
| 目标没有家 | 目标有独立页面，创建入口仍保留在各处 |
| 王冠 / 评价 / 难度只有文字 | 建立一套业务原子组件，全站唯一来源 |
| 图表三套实现 | 统一为可主题化的原生图表 |
| 权限引导不一致 | 一种引导形态：留在原地，说明差哪一步，给出那一步的按钮 |
| 手机只是缩放 | 手机单独设计：列表行、底部抽屉、固定操作条 |
