## G1 · 深色主题拉开层次

Phase A 的深色里，页面、卡片、分区的明度挤在一起。C+ 把页面压暗、把表面提亮，并给浮层单独一级。

| Token | Phase A | C+ | 说明 |
|---|---|---|---|
| `--bg-sunk` | `#0B1E21` | `#081619` | 下沉区、谱面带 |
| `--bg` | `#10282B` | `#0C2023` | 页面 |
| `--surface` | `#193338` | `#1A383D` | 卡片、面板 |
| `--surface-2` | `#234247` | `#234A50` | 表面上的分区、表头、悬停行 |
| `--overlay-bg`（新增） | 与 `--surface` 相同 | `#265056` | 对话框、抽屉、搜索面板、菜单、浮动面板 |
| `--line` | `#2E4E52` | `#2F5257` | 分隔线 |
| `--line-strong` | `#3D6165` | `#447378` | 强分隔、卡片外框 |
| `--brand-soft` | `#244B4E` | `#2A565A` | 选中浅底，要在 `--surface` 上看得出 |
| `--ink-3` | `#8FB0B0` | `#A3C0C0` | 弱文字，要在 `--surface-2` 与 `--overlay-bg` 上 ≥ 4.5:1（最初定的 `#9ABABA` 在浮层上只有 4.27:1） |
| `--ctl-border` | `#719B9D` | `#779FA1` | 控件边框，要在浮层上 ≥ 3:1 |

- 浅色主题下 `--overlay-bg` 等于 `--surface`。浮层另有阴影和 1px `--line-strong` 外框。
- 页面到卡片的明度差约为 Phase A 的两倍。目标是五级能一眼分开：下沉 < 页面 < 卡片 < 分区 ≈ 浮层。
- 卡片在深色下加 1px `--line` 外框（浅色已有）。
- 品牌色、文字色、真实素材都不变。银色王冠的黑描边在深色下看不见，这是素材本身的样子，不处理。
- 全部数值用对比度脚本验证；不达标的在同一色相内调明度，并报告改了哪些。

## G2 · 核心数据靠排版突出，不靠红色

Rating、最好成绩、重要变化的层级由字号、字重、位置和对比度建立。

| 对象 | 规则 |
|---|---|
| 每张卡片的主数字（Rating、最好成绩、Rating 表的合计） | `--ink`，数字字体，字重 700，用这张卡片里最大的一档字号；同一张卡片里其他数字至少小两档 |
| 主数字旁的辅助数字（上限、百分比、次数） | `--ink-2`，字重 500 |
| 变化量 | 上升：`--ok` 加上箭头；下降：`--ink-2` 加下箭头。不用红色表示下降 |
| 新纪录、新全连、新全良 | 行首一个咚色的音符点（沿用谱面带图例的画法），标题加粗。只有这个点是朱色，文字不是 |
| Rating 圆环 | 环用品牌色，环内数字 `--ink`，是首页第一屏里最大的数字 |

- 今日页首屏的阅读顺序：一句话摘要 → Rating → 这次想练 → 最近 21 天。Rating 卡片的数字比 Phase A 大一档，如果圆环里放不下，就加大圆环，卡片外尺寸不变。
- 歌曲详情「我的成绩」里，最好成绩是卡片里唯一的最大字号；王冠、评价排在它上方一行，尺寸不超过数字的高度。

## G3 · 朱色数据保留语义，收窄范围

朱色仍然表示咚、良、难点。问题是在青绿底上，大面积的朱色成了一屏里唯一的焦点。

- **小图形用原色，大面积用柔化色。** 新增 `--don-data`：只用于图表里成片的朱色（密度图的难点柱、成绩判定条的「良」段、雷达与折线里的朱色填充）。浅色 `#E58572`（最初定的是 `#E0705C`，全站推广后按下面的验收结果调浅了一档），深色 `#E8806C`。音符、图例圆点、新纪录的点、通知角标、咚键仍用 `--don` 原色。
- **判定条变细。** 成绩判定条高 6px。数字仍在条下方，信息不变。
- **密度图。** 普通小节用 `--line-strong`，难点小节用 `--don-data`。图的尺寸不变。
- **验收口径。** 歌曲详情首屏里，朱色带的面积不超过品牌色带的 60%。用 Phase A 的同一套像素统计，四个代表页面前后对比。统计时排除曲绘和头像：它们是图片，不是界面自己的颜色。正式站的默认头像是橙粉渐变，落在朱色带里，不排除的话社区页的数字会被它拉高。
- **结果：16 个状态里 15 个达标，1 个没有达标。** 歌曲详情在 1440 宽、浅色下是 0.70。调浅 `--don-data` 没有改变这个数：统计按色相分带，调浅不改变色相。剩下的朱色主要是谱面图里的音符，那是谱面内容，不动；另外页头的「游玩练习」降为次要按钮后，品牌色的面积变小了。这一项按「没有达标」记录，不再调整口径，也不为了数字去改谱面图。
- **歌曲详情只有一个主按钮。** 「设为这次想练」（手机上是「想练这首」）是主按钮，页头的「游玩练习」在桌面上也是次要按钮。
- 谱面带、谱面图里的音符不动。

## G4 · 评价：手机上图标加短名

- 桌面密集表格：图标（占位 24，绘制 28）加评价名，沿用 Phase A 第二轮的做法。
- 手机列表行：图标后面跟两个字的评价名（白粹、铜粹、银粹、金雅、粉雅、紫雅、极；日文同理），`--fs-11`、`--ink-2`。图标缩为占位 20、绘制 24，给文字让位。
- 375 宽以下，成绩行不显示「良 / 可 / 不可」三个数，把位置让给「王冠 + 评价图标 + 评价名」，排法与 390 宽相同。三个数在 375 以上和歌曲详情里仍然显示。任何宽度下评价名都不省略，评价不能只靠颜色区分。
  - 最初的写法是「放不下时评价名换到图标下方」。实现后在 360 宽下量到：行高 68px，分数超出行顶 5px，评价名超出行底 4px。所以改成上面的做法。
- 王冠的三档只有颜色不同（银、金、彩虹），形状相同。列表里王冠旁不加文字，靠可访问名称和筛选项里的文字说明。这一点记为已知局限。

## G5 · 小尺寸素材（D10）

- 为评价和王冠各做一组缩小版，保留原图。评价：56px、80px（对应 28、40 两种绘制尺寸的 2× 屏）。王冠：36px、60px、96px（对应 18、30、48）。
- 只做等比缩小，不裁切、不改色、不锐化到改变图形的程度。用高质量重采样。格式用带透明通道的 WebP，同时保留同尺寸的 PNG 作为不支持时的回退。这台机器上没有无损 WebP 的编码器，WebP 是质量 0.92 的有损压缩；PNG 回退是无损的。
- 生成脚本放进仓库，可重复运行，输出每个文件缩小前后的字节数。
- 组件用 `srcset` 按屏幕密度选图，图片盒子的宽高固定。
- 在 1× 与 2× 两种屏幕密度下各截一组图，与原图并排，确认图形没有走样。
- 难度图标原图只有 6–7 KB，不做缩小版。
- 报告成绩页首屏图标的总字节数，前后对比。

## G6 · 默认头像与标志（D3、D4）

- 没有头像的玩家统一显示正式站的 `/default-avatar.svg`，原样使用。有 `avatarUrl` 时显示上传的图片；加载失败退回默认头像。
- 去掉 Phase A 的中性鼓面默认头像。模拟玩家仍然没有头像地址：不生成任何随机的身份图。
- 紧凑导航（桌面窄轨、手机顶栏）继续用简化的鼓面标志，鼓缘是品牌青绿。
- 旧版的完整标志（正式站的 `optimized/logo-256.webp`）用在品牌展示的位置：登录页的品牌区。其他位置不强制替换。

## G7 · 段位徽章（D9）

- 正式站的论坛用户数据和账号数据里都查不到段位字段的来源。真实素材模式下，所有表示「这个玩家是几段」的徽章都不显示：社区帖子行、帖子详情作者区、达人榜、个人主页身份带、今日页与「我的」的身份行。
- 模拟数据里的段位字段保留但不渲染，并在风险清单里写明缺口。
- 段位道场页面是 V1.2 信息架构的一部分，保留。它展示的合格记录同样没有确认的数据来源，已在风险清单里。
- 徽章去掉后身份行变短，不补别的东西。

## G8 · 称号（D8、D13）

- Phase A 的规则不变：宽位置用真实牌面，列表行用文字；游戏称号与站内称号是两个组件；没有明确牌面对应的组合只显示文字，不猜。
- 从模拟数据和组件里删掉 `rare` 与虚构的稀有称号集合。称号页里自造的「稀有 / 限定 / 虹」分类一并去掉，改为按正式数据里有的两个维度分组：达成类型（通关、全连、全良）与难度范围。

## G9 · 数据修正（D11、D12、D14）

- **精选曲。** 原型手写的精选曲里，ID 与曲名对不上或没有依据的（702、960、278、233、512、88、1290、41、十首 `1000xx`）全部换掉：换成仓库里有依据的真实曲目（曲号与中日文曲名来自正式站的测试数据），或者明确标成示例曲。换完之后，默认数据里所有带真实曲名的曲目，ID 与曲名都对得上。
- **默认数据的首屏。** 默认数据（1,520 首）保留规模，其中真实曲目排在各页面自然靠前的位置（最近游玩、最近更新、精选帖子关联的曲目），让首屏以真实曲绘为主。合成曲仍然显示示例占位。不为了好看改变排序的含义。
- **缺缩略图的六首**（1255、345、32、1323、395、1324）：检查同一首歌的原图是否存在。原图也没有的，显示中性缺失占位。结果写成一份缺失资源清单。
- **评价映射测试。** 评价值 2–8 与图片文件的对应逐项核对，写成 Node 测试：评价值、中日文名称（与正式站 `scoreRank.ts` 一致）、文件名、文件校验和。看图核对的结果：

## G10 · 全站推广

把品牌 token、角色 token 和真实素材组件用到全部页面。

- **清掉直接用色。** Phase A 剩下的 41 处用咚、咔、连打色表示普通交互的地方全部改成角色 token。改完后，组件与页面里 `--don*`、`--ka*`、`--roll*` 只出现在游戏数据上。
- **导航与主要操作。** 每个区域一个主按钮（品牌实色）；其余是次要按钮或文字按钮。
- **链接、筛选、焦点、选中。** 全部走角色 token。
- **表格与图表。** 单一序列用品牌色；多序列用品牌色加中性色，第三个序列才用别的颜色；表示游戏数据的序列（判定、音符类型、王冠分布）用各自的语义色，大面积时用柔化色。
- **点灯进度。** 格子仍是色块，颜色用 `--crown-*`；图例里用真实王冠。
- **状态。** 成功、警告、危险各一种，不变。通知铃铛上的数字角标保留朱色。
- **年度回顾。** 只统一入口卡片与外围导航，内部不动。
- **设计评审页。** 活样张更新到 V1.3。
- **真实素材。** 曲绘、难度、王冠、评价用到所有出现它们的页面，包括搜索面板的结果行、曲库、成绩各页签、成长、目标、个人主页、帖子详情、通知。

每个页面改完后对照这张清单自查：有没有两个实色按钮并排；有没有红色的非数据元素；有没有只靠颜色区分的状态；深色下卡片与页面是否分得开。

**全站推广后复核截图，补的四条：**

1. 曲库桌面表格：鬼和里都有成绩的行，评价名离日期只有 3px。要求每一行「我的」两格与日期之间至少 12px，宽度从曲名列让出来。
2. 成绩手机行在 375 宽以下的排法，见 G4。
3. 个人主页的五个统计数字要在同一条基线上（原来「极」的数量和 Rating 比三个王冠数低约 4px）。
4. 按单曲 RT 排序的列表（构成 Rating 的成绩、个人主页的代表成绩与最好成绩）原来几乎全是示例占位，看不出真实曲绘的效果。调整模拟数据，让真实曲目排在这些列表的前面。数据规模不变。

**复核后接受、不改的：**

- 浮层上的选中行（搜索面板的当前结果）在深色下用下沉一级的底色。品牌浅底在浮层底色上分不出来。
- 通知未读的小圆点、Toast 里的音符点是朱色，与通知角标同一个意思。
- 登录页左上角的完整标志是 32px。
- 默认头像的橙粉渐变是每一屏里最鲜艳的元素。这是裁定 D3 的结果，原样使用，不调色。

## G12 · 验收

- 完整浏览器矩阵跑在默认状态（C+）上：1440、1280、820、390、360；浅色与深色；中文与日文；四种登录态；默认的大数据量。
- 加一组缺失素材的用例：屏蔽曲绘域名后跑今日、曲库、歌曲详情、成绩、社区、个人主页。
- 18 条交互流程全部重跑。
- 性能多轮测量（至少 5 轮）：搜索首键与热态 p95 ≤ 50ms，路由切换 p95 ≤ 200ms，其余预算沿用 V1.2。

- 全部测试基于模拟数据，不是生产验收。
