# 06 · 实施建议与分阶段迁移方案

**状态（2026-11-17）：** Design V1.3 Final 已批准，冻结基线为提交 `5f770a2ddd2df970454f85fda09fa73008120b66`。按本方案从阶段 0 开始实施，条件见第 1 节。

- 批准不包括合并到 main 或部署。合并与部署按仓库现有流程另行处理：版本号、`scripts/deploy_forum_web.sh`、测试库规则见仓库 `AGENTS.md`。
- 设计依据是 `04-design-system.md`（Design System V1.3）。本文与它不一致时以 `04` 为准。
- 风险编号 RK-xx 与验收编号 Bx.y 见 `12-risks-and-integration-acceptance.md`；阶段 0 的任务清单见 `23-phase-0-implementation-tasks.md`。

## 1. 总体策略

**换壳不换芯，逐页替换，随时可回退。**

- 后端、`/api/forum/*`、`/api/account/*`、内容接口、数据库结构不变。重新设计只发生在 `taiko_viewer` 的 `layouts/`、`components/`、`pages/` 和 `assets/css/`。新增的只读接口（第 2 节注明的几处）另行评审，不改现有契约。
- **保留正式站的工程约定：** Nuxt 3 的 SSR、`@nuxtjs/i18n`（`/ja` 前缀、locale 文件）、PWA、权限中间件，以及业务接口的调用约定。
- **原型不直接搬运。** Vite 原型的路由（hash 模式）、状态机（`store.js`、`sync.js`）、`useQueryState`、模拟数据模型都只作参考，不移植进正式站。组件的外观与行为按 `04` 在正式站的结构里重新实现。
- **不改现有业务逻辑：** Rating 计算、成长事实、目标判定等都保持正式站现有实现，界面只读取它们的结果。
- **数据模型差异先裁定，再实现。** `12` 的 A7 列出了原型与正式字段的差异（RK-05–RK-10、RK-46–RK-48、RK-55 等）。哪个功能用到哪一项差异，就在实现这个功能之前把那一项裁定下来；没有裁定的不实现。
- **Element Plus** 保留为表单、弹层等基础控件的实现，变量按 `04` 的 Role token 映射：
  - 主操作 → `--action-bg` / `--action-ink`（Viewer Teal，**不是**咚的朱色）；
  - 链接 → `--link`；
  - Element Plus 的 `info` 类型（中性的标签、按钮、消息）→ 中性：`--ink-2` 文字、`--bg-sunk` 底，不用品牌色。品牌色只留给主操作、链接与选中，info 标签如果也是青绿，一个区域里会出现多处品牌色。这是设计负责人的建议，待负责人在 `23` D0-3 确认；
  - 焦点 → `--focus-ring`；
  - 选中 → `--selected-*`；
  - 浮层 → `--overlay-bg` 与浮层 token；
  - 危险 → `--danger`，破坏性按钮用描边形态。

  音符色（`--don*`、`--ka*`、`--roll*`）不映射到任何 Element Plus 的交互变量。
- **新旧界面并存**一段时间：新页面挂在新布局下，用路由级开关切换，旧路由保留并重定向。
- **每个阶段独立验收、独立发布、可以回退**，符合仓库「每个 Phase 独立发布」的做法。

## 2. 阶段划分

### 阶段 0 · 地基（不替换任何生产页面，不产生用户可见变化）

阶段 0 只做设计系统、工程基础、组件样张页与兼容性工作。

- **Token。** 把 V1.3 的 Brand、Role 与 teal Semantic 层（浅、深两套）连同 Domain 层迁入 `assets/css/`。
  - 正式站已有 `--viewer-*` token：它本身就是青绿体系（如 `--viewer-link` `#006c76`），但主按钮是红色（`--viewer-primary` `#bd352f`）。
  - 新旧两套怎么并存、谁作为谁的别名、什么时候让旧页面换色，在阶段 0 设计并评审。阶段 0 本身不改变旧页面的显示。
- **Element Plus 映射。** 按第 1 节的规则写映射，只在样张页里生效。
- **主题。** 样张页原样沿用正式站的 `taiko_theme` cookie 方案（只有浅 / 深），不改。现有两种主题的首屏不闪仍是要求（RK-30）。是否增加「跟随系统」见第 4 节，阶段 1 之前定。
- **字体。** 自托管 Noto Sans SC / JP（按 unicode-range 分片）、Barlow、Barlow Condensed。评估首屏字体体积，必要时汉字回退到系统字体，只对数字与拉丁字母自托管（第 4 节待定）。
- **真实素材组件**（规则见 `04` §7）：
  - `Cover`：同曲 WebP → 同曲 PNG → 中性缺失占位；不显示任何其他歌曲的曲绘（不用 `fallbackSongId`）。
  - `Diff`：图标取自正式站 `icons/diff/1–5.png`，正方形框等比显示；`icons/difficulty/` 旧路径保留兼容。
  - `Crown`：真实王冠素材。
  - `Rank`：真实评价素材加小尺寸版本。
  - `TitlePlate`：游戏称号牌面与文字两种形式，站内称号单独一个组件。
  - `PlayerAvatar`：有上传头像显示上传头像，缺失与加载失败显示 `/default-avatar.svg`。
  - **不做段位徽章**（RK-46）。
- **其他原子组件：** `SongCell`、`Note`、判定条。
- **小尺寸素材的生成。** 评价 56 / 80、王冠 36 / 60 / 96，WebP 加同尺寸 PNG 回退，只做等比缩小，保留原图；生成方式可重复运行并记录前后体积（RK-45、RK-52）。
- **图表组件：** `Lane`、`DrumDial`、`Radar`、`LineChart`、`DensityStrip`。替换 `PassportMetricChart` 等现有 SVG 图表放到用到它们的阶段，阶段 0 只做样张。
- **断点约定** 767 / 1099 / 1239，写成共享的媒体查询约定，供新组件使用。
- **工程规则：** scoped 样式里不用 `:global(:root[...]) .x` 这种前缀写法——Vue 只保留 `:global()` 里面的部分，后面的选择器被丢掉（`04` §7.10）。阶段 0 增加一项检查：检查编译后的 scoped CSS，确认依赖根元素属性的规则确实匹配到目标元素。这也是 P0 门槛的工程前提（RK-56）。通过标准：新代码里 0 处这种写法；现有代码里已有的出现处（如后台 `pages/admin/taiko/chart-ugc.vue` 第 212 行，`23` §2.9）列入阶段记录，阶段 0 不改，是否修复由负责人另行决定。

**验收：**
- 现有页面视觉无变化；新组件与真实素材有独立的样张页。
- 迁入的 token 通过对比度脚本（B2.2）。
- 素材与正式站原文件逐字节一致（B12.1）。
- 编译后 CSS 的选择器检查通过（B12.13）。

### 阶段 1 · 框架与曲库（最高频，游客也能感知）
- 新 `layouts/default.vue`：左轨、顶栏、手机底栏、二级页签。
- 全局搜索：先接歌曲与页面动作；帖子搜索等接口就绪后再接（RK-15）。别名搜索依赖曲目数据的裁定（RK-09）。
- `/songs`（三个列表合一）、`/songs/:id`、`/songs/constants`。歌曲详情的密度图（`DensityStrip`）在生产里没有找到数据来源，实现歌曲详情之前先裁定（RK-58）。
- 旧路由重定向：`/songs/available|removed|other` → `/songs?shelf=`，`/songs/v2-constants` → `/songs/constants`。
- 统一的权限引导组件 `Gate`，替换 `AccountToolGate` 和各页自写的提示。

**验收：**
- 查一首歌并看到定数，从任何页面出发不超过两步；Lighthouse 性能分不低于当前。
- 曲绘降级不显示其他歌曲的曲绘（B12.3）；难度图标不变形（B12.7）。
- 若歌曲详情的「我的成绩」在本阶段就用到正式的王冠组件，P1 门槛在本阶段生效（见阶段 2）。

### 阶段 2 · 今日、成绩、成长（登录玩家的主线）
- `/`（四种登录态）、`/play`、`/play/scores`、`/play/progress`、`/play/recommend`。
- `/growth`、`/growth/weekly`、`/growth/goals`。
- 顶栏同步状态（同步接口能给出的阶段与结果先确认，RK-03）。
- **需要后端配合、尚未裁定：**
  - Rating 与点灯进度的原生页面要把 B30 / 走势 / 进度的数据以 JSON 提供（新增只读接口，不改现有契约；RK-12）。在裁定之前，保留服务端图片，嵌进新版式。图片生成保留，用于发群。
  - 成绩页的王冠由三个计数换算（RK-05）；目标的「尝试轨迹」（RK-08）、时间栈的 `rating` / `dan` 里程碑（RK-07）、成长历史的数据充分度（RK-13）都要先裁定再实现。
- 旧路由重定向：`/account/songs`、`/tools/b30|trend|progress|recommend`、`/my/*`。

**验收：**
- 成长闭环（选目标 → 同步 → 看到进展）全程不离开「今日 / 成长」两个目的地。
- **P1 门槛：** 正式的成绩组件里，王冠三档（通关 / 全连 / 全良）有一种看得见、读得出的方式区分，不只靠银、金、彩虹的颜色；王冠原图不改（B12.8）。
- 评价值与图片文件的对应与 Bot 的选图函数一致（B12.4）。

### 阶段 3 · 社区
- `/community`、帖子、发帖、我的社区、通知。
- 旧路由重定向：`/forum/*` → `/community/*`（保留帖子 ID）。
- 论坛 App（Flutter）不受影响，接口不变。
- 身份信息按 V1.3：不显示段位（RK-46）；称号的牌面与文字形式按 `04` §7.7（RK-10）。

**验收：**
- 论坛帖子数增量为零的前提下完成切换（只换界面，不迁数据）。
- **P0 门槛（帖子回复框上线之前）：**
  - 软键盘避让的选择器在编译后确实匹配；
  - 在 iOS Safari 与 Android Chrome 真机上通过 B6.4、B6.8、B12.14；
  - 缩短视口的模拟不算软键盘测试通过（RK-56）。
- **P2 门槛：** 保留已批准的 `/default-avatar.svg`；用混合数据（真实上传头像、默认头像、图片加载失败）复核社区的观感，不为模拟截图重新调色（B12.5、B12.15）。

### 阶段 4 · 账号与绑定
- `/login`、`/bind`、`/account`（拆分 2,200 行的 profile 页）、`/account/sync`、设置、开发者、工单。
- 这一阶段涉及 OIDC 交互与绑定校验，改动面最敏感，放在框架稳定之后，并保留旧页面作为回退。

**验收：** 新用户从注册到第一次同步完成，全程在一个连续流程里；会话过期有明确的下一步（B4.2）。

### 阶段 5 · 收尾
- 段位、攻略、称号、工具页（段位道场的合格记录没有确认的数据来源，先裁定，RK-46）。
- 年度回顾入口页；故事播放器与后台换用新 tokens（不改结构）。
- 清理：删除旧 `--viewer-*` 别名（若阶段 0 的并存方案采用了别名）、`/my`、`/more`、废弃组件；把 65 个内联双语的组件迁回 locale 文件。
- 个人主页 `/u/:name` 等新增提案，按第 4 节的决定执行；个人主页需要公开范围设置与公开资料接口，没有后端之前不实现（RK-11）。

**验收：** 每个页面替换前后各跑一次第 3 节的回归；清理后没有残留的旧路由 404。

## 3. 风险与对策

| 风险 | 对策 |
|---|---|
| 汉字网页字体体积影响首屏 | 分片加载 + `font-display: swap`；阶段 0 实测，不达标就只对数字和拉丁字母用自托管字体（RK-34） |
| Element Plus 控件与新视觉不一致 | 只在表单与弹层内部使用；外观由第 1 节的 Role token 映射统一；映射不了的控件再单独重写 |
| 服务端 PNG 的数据拿不到 JSON | 阶段 2 之前先确认接口；拿不到就先保留图片，嵌进新版式（RK-12） |
| 旧链接失效（搜索引擎、群里的分享链接） | 所有旧路由保留服务端重定向；站点地图与百度推送同步更新（RK-29） |
| 手机端回归 | 每个阶段按 1440 / 1280 / 820 / 390 / 360 五个宽度、深浅两种主题验收；沿用仓库的内存隔离 QA 脚本跑浏览器检查（RK-39） |
| 新旧并存期间风格割裂 | 阶段 1 先换框架，旧页面在新框架里显示；旧页面怎样换色由阶段 0 的并存方案决定 |
| 年度回顾与后台有独立的设计系统 | 不在本次范围内重做；只做 token 对齐（RK-41） |
| 真实素材被改色或重新压缩 | 素材原样复制并核对 md5，只允许等比缩小（RK-45） |
| scoped 样式的 `:global()` 前缀让规则失效 | 阶段 0 的编译后 CSS 检查；P0 门槛（RK-56） |

## 4. 已决定与待决定

**已决定**
- 方向：C+（真实游戏素材 + Viewer Teal），Design V1.3 Final 已批准，冻结基线 `5f770a2`。不再探索品牌方向，没有 V1.4。
- 冻结范围：Fumen 的信息架构、导航与响应式布局；Viewer Teal 品牌色与深浅主题；品牌色与游戏语义色的分工；真实曲绘、难度、王冠、评价、称号牌与素材降级规则；核心组件的视觉；V1.1–V1.3 的交互裁定；设计性能预算（搜索首键与热态 p95 ≤ 50 ms 等）。
- G3 例外：歌曲详情 1440 浅色的朱色 / 品牌比例为 0.70（目标 ≤ 0.60），因为谱面音符有真实的游戏含义；记录为已接受的例外，不算达标（RK-54）。
- 三项实施门槛：P0 软键盘避让（阶段 0 的工程检查 + 阶段 3 回复框上线前的真机测试）、P1 王冠不只靠颜色区分（正式成绩组件上线的阶段）、P2 默认头像在社区接入时用混合数据复核。

**待决定**
1. **新增提案**（见 `03-ia-mapping.md` 第 4 节）：全局搜索、个人主页、曲库「我的进度」筛选、目标独立页、原生 Rating / 进度页，哪些要、哪些不要（B1.2；个人主页见 RK-11，原生页面见 RK-12）。
2. **字体**：是否接受自托管思源黑体带来的体积；不接受则汉字用系统字体（B1.3、RK-34）。
3. **顺序**：上面的阶段顺序按使用频率排列；如果希望先解决绑定流程，阶段 4 可以提前到阶段 2 之前。
4. **命名**：`03-ia-mapping.md` 里的统一叫法（曲库、全部成绩、这一周、账号与绑定、鼓众广场 ID）是否采纳。
5. **数据模型差异**（`12` A7），在用到它的功能实现之前逐项裁定：
   - 王冠由计数换算（RK-05）；
   - 成长事实类型名（RK-06）；
   - `rating` / `dan` 里程碑（RK-07）；
   - 目标尝试轨迹（RK-08）；
   - 曲目的别名与资源可用性（RK-09）；
   - 身份字段：称号牌面编号、站内称号（RK-10）；
   - 段位数据（RK-46）；
   - 头像的两种缺省（RK-47）；
   - 曲绘降级（RK-48）；
   - 歌曲详情的每小节音符密度（RK-58，阶段 1 歌曲详情之前）。
6. **新旧 token 的并存方案**（阶段 0 设计并评审，`23` D0-2）。
7. **主题「跟随系统」**：是否在现有的浅 / 深之外增加，阶段 1 之前定（B1.2、RK-30）。阶段 0 不实现。
8. **Element Plus 的 info 色**：建议映射到中性（见第 1 节），待负责人在 `23` D0-3 确认。
