# 06 · 实施建议与分阶段迁移方案

本文件是建议，不是已经开始的工作。在 Design V1 通过评审之前，不改生产页面、不动业务逻辑、数据库和 API 契约、不部署。

## 1. 总体策略

**换壳不换芯，逐页替换，随时可回退。**

- 后端、`/api/forum/*`、`/api/account/*`、内容接口、数据库结构全部不变。重新设计只发生在 `taiko_viewer` 的 `layouts/`、`components/`、`pages/` 和 `assets/css/`。
- 继续使用 Nuxt 3 + Vue 3。Element Plus 保留为表单、弹层等基础控件的实现，通过 CSS 变量映射到新的 Semantic tokens；业务组件（难度、王冠、评价、谱面带、图表）用原型里的写法新建。
- 新旧界面并存一段时间：新页面挂在新布局下，用路由级开关切换，旧路由保留并重定向。
- 每个阶段都可以独立发布，符合仓库现有的「每个 Phase 独立发布」的做法。

## 2. 阶段划分

### 阶段 0 · 地基（不产生用户可见变化）
- 把 `tokens.css` / `base.css` / `domain.css` 迁入 `assets/css/`，与现有 `--viewer-*` 并存；旧 token 暂时作为别名指向新 token。
- 建立 Element Plus 变量映射（`--el-color-primary: var(--don)` 等）。
- 自托管字体：Noto Sans SC / JP 按 unicode-range 分片、Barlow、Barlow Condensed。评估首屏字体体积，必要时汉字回退到系统字体，仅数字与拉丁字母使用自托管字体。
- 落地业务原子组件：`Diff`、`Crown`、`Rank`、`Cover`、`SongCell`、`Note`、判定条。
- 落地图表组件：`Lane`、`DrumDial`、`Radar`、`LineChart`、`DensityStrip`。`PassportMetricChart` 等现有 SVG 图表并入。
- 统一断点为 767 / 1099 / 1239，写成共享的媒体查询约定。

验收：现有页面视觉无变化；新组件有独立的样张页。

### 阶段 1 · 框架与曲库（最高频，游客也能感知）
- 新 `layouts/default.vue`：左轨、顶栏、手机底栏、二级页签。
- 全局搜索（先接歌曲与页面动作；帖子搜索等接口就绪后再接）。
- `/songs`（三个列表合一）、`/songs/:id`、`/songs/constants`。
- 旧路由重定向：`/songs/available|removed|other` → `/songs?shelf=`，`/songs/v2-constants` → `/songs/constants`。
- 统一的权限引导组件 `Gate`，替换 `AccountToolGate` 和各页自写的提示。

验收：查一首歌并看到定数，从任何页面出发不超过两步；Lighthouse 性能分不低于当前。

### 阶段 2 · 今日、成绩、成长（登录玩家的主线）
- `/`（四种登录态）、`/play`、`/play/scores`、`/play/progress`、`/play/recommend`。
- `/growth`、`/growth/weekly`、`/growth/goals`。
- 顶栏同步状态。
- **需要后端配合的一项**：B30 / 走势 / 进度目前是服务端渲染的 PNG。原生页面需要同样的数据以 JSON 提供（新增只读接口，不改现有契约）。图片生成保留，用于发群。
- 旧路由重定向：`/account/songs`、`/tools/b30|trend|progress|recommend`、`/my/*`。

验收：成长闭环（选目标 → 同步 → 看到进展）全程不离开「今日 / 成长」两个目的地。

### 阶段 3 · 社区
- `/community`、帖子、发帖、我的社区、通知。
- 旧路由重定向：`/forum/*` → `/community/*`（保留帖子 ID）。
- 论坛 App（Flutter）不受影响，接口不变。

验收：论坛帖子数增量为零的前提下完成切换（只换界面，不迁数据）。

### 阶段 4 · 账号与绑定
- `/login`、`/bind`、`/account`（拆分 2,200 行的 profile 页）、`/account/sync`、设置、开发者、工单。
- 这一阶段涉及 OIDC 交互与绑定校验，改动面最敏感，建议放在框架稳定之后，并保留旧页面作为回退。

验收：新用户从注册到第一次同步完成，全程在一个连续流程里。

### 阶段 5 · 收尾
- 段位、攻略、称号、工具页。
- 年度回顾入口页；故事播放器与后台换用新 tokens（不改结构）。
- 清理：删除旧 `--viewer-*` 别名、`/my`、`/more`、废弃组件；把 65 个内联双语的组件迁回 locale 文件。
- 评估并决定第 4 节的新增提案（个人主页等）。

## 3. 风险与对策

| 风险 | 对策 |
|---|---|
| 汉字网页字体体积影响首屏 | 分片加载 + `font-display: swap`；阶段 0 实测，不达标就只对数字和拉丁字母用自托管字体 |
| Element Plus 控件与新视觉不一致 | 只在表单与弹层内部使用；外观由变量映射统一；发现映射不了的控件再单独重写 |
| 服务端 PNG 的数据拿不到 JSON | 阶段 2 之前先确认接口；拿不到就先保留图片，嵌进新版式 |
| 旧链接失效（搜索引擎、群里的分享链接） | 所有旧路由保留服务端重定向；百度推送清单同步更新 |
| 手机端回归 | 每个阶段按 360 / 390 / 820 / 1440 四个宽度验收；沿用仓库的内存隔离 QA 脚本跑浏览器检查 |
| 新旧并存期间风格割裂 | 阶段 1 先换框架，旧页面在新框架里显示；用 token 别名让旧页面至少换上新色 |
| 年度回顾与后台有独立的设计系统 | 不在本次范围内重做；只做 token 对齐 |

## 4. 需要你决定的事

1. **方向**：是否按 A「譜面」继续，还是希望在 B / C 上再探索一版。
2. **新增提案**（见 `03-ia-mapping.md` 第 4 节）：全局搜索、个人主页、曲库「我的进度」筛选，哪些要、哪些不要。
3. **字体**：是否接受自托管思源黑体带来的体积；不接受则汉字用系统字体。
4. **顺序**：上面的阶段顺序按使用频率排列；如果希望先解决绑定流程，阶段 4 可以提前到阶段 2 之前。
5. **命名**：`03-ia-mapping.md` 里的统一叫法（曲库、全部成绩、这一周、账号与绑定、鼓众广场 ID）是否采纳。
