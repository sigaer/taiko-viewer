## 2. 建议：选 C

V1.3 要解决两个问题：没有品牌色，游戏素材被自绘图形替代。

- **B 解决了第二个。** 曲绘、难度、王冠、评价、称号牌换回游戏原图后，游戏辨识度回来了，朱色面积少了三成。
- **只有 C 解决第一个。** B 里主按钮仍是音符的朱色，链接仍是咔的浅葱，没有一个颜色代表 Viewer。C 把交互全部收到青绿上，红色只留给游戏数据。
- **C 的颜色总量没有增加。** 有颜色的面积 B 与 C 都是 4.5%，C 是把它集中到了一个色相上。

C 有代价，都列在 `17` 第 6 节。最需要你知道的三条：咔的颜色向蓝偏移了；深色主题的层次比夜藍平；Rating 等大数字不再是红色，首页第一眼看到的是曲绘而不是数字。我认为这些可以接受，也都能在 Phase B 里继续调，但它们是真实的损失，不是没有代价的升级。

如果你选 B：真实素材的全部工作保留，品牌色的问题留待以后。

## 3. 需要你裁定的事项

**选方向时一起定：**

| # | 事项 | 现在的做法 | 备选 |
|---|---|---|---|
| D1 | 咔在 C 里向蓝偏移 | 浅色 `#2B9BCF`，深色 `#5CC4EF`，只以音符形状出现 | 保持浅葱，接受它与品牌色在深色下分不开 |
| D2 | 手机底栏中间的「咚」键 | 保持朱色，它本身是一个咚音符 | 改为青绿，全站交互只有一个颜色 |
| D3 | 默认头像 | 单色的中性鼓面加昵称首字 | 正式站的 `/default-avatar.svg`（橙粉渐变人形）；或正式站论坛现在回落的 `miku.png`（角色插画，非正方形） |
| D4 | 标志 | 沿用 V1.2 的鼓面标志，C 里鼓缘改青绿 | 用正式站现在的图标（游戏角色的脸） |

**与正式站现有行为不同，需要你确认：**

| # | 事项 | 正式站现在 | 原型的做法 |
|---|---|---|---|
| D5 | 曲绘加载失败 | 缩略图 → 原图 → 显示 1384 号歌的曲绘 → 占位 | 不走「1384」这一步：不把另一首歌的曲绘显示在当前歌曲上 |

**素材与数据上的缺口：**

| # | 事项 | 情况 |
|---|---|---|
| D9 | 段位 | 原型保留文字段位徽章。正式站的论坛用户数据没有段位字段；Bot 有段位图标，但不在 Viewer 的公共资源里。要么后端补字段并同步图标，要么去掉段位徽章 |
| D10 | 评价图标的大小 | 200×200，每张 19–42 KB。成绩页首屏的图标合计 191 KB，比曲绘还重。正式实现需要小尺寸版本 |
| D11 | 缺缩略图的曲目 | 「真实曲目集」50 首里有 6 首在正式站的静态域名上没有缩略图（1255、345、32、1323、395、1324），显示为缺失占位。其中 1255 与 345 是仓库测试数据里确认存在的曲目 |
| D12 | 评价图与评价值的对应 | 文件序号 2–8 对应白粹到极，是看图确认的。选图的函数在 Bot 仓库，本仓库查不到，需要有人对一下 |
| D13 | 没有牌面的称号 | 称号关系表里有 19 种「达成类型 × 难度范围」的组合不在牌面清单里，它们用哪张牌取决于 Bot 的实现。原型把它们显示为文字 |
| D14 | 原型精选曲的 ID | 702 在仓库里是另一首歌，960 很可能不是「幽玄ノ乱」（正式站的脚本写的是 463），278 与十首 `1000xx` 没有曲绘。默认数据没有改，这些曲目在 B、C 下显示示例占位 |

## 5. Phase A 没有做的

- **C 只整理了四个对照页和外壳。** 其余页面还有 41 处直接用音符色表示交互的地方（24 个文件），在 C 下是混色的。不要用这些页面评价 C。
- **Design System 文档（`04`）没有更新。** 它仍是 V1.2。方向定了之后在 Phase B 更新。
- **默认数据没有改。** 真实曲绘只在「真实曲目集」里完整出现。
- **点灯进度的格子仍是色块**，没有换成王冠图。
- **第二轮修正后没有重跑版本 A 的完整矩阵。** 做了什么检查见 `17` 第 8 节。
- **V1.2 遗留的风险都还在**，见 `12`。原型里的王冠、评价、目标尝试、段位仍然不是正式的数据模型。

## 6. Phase B 做什么

只有在你选定方向之后才开始。

1. 把选定的品牌体系推到全部页面，清掉剩余的 41 处直接用色。
2. 把真实素材用到全部相关页面：曲库、成绩的其他页签、成长、个人主页、帖子详情、搜索面板等。
3. 按你对第 3 节的裁定调整：默认头像、咚键、标志、段位。
4. 处理 `17` 第 6 节列的代价：深色层次、段位徽章的颜色、大数字的强调。
5. 更新 Design System 到 V1.3。
6. 完整的响应式与浏览器回归，多轮性能复测，记录资源体积。
7. 最终的 Design Freeze 文档。
