## 4. 已知没有做到或没有验证的

- G3：歌曲详情浅色 1440 的朱色比例没有达到 ≤ 60%，按「没有达标」记录（`19` G3、`21` §9）。
- 王冠三档只靠颜色区分（列表里不加文字），记为已知局限。
- 评价值 ↔ 文件的对应没有对照 Bot 的选图函数。
- WebP 有损压缩的像素级色差只做了肉眼对照。
- A、B 两个历史版本不再维护与验收。
- 真实玩家数据、真实设备与软键盘、真实网络下的曲绘缓存都没有验证。
- **软键盘避让很可能从未生效（更正）。** `src/views/Thread.vue` 在 scoped 样式里写了 `:global(:root[data-kb]) .composer`，Vue 会把它编译成只剩根元素的选择器（与 R1 的根因相同），所以「键盘弹出时回复框贴在键盘上方、不叠加安全区」那条规则很可能从 V1.2 起就没有作用。V1.2 的文档把键盘跟随写成「只有代码、未在真实键盘下验证」；准确的说法是：没有验证，而且其中一条规则大概率无效。本轮没有修改，正式集成时必须在真机上实现并测试（`12` 的 RK-56）。
- **性能数字的更正。** Stage 2 的性能数字是在历史版本 A 上测的；最后一轮改为在 C+ 上测，C+ 的路由切换比 A 慢约 32 ms（`21` §5）。

正式集成阶段的处置见 `12-risks-and-integration-acceptance.md`。
