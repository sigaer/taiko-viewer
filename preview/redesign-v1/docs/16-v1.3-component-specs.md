# 16 · Design V1.3 组件规范（真实素材）

日期：2026-11-16　基线：V1.2 提交 `cb8fb5aa`　依据：`14-v1.3-asset-audit.md`

这份文档规定 `data-assets="authentic"`（对照版本 B、C）下六个身份与成绩组件的外观。`generated`（版本 A）保持 V1.2 的画法不动。组件的尺寸档位、在页面里的位置和信息顺序都不变；只有素材比例确实放不下的地方才调整组件内部的排版，这些地方在下面逐条写明。

`14` 第 5 节列的冲突 X1–X14，裁定结果在各节末尾标注。

---

## A0 · 素材怎么进原型

- **图标类**（难度 5、王冠 3、评价 7、称号牌 12）从 `origin/main`（`f9b39e6`）的 `taiko_viewer/public/` 原样取出，放进 `preview/redesign-v1/public/game/{diff,crown,rank,plate}/`。不改名以外的任何内容：不裁切、不重绘、不压缩、不改色。目录里放一份来源说明（原路径、提交、文件大小）。
- **曲绘**不复制。运行时按正式站的规则从 `static.sakura-bot.cn` 加载。
- **难度图标路径**统一用 `icons/diff/`。它与 `icons/difficulty/` 逐字节相同，是 1.14.2 同步进来的那一套（X2：采纳）。
- 不对任何素材使用 CSS 滤镜、混合模式、遮罩或透明度来改变它的颜色。
- 每张图都有固定的宽高，加载前后不改变布局。

## A1 · Cover 曲绘

**谁显示真实曲绘。** 只有一份白名单里的曲目：ID 与曲名的对应关系在仓库里有依据的那些（`14` 第 4 节的「已验证」）。其余一律不请求图片。
- 合成曲目的 ID 落在真实 ID 的范围内，直接按 ID 取图会配上别的歌的曲绘，所以必须走白名单，不能「先请求、失败再降级」（X11：采纳白名单，不改合成曲的 ID）。
- ID 与曲名对不上或查不到依据的精选曲（702、960、233、512、88、1290、41、278、十首 `1000xx`）在 Phase A 按示例曲处理，显示示例占位（X12）。

**加载规则**（沿用正式站 `SongCoverImage` 的规则）：
- 缩略图 `cover/thumb/{200|400}/{id}.webp?v=0841`，用 `srcset` 提供两档；显示边长 ≤ 100px 的档位只会用到 200。
- 缩略图失败 → 同一首歌的原图 `cover/{id}.png` → 中性缺失封面。
- 不使用正式站的 `fallbackSongId`（1384）：它会把另一首歌的曲绘显示在当前歌曲上。这一条与正式站现有行为不同，记入 `18` 供你裁定。
- 首屏以外懒加载（进入视口前 320px 开始），`decoding="async"`；歌曲详情的主封面优先加载。
- 切换歌曲时先回到底色，不残留上一首的图。

**外观。**
- 尺寸档位与圆角沿用 V1.2 的 `.cover` 阶梯（32 / 44 / 72 / 96 / 168 / 撑满），1:1，`object-fit: cover`。
- 加载中是 `--bg-sunk` 底色。图片出现时允许 120ms 淡入，减少动效时不淡入。
- 曲绘上不叠任何渐变、色罩或文字。外圈 1px `--line` 内描边，让浅色曲绘在浅色底上有边界。

**两种占位，看得出区别：**

| 状态 | 画法 | 可访问名称 |
|---|---|---|
| 缺失（真实曲目，图片加载失败） | `--bg-sunk` 底、1px `--line` 内描边，中间一个 `--ink-3` 的音符图标 | 「没有曲绘」 |
| 示例（合成或未验证的曲目） | 同上，底上加 45° 细斜纹（`--line`），≥ 96px 的档位在图标下显示「示例」 | 「示例曲目」 |

两种占位都不用流派色、不用曲名首字、不用随机色。

## A2 · Diff 难度

**图标。** `diff/1–5.png` 对应简单、普通、困难、魔王、魔王（里）。图标宽高比不统一（94×78 到 86×86），放进固定的正方形框里 `object-fit: contain`，不拉伸（X1：采纳）。正式站曲库现在把它拉成 20×20，是变形的，记入 `18`。

**徽章结构：** 难度图标 + ★星级 + 定数。

| 部分 | 画法 |
|---|---|
| 容器 | `--surface` 底、1px `--line`、圆角 `--r-xs`；不再用难度色实色填充 |
| 图标框 | 徽章 18px（徽章高 22px，含边框后放不下 22px 的图标），大号徽章 22px，难度页签 26px |
| ★星级 | `--ink`，数字字体，加粗 |
| 定数 | `--ink-2`，数字字体；没有定数显示「—」 |
| 「里」标记 | 魔王与里魔王的图标形状相同、只有颜色不同，所以里魔王在图标后加一个「里」字（日文「裏」） |

- 徽章里不再写「鬼」「难」等单字：图标的形状已经能区分简单、普通、困难、魔王。可访问名称读完整的难度名、星级与定数。
- 徽章高度与 V1.2 相同，表格列宽不变。
- `--diff-*` token 保留，用于点灯格、图表等没有图标的地方（X14：采纳，不用正式站曲库那组颜色）。

**难度页签（歌曲详情）。** 图标 + 难度名 + ★星级 + 定数。C5 仍然有效：页签始终带文字，360 宽下用单字短标。

| 状态 | B（Fumen 配色） | C（Viewer Teal） |
|---|---|---|
| 未选中 | `--surface` 底，1.5px `--line`（沿用 V1.2 的边框宽度，盒子尺寸不变） | 相同 |
| 选中 | 2px 该难度色边框（1.5px 边框 + 0.5px 内描边），难度色 14% 浅底 | 2px `--selected-line`，`--selected-bg` 浅底 |
| 两者共同 | 文字加粗，`aria-selected`，底部 2px 指示线 | 相同 |

选中不靠图标的颜色表示。360 宽下页签横滑，两端渐隐（沿用 V1.2）。

## A3 · Crown 王冠

**对应关系**（正式站 `AccountSongScores.vue`）：全良次数 > 0 → `dondaful.png`；否则全连次数 > 0 → `full.png`；否则通关次数 > 0 → `clear.png`；有记录但三项都是 0 → 已游玩；没有记录 → 未游玩。

| 状态 | 画法 | 可访问名称 |
|---|---|---|
| 全良 / 全连 / 通关 | 对应的 PNG，正方形框 | 全良 / 全连 / 通关 |
| 已游玩 | 8px 空心圆环，`--ink-3`（沿用 V1.2；它不是王冠） | 已游玩 |
| 未游玩 | 「—」 | 未游玩 |

- 尺寸：密集表格 18px，默认 22px，歌曲详情成绩区 30px，新全连、新全良的达成时刻 48px（X3：采纳正方形框）。
- 不加底板、不加色圈。银、金、彩虹由素材自己表现。
- 不画灰色王冠表示「没拿到」。
- 筛选胶囊里的小王冠也用真实素材，16px。
- 点灯进度的格子仍是色块（一屏 240 格，不放 240 张图），颜色用 `--crown-*`。
- 原型的模拟数据仍用单个王冠值；正式实现按上面的三项计数换算（X13：Phase A 不改模拟数据，换算规则以这里为准，风险见 `12` 的 RK-05）。

## A4 · Rank 评价

**对应关系**（正式站 `scoreRank.ts`）：值 2–8 = 白粹、铜粹、银粹、金雅、粉雅、紫雅、极，对应 `rank/2–8.png`。文件序号与值的对应是看图确认的（2 是白色「粋」，5 是金色「雅」，8 是彩虹「極」）；选图函数在 Bot 仓库，不在本仓库，这一点在 `14` 里标为待验证。

| 值 | 画法 | 可访问名称 |
|---|---|---|
| 2–8 | 对应的 PNG | 评价名（中文 / 日文） |
| 1 未取得 | 「—」。`rank/1.png` 是全透明图，不加载 | 未取得 |
| 0 未设置 | 「—」 | 未设置 |

（X4：采纳。）

- 素材四周有透明边。占位 24px 的位置，图片按 28px 绘制并居中，不裁切。
- 尺寸：密集表格与手机列表占位 24px；歌曲详情成绩区占位 36px（按 40px 绘制），旁边写评价全名，图与字之间至少 8px；评价升级记录见下。
- **桌面的密集表格里，图标后面跟评价名的文字**（`--ink-2`、`--fs-12`）。28px 的图里汉字已经认不清，三种粹、三种雅只剩颜色不同，单靠图标比 V1.2 的字形圆圈更难读。有文字时图标对读屏隐藏。手机列表行放不下文字，只放图标。
- 小于 24px 的位置不放图，改用文字写评价名（X5：采纳）。
- 不加彩色圆底。
- **评价升级**写成「原评价 → 新评价」：原评价 24px，新评价 30px，中间一个 `--ink-3` 箭头。两个图标不等大，只有新评价醒目。

## A5 · 称号

正式站有三样不同的东西，V1.2 把它们画成了同一个 `TitlePlate`。V1.3 分开（X8：采纳）：

**游戏称号**（绑定时从游戏读到的称号文字与牌面编号；「我的小咚」的展示称号用同一套牌面规则）
- 牌面由达成类型 × 难度范围决定，一共 9 张切片；自定义称号按通关 / 全连 / 全良用银 / 金 / 虹三张。
- 有对应切片：切片图铺满一个保持原比例的框，称号文字压在图上。文字用固定的深色加白色描边（游戏里的写法），新增两个 Domain token `--plate-ink`、`--plate-ink-outline`，深浅主题相同。
- 文字的位置按牌面种类定：切片牌上文字落在色带里，不压在色带边缘；自定义牌（556×90）上文字落在下半的米白名牌区；带角色图案的切片在右侧留出图案的位置。文字缩到 10px 仍会碰到图案时，退回文字形式，不盖住图案。
- 没有对应切片（关系表里有 19 种组合不在清单里，或没有牌面编号）：只显示文字，`--ink-2`，不加边框和底色。
- 去掉 V1.2 的 `rare`：正式站没有「稀有称号」这个概念（X6：采纳）。称号的轻重由牌面自己表现——全良的彩虹牌本来就比通关的木纹牌显眼。
- 原型里虚构的称号（「精度调律师」「连打之鬼」等）换成 `title_song_relations.json` 里真实存在的称号，按它们的达成类型与难度范围取牌面。至少覆盖：木纹、金、彩虹三类切片，一个自定义称号，一个没有牌面的称号，一个没有称号的玩家。

**牌面只出现在宽的位置**（X7：采纳）。切片是 12.4:1 或 7.8:1 的长条，放不进列表行。

| 位置 | 形式 |
|---|---|
| 个人主页身份带、帖子详情的作者区、社区头条的作者区 | 牌面，宽 220px（切片牌高 18px 或 28px，自定义牌高 36px），文字 12px |
| 今日页与「我的」的身份行、帖子列表行、回复行、达人榜、搜索结果 | 只显示文字，`--ink-3`，`--fs-12`，单行截断 |

- 称号太长、12px 放不进 220px 时：先缩到 10px；还放不下就退回文字形式，完整称号放在 `title` 里。
- 社区与个人主页用同一个组件、同一套规则。

**站内称号**（`AccountTitle`，目前只有「虹光先行者」一个，键名 `annual-beta-pioneer`）
- 小标签：中性底、左侧一条 3px 彩虹竖条，沿用正式站的画法。它不是游戏称号，不套牌面。
- 原型里给一个模拟玩家挂上它，用来在社区里看效果。

## A6 · PlayerAvatar 头像

| 状态 | 画法 |
|---|---|
| 有头像（`avatarUrl`） | 显示图片，圆形，`object-fit: cover`，1px `--line` 外描边 |
| 没有头像 | 默认头像：中性鼓面——`--bg-sunk` 鼓面、`--line-strong` 鼓缘、`--ink-2` 的昵称首字。所有人同一种颜色 |
| 图片加载失败 | 退回默认头像 |

- 去掉随机色相的鼓面和按段位着色的鼓缘。段位字段正式站的论坛数据里没有（`12` 的 RK-10）。
- 默认头像是单色的，一眼看得出是「没上传头像」，不会被当成真实头像。
- 正式站现在有两个默认头像：论坛接口回落到 `miku.png`（一张角色插画，443×402，不是正方形），`/my` 页用 `/default-avatar.svg`（橙粉渐变的人形）。两者都是高饱和的整块颜色，放进列表里每一行都抢眼。Phase A 用上面的中性鼓面；用哪一个由你定，见 `18`。素材页把三种并排放出来。
- 原型里没有真实玩家的头像：不能导入真实用户的图片，也不拿别的图片冒充。所以社区对照里所有玩家都是默认头像，「有头像」这个状态只在素材页用正式站的两个默认图做演示。对照文档里要写明这个局限（X9）。
- 段位徽章（`DanBadge`）保持 V1.2 的文字徽章。Bot 有段位图标，但不在 Viewer 的公共资源里（X10：Phase A 不动）。

## A7 · 真实图片的加载指标

在对照用的四个页面上，B、C 各测一遍，桌面 1440 与手机 390：

| 指标 | 记录什么 |
|---|---|
| 请求数 | 图片请求数，分曲绘与本地图标 |
| 体积 | 图片传输字节数，分曲绘与本地图标；各页面首屏合计 |
| 首屏图片加载时间 | 从导航开始到首屏最后一张图加载完成 |
| 失败比例 | 请求失败数 / 请求总数 |
| 降级 | 屏蔽曲绘域名后，占位是否正确、有没有报错、布局有没有变化 |
| 快速滚动 | 长列表快速滚动时，请求数有没有失控、离开视口的请求有没有堆积 |
| 布局偏移 | 累计布局偏移（CLS），与版本 A 对比 |

这些数字来自真实的网络请求，不拿版本 A 的纯 CSS 图形代替。原型的图标是本地文件，正式站经过 CDN，体积与时间只能作参考。

## A8 · 对照用的数据

V1.2 的精选曲里只有 12 首能确认是真实曲目，成绩页首屏几乎全是合成曲。直接对照的话，B、C 的成绩页会是一屏示例占位，看不出真实曲绘的效果。

所以增加第三套数据 `real`（真实曲目集），只给对照和素材页用：
- 曲目全部取自仓库里有 ID 与曲名对应依据的那些（`main:tests/fixtures/annual-summary.sample.json` 的曲号与曲名），只取曲号、中文名、日文名三项。
- 成绩、王冠、评价、定数、帖子内容仍是确定性生成的模拟数据。
- 这套数据里，页面上提到曲名的文字与它旁边的曲绘必须是同一首歌。
- A、B、C 三个版本在对照里都用这一套，数据完全相同。
- 默认数据 `full` 与 `demo` 不动，V1.2 的验收用例不受影响。`full` 下 B、C 的成绩页另拍两张，如实展示合成曲的占位状态。
