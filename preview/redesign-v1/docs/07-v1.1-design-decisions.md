# 07 · Design V1.1 设计裁决

V1.1 不重新探索方向，也不改信息架构。本文件是这一轮所有修复的设计依据：每条裁决有编号，实现与验收都按编号对应。逐项的完成情况记录在 `08-v1.1-fix-record.md`，浏览器验收结果在 `09-v1.1-qa-report.md`。

约定：手机 = ≤767px；平板 = 768–1099px；桌面 = ≥1100px；宽屏 = ≥1240px。

## S · 同步

**S1 一个同步模型。** 全站只有一个同步状态机（`src/sync.js`）：`idle → running → success | partial | failed`。`running` 分三个阶段：读取鼓众广场 → 写入 Viewer → 推送到同步目标。结果包含：时间、新进展条数（刷新成绩 / 新全连 / 新全良）、各同步目标的结果与失败原因。原型用 Mock 模拟，下一次同步的结果（成功 / 部分成功 / 失败）由原型控制面板指定。

**S2 手机入口在顶栏。** 手机顶栏右侧改为「同步」「通知」两个 44px 按钮；**顶栏不再放头像**（底栏「我的」已经是账号入口，头像是重复入口）。同步按钮用状态角标表达：

| 状态 | 图标 | 角标 |
|---|---|---|
| 已同步、空闲 | 同步图标 | 无 |
| 游客 / 未绑定 / 从未同步 | 同步图标 | 山吹色点（需要你做一步） |
| 同步中 | 图标旋转（减少动效时静止并显示进度点） | 无 |
| 刚刚成功 | 对勾，约 2.5 秒后回到空闲 | 无 |
| 部分成功 | 同步图标 | 山吹色点 |
| 失败 | 同步图标 | 危险色点 |

按钮的 `aria-label` 必须读出当前状态（例如「同步：2 小时前同步」「同步：上次同步失败」）。

**S3 点按打开同步面板。** 手机是底部抽屉，桌面是锚在顶栏状态条下方的浮层，两者内容是同一个 `SyncPanel`。面板内容随登录态与同步状态变化：

| 情形 | 面板内容 | 主按钮 |
|---|---|---|
| 游客 | 一句话说明同步能得到什么 | 登录（次要：注册） |
| 未绑定 | 三步清单，第二步为当前 | 去绑定 |
| 已绑定无成绩 | 已绑定的账号 + 「第一次同步大约需要 10 秒」 | 开始同步 |
| 空闲 | 上次同步时间与结果摘要 + 各同步目标的状态 | 立即同步；链接「同步设置」 |
| 同步中 | 三个阶段，当前阶段高亮 | 禁用，文案「正在同步…」；可以关闭面板，同步继续 |
| 成功 | 「同步完成：4 条新进展，1 个新全良」 | 看看有什么变化（回到今日） |
| 部分成功 | 「成绩已更新到 Viewer，1 个同步目标没有成功」+ 失败目标的原因 | 重试失败的目标 |
| 失败 | 「没有同步成功：鼓众广场暂时没有响应。已有的数据没有变化。」 | 重试 |

**S4 桌面状态条。** 文案随状态变化：`2 小时前同步` / `正在同步… 2/3` / `刚刚同步 · 4 条新进展` / `部分同步`（山吹底）/ `同步失败`（危险色描边）。空闲时点击直接开始同步；部分成功或失败时点击打开面板看原因。未绑定、无成绩时文案是下一步动作（保持现状）。

**S5 不重复。**
- 「我的」页去掉同步按钮，只保留一行只读的上次同步信息。
- 目标卡的「练后同步」保留：它是练习闭环的下一步，调用同一个状态机，在手机上打开同一个面板。
- `/account/sync` 的主按钮与结果区使用同一个状态机和同一套结果展示。
- 成功且面板未打开时才出 Toast。

## P · 全局搜索与命令面板

**P1 搜索范围与匹配。** 歌曲按中文曲名、日文原名、别名、艺术家、曲目 ID 匹配。统一规范化后比较：NFKC、忽略大小写与空格标点、片假名与平假名互通、全角半角互通。多个词需全部命中。排序：标题完全相同 > 标题前缀 > 别名 > 标题包含 > 艺术家。最多显示 8 首，末行「在曲库中查看全部 N 首」带着关键词进入曲库。

**P2 歌曲结果行。** 封面、标题；若命中的是别名或另一种语言，在副行注明（「别名：qby」）。右侧对魔王与里各显示：难度徽章（星级 + 定数，没有定数显示「—」）与我的成绩（王冠、评价、成绩；没打过显示「—」）。回车进入默认难度（查询里含「里 / 裏 / ura」则进里谱）；难度徽章本身可以点，直达该难度。

**P3 配置串。** 形如 `16 oxxo 180 鬼10` 的输入被识别为「按配置查谱」：先显示解析结果（分音、用咚 / 咔音符画出的配置、BPM、难度），再直接列出最多 5 张命中的谱面（歌曲、难度、第几小节、出现次数）。回车打开对应歌曲并定位到那一小节；末行「在工具页查看全部」把同一查询带到工具页，工具页显示同一份结果。

**P4 纯数字。** 2–4 位数字识别为「按物量查谱」，列出物量最接近的 5 张谱。

**P5 帖子。** 匹配标题、标签、版块、作者；最多 4 条；末行「在社区搜索」把关键词带到社区。

**P6 操作与页面。** 快捷操作：同步成绩、发布新帖、单曲 RT 计算器（查询命中歌曲时变成「用 RT 计算器算〈曲名〉」并带上歌曲）、选一个目标、切换深浅色、切换语言。页面：所有一级与二级页面按名称可搜。

**P7 键盘。** `Ctrl/⌘ K` 开关；非输入状态下 `/` 打开；`↑ ↓` 循环移动，`Home / End` 到首尾；`Enter` 执行；`Esc` 关闭。输入框是 `combobox`，结果是 `listbox / option`，用 `aria-activedescendant` 指示当前项；当前项始终滚入可视区；鼠标移动才改变当前项，滚动不改变。

**P8 焦点。** 打开时焦点进输入框；关闭时回到触发它的元素；执行导航后焦点移到新页面的主内容区，并用 `aria-live` 播报页面名。

**P9 手机。** 全屏；输入行固定在顶部，右侧「取消」；用 `visualViewport` 让结果区避开软键盘；开始滚动结果时收起键盘；首次点按结果即生效。空状态给出可点的示例查询（一首歌、一个别名、一个配置串、一个物量），点了就填入并出结果。

**P10 最近看过。** 记录最近打开的 5 首歌（本地存储），可清除。

**所有示例查询都必须有真实可操作的结果**，不允许只出 Toast 或跳到无关页面。

## R · 路由状态

**R1 切换难度保留上下文。** 歌曲详情切换难度只替换 `d`，保留其余查询参数（`from`、`q`、`m` 等）。

**R2 列表状态写进地址。** 曲库的关键词、上架状态、流派、星级、有里谱、我的进度、排序、视图都与地址同步（默认值不写）；输入关键词时 250ms 防抖，用 `replace` 不堆历史。成绩、定数表、社区、点灯进度、Rating、成长档案、推荐、段位、攻略的筛选与切换同样处理。从地址初始化，刷新或分享链接能还原同一个视图。

**R3 返回还原。** 浏览器后退 / 前进恢复滚动位置；只改查询参数不滚动；新导航回到顶部。虚拟列表的总高度由行数决定，保证首帧即可还原位置。

**R4 返回按钮走历史。** 详情页的返回按钮优先 `history.back()`，回到带着筛选的列表；没有站内历史时才回到模块首页。

**R5 同一路由换对象。** 从一首歌到另一首歌是全新状态并回到顶部；同一首歌换难度就地更新，不跳动。

**R6 快速切换不出错。** 所有定时器、观察器、监听器在卸载时清理；异步的 Mock 流程在组件卸载后不再写状态。验收：6 秒内连续切换 60 个路由，无控制台错误、无超过 200ms 的长任务。

## D · Design System 缺陷

对应 V1 规范「已知未解决」的 10 项（K1–K10）与本轮新增要求。

| 编号 | 对应 | 裁决 |
|---|---|---|
| D1 | K1 | 页面与组件一律不引用 Primitive 色与十六进制色。原型评审页里 B / C 方向的概念稿除外（它们本来就是别的配色）。 |
| D2 | K2 | 难度切换条收进 `domain.css`（`.diff-tab`）。页面不得声明难度色、王冠色、评价色。 |
| D3 | K3 | 封面圆角用现有阶梯：小 `--r-xs`、默认 `--r-ctl`、大 `calc(var(--r-ctl) + 2px)`、特大 `--r-panel`。命令面板图标格用 `--r-ctl`。 |
| D4 | K4 | 新增中性 token：`--note-ring`、`--note-outline`（音符的白环与深色描边，谱面带内外通用）、`--toast-bg`、`--toast-ink`。`--lane-*` 只在谱面带、谱面图、空状态条里使用。 |
| D5 | K5 | 修正 `tokens.css` 里三处过时注释。 |
| D6 | K6 | 无障碍补齐，见下方「无障碍」。 |
| D7 | K7 | 触控目标，见下方「触控」。 |
| D8 | K8 | 缺失值统一用「—」（`.na`，`--ink-3`），包括星级格、定数、成绩、未游玩的王冠位。 |
| D9 | K9 | 新增 `--bar-h-m: 52px`、`--subtab-h-m: 44px`、`--hit: 44px`。断点只用 767 / 1099 / 1239 三个；定数表的 1439 断点删除，改用列优先级。 |
| D10 | K10 | `index.html` 在样式加载前写入 `data-theme`（读本地设置，否则跟随系统），并设置 `color-scheme` 与页面底色，深色用户首屏不闪。 |

**D11 对比度。**
- 正文与小字（<24px，或 <18.66px 的粗体）在它所处的每一种底色上 ≥ 4.5:1，浅色与深色都要满足。需要重新校准：`--ink-3`、`--don-ink`、`--ka-ink`、`--roll-ink`、`--ok`、`--danger` 及其 wash 底上的文字、占位符、图表坐标轴文字、谱面带上的日期文字。
- 难度色作为**文字**使用时，新增 `--diff-*-ink`（保证在 `--surface` 与自身浅底上 ≥ 4.5:1）；色块、边框、图形继续用 `--diff-*`。
- 大字 ≥ 3:1。
- 非文字界面元素（输入框边界、未选中的分段、图标状态）≥ 3:1：新增 `--ctl-border` 用作输入类控件的边框。
- 禁用态不受此限，但不得承载必要信息。
- 没打过 / 休息日等「弱」状态用字重和形状区分，不再靠降低不透明度。

**D12 控件 token 统一。**
- 高度：`--ctl-h-sm: 30px`、`--ctl-h: 38px`、`--ctl-h-lg: 46px`；手机上可点控件不低于 `--hit`。
- 按钮、输入框、选择框、文本域、分段、筛选胶囊共用 `--ctl-border`、`--ctl-radius`、`--ctl-pad-x`。
- 标签：`--tag-h`、`--tag-radius`。色调固定五种：中性、信息（浅葱）、高光（山吹）、成功、危险。**朱色标签只表示「主操作相关 / 置顶」等强调，不表示失败**；失败、错误一律用危险色调。
- 浮层（对话框、抽屉、命令面板、菜单、浮动面板、Toast）共用 `--overlay-radius`、`--overlay-pad`、`--overlay-shadow`，抽屉顶角用 `--r-sheet`。

**D13 减少动效。** 尊重 `prefers-reduced-motion`，并提供原型开关模拟（根元素 `data-motion="reduce"`）。减少动效时：没有无限循环动画（加载条显示静止的三个音符 + 文字，骨架屏不扫光，同步图标不旋转而显示阶段文字）；没有回弹缩放；滚动定位不用平滑滚动。

**D14 中日文与长标题。**
- 列表与表格里的标题：单行截断，`title` 属性给出全文。
- 详情页头部、卡片标题：最多三行，`overflow-wrap: anywhere; line-break: strict; text-wrap: balance`，超出再截断。
- 数字永不截断。
- 曲名里的数字用正文字体，不用数字字体。
- 另一种语言的副标题带正确的 `lang`。
- 日文界面：标签比中文长约 1.3–1.4 倍，按钮不换行，由容器换行或横滑；左轨标签 11px。
- 特殊字符（＊、～、↑↑、♡、!?、全角括号）不得破坏行高与对齐。

**D15 语义统一。** 难度、王冠、评价、判定、状态色只有一个来源（`tokens.css` 的 Domain 层 + `domain.css` + 对应组件）。页面里出现这些语义时必须用组件或 domain 类，不得自己配色。

**D16 规范与实现一致。** 规范以实现为准更新；规范里写了而实现没做的，要么做掉，要么从规范里删掉。

**无障碍（D6）。**
- 地标：`header`、`nav`（带名称）、`main`；页首有「跳到主要内容」。
- 路由切换后焦点到主内容，播报页面名。
- 账号菜单：`Esc` 关闭并还原焦点，`↑ ↓` 在菜单项间移动。
- 分段控件是带名称的 `group`，项用 `aria-pressed`；页签是 `tablist / tab`，支持左右键。
- 所有只有图标的按钮有 `aria-label`；表单控件有可见标签或 `aria-label`；表格有 `caption`（可视觉隐藏）与 `scope`。
- 图表有文字替代（可访问名称 + 相邻的数字）。图表与谱面图的标签随语言切换。
- 目标卡的尝试轨迹用有序列表并带读屏文字。
- 焦点环在所有底色上可见（含谱面带与主按钮）。

**触控（D7）。** 手机上：`.btn`、`.btn-sm`、图标按钮、底栏项、列表行的可点区域 ≥ 44×44。筛选胶囊与分段内钮视觉高度 38px，用透明的扩展区补到 44px，相邻控件间距 ≥ 6px 避免扩展区重叠。正文里的行内文字链接不受此限。

## M · 真实规模的模拟数据

**M1 两套数据。** `full`（默认）：30 首精选曲 + 确定性生成的曲目，共 ≥ 1,500 首；`demo`：只有 30 首精选曲。原型控制面板与地址参数 `?data=` 可切换，切换后刷新。生成曲目带 `generated: true`，曲名由词库组合，明显是示例；字段结构与精选曲一致，并补充 `aliases`、`hasChartImage`、`hasAudio`。

**M2 边界情况必须出现。** 国行未上架、其他平台；没有里谱、只有魔王；缺定数；没有谱面图；没有试听；缺艺术家；BPM 区间；≥ 40 字的日文长标题与长中文译名；含特殊字符的标题；中日文同名；别名很多的曲目。

**M3 成绩。** ≥ 800 条，分布与玩家能力相符。页面上的合计（王冠数、评价分布、有成绩的谱面数）全部由数据计算，不再写死。

**M4 成长与目标。** 400 天的 Rating 历史、60 周的六维历史、120 天的每日进展、12 周的每周回顾（上一周 / 下一周可用）、约 14 个里程碑、1 个进行中的目标 + 24 条历史。

**M5 社区。** 约 240 个帖子（含 120 字长标题、280 字长摘要、无关联谱面、多标签）；1 个 60 楼的长帖（含楼中楼与 2,000 字以上的长正文）；60 条通知。

**M6 性能预算**（生产构建、`full` 数据、1440×900）：数据生成 ≤ 150ms；搜索每次按键出结果 ≤ 50ms；曲库筛选 / 排序 ≤ 100ms；路由切换到内容可见 ≤ 200ms；曲库与成绩列表同时挂载的行 ≤ 60（虚拟滚动）；点灯进度首屏挂载的格子 ≤ 400（折叠低星级分组）；帖子楼层分页加载。

## V · 模块的视觉表现

同一套 token 与组件，四类模块在版面节奏、字号用法和「谱面元素出现多少」上有意区分。

| 模块 | 关键词 | 版面 | 文字与密度 | 颜色角色 | 谱面元素 |
|---|---|---|---|---|---|
| 曲库、成绩 | 效率、可比 | 表格、分面、吸顶表头、固定首列 | 13–14px，紧凑行 | 中性为主；朱只给主定数与 Rating | 只作为数据编码（星级格、王冠、密度条） |
| 成长、目标 | 时间、过程 | 共享一条时间轴；图表开放、不加面板框；纵向留白宽 | 16px 正文；用叙述句作标题 | 浅葱 = 过程，山吹 = 里程碑，朱 = 达成 | 谱面带、用音符标里程碑 |
| 社区、个人主页 | 身份、内容 | 阅读栏、头条、更大的封面与头像 | 标题 16–22px，行高宽 | 版块色点；称号牌用山吹 | 不用谱面带；用鼓面头像 |
| 账号、绑定 | 清晰、可靠 | 单栏 760px、分段标题、状态行、步骤器 | 14–16px；按钮文案写明后果 | 中性 + 状态色 | 只有步骤器里的音符 |

**V1 今日。** 问候降级为一行身份信息（头像、昵称、称号牌、段位、ID）。页首主句是上次同步带来的变化（「上次同步带来 4 条新进展，其中 1 个新全良。」），没有新进展时才是问候。宽屏下第一行三栏：Rating ｜ 六维 ｜ 当前目标。1280×800 下首屏要能看到谱面带。

**V2 歌曲详情。** 头部压缩：封面桌面 112px / 手机 72px，标题最多两行，事实信息排成一行。1440×900 下首屏要能看到谱面图上沿和完整的「我的成绩」。补齐三种缺失状态：没有定数、没有谱面图、国行未上架。带 `m=` 参数时定位并高亮那一小节。

**V3 成长档案：时间栈。** 指标折线、关注方向带、里程碑标记、练习密度条共用同一条横轴，上下对齐，切换范围时一起变化。图表开放、不加面板框。里程碑列表按时间在前的竖向脊线排列。

**V4 目标。** 当前目标是一条「路径」：每次尝试沿横轴排开，终点是目标的判定圈；下面是按日期的练习记录。历史按月分组，带竖向脊线。

**V5 这一周。** 12 周数据下「上一周 / 下一周」可用；其余保持。

**V6 社区广场。** 帖子流顶部有「头条」（置顶或精选的第一帖：22px 标题、三行摘要、96px 关联谱面封面、作者头像与称号牌）。普通帖子行先显示作者（头像 32px + 昵称 + 段位），再是标题。新增三个身份原子：`PlayerAvatar`（鼓面头像，鼓缘颜色随段位档次）、`TitlePlate`（称号牌，稀有称号用山吹）、`DanBadge`（段位）。它们在帖子、楼层、榜单、通知、个人主页、今日、我的里统一使用。

**V7 帖子详情。** 作者区放大（头像 44px、称号牌、段位）。长帖：楼层分页（每页 20 楼）、「只看楼主」、跳到楼层；楼中楼超过 3 条折叠。

**V8 个人主页。** 顶部身份带（用谱面带的深色做底，不放图片）：96px 鼓面头像、昵称、称号牌、段位。其下是王冠与「极」的数量，再是三首「代表成绩」（96px 封面）。

**V9 我的（手机）。** 身份带 → 一块概览（Rating、近 30 天变化、最近 7 天的迷你谱面（天数按 C2），不放同步按钮）→ 2×2 快捷格（Rating / 全部成绩 / 目标 / 这一周，每格带一个实时数字）→ 其余入口分组列表 → 语言与主题 → 退出登录。390×844 下总长度不超过两屏半。

**V10 账号、设置、开发者。** 单栏 760px；桌面左侧有吸顶的页内目录。状态一律「图标 + 文字」。危险操作集中在页面底部。

**V11 数据页的列优先级。** 1280 宽与平板下按优先级隐藏列（先隐藏上架日期、流派、次要能力值），横向仍放不下时首列固定、表格内部横滑。「我的」列同时显示魔王与里。设置里的列表密度对所有表格生效。

**V12 平板。** 保留左轨；双栏按规则折叠；表格保留为表格（不变列表行），对话框保持居中。

## Q · 真实浏览器验收

**Q1** 用系统安装的 Chromium 内核浏览器（Chrome 或 Edge）经 Playwright 驱动，针对生产构建（`vite preview`）运行；脚本在 `qa/`。一次只开一个浏览器，页面并发 ≤ 2，结束时关闭。

**Q2 视口**：1440×900、1280×800、820×1180、390×844、360×740。**状态**：浅 / 深，中 / 日，游客 / 未绑定 / 无成绩 / 已同步，`full` / `demo` 数据。核心页面做有代表性的交叉，不做无意义的全排列。

**Q3 每页自动检查**：控制台错误与未捕获异常；横向溢出及溢出元素；可点元素是否被固定栏遮挡；未声明的文字截断；手机触控目标；文字对比度；焦点环。

**Q4 交互脚本**：命令面板全流程（含别名、日文、艺术家、配置串、物量、帖子、操作、手机全屏）；同步在四种登录态 × 三种结果下的流程；对话框 / 抽屉 / 菜单的开关与焦点；曲库筛选 → 详情 → 返回的状态还原；难度切换保留参数；60 路由快速切换；主题首屏不闪；减少动效下无循环动画。

**Q5 性能**：按 M6 的预算实测并记录。

**Q6 产出**：全部原始截图在 `qa/out/`（不入库）；关键截图与浅深对照在 `qa/screenshots/`（入库，压缩）；报告区分「已在真实浏览器验证 / 仅源码或静态检查 / 尚未验证」。模拟数据下的测试不是生产验收。

## C · 截图复核裁定

第一轮验收的截图由设计负责人逐张看过。自动检查全部通过，但下面这些问题只有看图才能发现，一并在 V1.1 内修掉。

**C1 今日（平板）的「今天」列表。** 820 宽下标题列与两栏成绩行挤在一起，文字逐字换行并与分数重叠。≤1099：标题在上，成绩行单栏通栏；≥1100 才并排、才分两栏。行内元素不允许逐字换行：曲名单行截断，说明文字单行截断，分数与差值不换行不截断。

**C2 谱面带（Lane）的列宽与音符。** 列宽不足时大音符互相压住，日期标签相撞（360 宽的「我的」、平板的今日）。规则：
- 音符直径不超过「列宽 − 8px」，三档大小按列宽等比缩小；
- 每天可点时列宽 ≥ 44px，放不下就横向滚动，默认停在今天，左缘用渐隐提示还有内容，不允许半个标签被硬切；
- 只作概览、每天不可点时（手机「我的」）列宽 ≥ 36px，显示最近 7 天，整条谱面带是一个去「成长」的链接；
- 列宽 < 40px 时日期只写「日」，月初与今天写全。

**C3 谱面图（ChartSheet）每行小节数。** 平板下 4 小节挤在 350px 里，音符糊成一团。每行小节数按容器宽度取：每小节 ≥ 150px，可选 4 / 2 / 1；随容器变化即时重排。

**C4 曲库（平板）的筛选。** 820 宽下四组分面占满第一屏，列表从第二屏才开始。768–1099 改用手机的做法：一行常用筛选 chip + 「筛选」按钮，完整分面放进居中对话框；表格仍是表格（V12 不变）。

**C5 歌曲详情（手机）的难度标签。** 未选中的难度只剩星级和边框颜色，等于只靠颜色区分。任何宽度下每个难度都带文字：放不下全称时用单字（简 / 普 / 难 / 鬼 / 里；日文沿用 Diff 组件的短标）。这一行可横滑，右缘渐隐。

**C6 歌曲详情的曲名。** 详情页是看完整曲名的地方，主标题不截断，按字自然换行；副标题最多两行，截断时 `title` 带全文。列表、卡片里的截断规则（D14）不变。

**C7 定数表（手机）行内的个人状态。** 难度徽标后面出现了孤立的小圆点和小王冠。个人状态只用 Crown 组件，尺寸与其他列表一致并带可读名称；没打过就不显示。

**C8 搜索面板的「查看全部」。** 结果已经全部列出时（总数 ≤ 已显示条数），不再显示「在曲库中查看全部 N 首」。

**C9 原型面板的侧边把手（手机）。** 把手压住了页面左缘的文字（社区的「精选」）。手机上把手的可见宽度 ≤ 12px，留在 16px 的页边距内；点击区域可以向屏幕外扩展，不向内容方向扩展。

**C10 触控目标的豁免范围。** 行内文字链接（行里的作者名、版块名）属于行内链接，不要求 44px，但点击高度 ≥ 24px，且所在整行是 ≥ 44px 的主目标。表单控件没有豁免：发帖页的标签输入在手机上与其他输入框一致，用 `--ctl-h-lg`（46px）。谱面带按 C2。

**C11 登录与绑定页的跳转链接。** 这两页没有导航可跳过，不加「跳到正文」；保留唯一的 `main` 地标与正确的标题层级。

**C12 搜索面板的首键延迟。** 预算不改（p95 ≤ 50ms）。打开面板时预先挂载结果行的结构，首批结果条数压到一屏以内；修后如果仍在预算边缘波动，如实记为非阻塞并写出多轮的范围。

**C13 认可的自行判断。** 步进器里浅色音符上的深色数字、社区侧栏吸顶后可独立滚动、浅色主题难度文字加深，均通过；难度文字颜色只允许经 `--diff-*-ink`。

**C14 文字相撞检查。** C1 这类问题自动检查没有拦住。验收脚本增加「相邻文字盒相交」检查，并在 820×1180 下对全部产品页逐张看图。
