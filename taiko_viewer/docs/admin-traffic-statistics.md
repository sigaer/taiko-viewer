# Viewer 管理台访问统计（1.5.0）

## 口径

- 数据来源：配置的 Viewer Nginx combined access log，独立来源键 `viewer_access_v2`。旧 `viewer_access` 汇总保留，不混入新版统计。
- 页面请求 PV：已发布 Nuxt 页面（含日语、动态路由）及练习播放器 HTML 的 GET，成功状态或 304；排除接口、资源、扫描路径、已知自动化、空 UA 和疑似异常行为。
- 独立 IP：上述有效请求中的 IP 在整个窗口内去重，不是自然人数。共享网络会合并多人，网络切换会拆分一人。
- 24h 窗口：北京时间界面显示起止时间，覆盖最近完整的 1440 分钟。最近未结束的分钟不进入总数，避免部分小时造成边界误差。
- 首页请求：有效 `/`、`/ja`、`/ja/` 请求，不是点击事件。
- 无刷新站内跳转、浏览器完全本地缓存命中不产生页面访问日志，无法从历史日志还原。后台明确采用服务器页面请求口径；GA 的浏览器 page_view 是独立数据源，不拼接相加。
- 原始请求 = 有效 PV + 疑似自动化 + 其他排除。原因互斥归类，不重复加总。

## 异常识别

每分钟按 IP + UA 分组，仅页面、错误和扫描流量参与行为判断，资源并发与 API 轮询不触发规则。满足以下任一条件，该组当分钟的候选页面请求整体转入疑似自动化：

1. 扫描路径至少 10 次，或请求至少 20 次且错误比例达到 80%。
2. 有效候选页面至少 60 次。
3. 同一路径至少 20 次（查询参数不参与路径去重）。

跨批次重新计算该分钟，避免阈值前的请求漏归类。这是可解释的启发式识别，不能证明真人身份，也不能识别全部低速或分布式自动化。仅调整统计，不封禁请求；同一共享 IP 的不同 UA 分组判断。

## 回填与恢复

Nitro 启动 5 秒后开始独立回填；空闲每 30 秒检查，积压时每批间隔 250ms。每批最多读取 8MiB，只提交完整行；每行最多解析 64KiB。使用文件设备号、inode、偏移和边界内容哈希识别轮转、截断和同尺寸覆盖，优先读完可找到的旧轮转文件。旧文件不可用时记录日志缺口，不声称完整覆盖。

数据库命名锁保证跨进程单写入；每批分钟统计和游标在同一事务提交，失败回滚后可重试。新键首次从当前日志起点重算最近 30 天，完成前展示回填状态。仅保留新版最近 30 天分钟明细。UI 展示检查时间、覆盖缺口和解析失败累计数量；超过 120 秒未检查标为延迟并隐藏汇总卡片数值。

隐私：不保存明文 IP、UA、路径、查询或请求正文。访客与路径使用独立随机密钥 HMAC；密钥在受限后台状态表中，不返回浏览器。每分钟最多 1000 个行为组，超出候选计入“超出统计容量”。单次快照最多处理 20 万行为组，超限失败，不返回截断的伪精确统计。日志畸形或资源限制不触发不受控回退。

## 验证与发布

通过 memory runner 运行：

```sh
bash scripts/memory/run_qa.sh /bin/bash -c 'cd taiko_viewer && TAIKO_ALLOW_TEST_DB_MUTATION=1 node --test --test-concurrency=1 tests/adminTraffic.test.mjs tests/adminTrafficSql.test.mjs tests/adminDashboardTime.test.mjs tests/versionProjection.test.mjs'
bash scripts/memory/run_qa.sh /bin/bash -c 'cd taiko_viewer && node scripts/verify_admin_traffic.mjs'
```

SQL 测试启动仅 Unix socket 可访问的独立 MySQL，验证 datadir 与实际 `SELECT DATABASE()` 的 `_test` 后缀及显式 mutation opt-in；仅生成合成数据。验证并发、事务中途失败、幂等重试、窗口去重、跨批次重分类和延迟状态。浏览器验证实际 Vue 页面在 390/1440px 的布局、原因展开与回填/延迟/等待状态。发布仍只使用标准 Viewer deploy 脚本。
