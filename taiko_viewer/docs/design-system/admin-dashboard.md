# 后台工作台（/admin/taiko/dashboard）

## 视觉
- 后台外壳 `layouts/admin-taiko.vue` 定义 `--admin-*` 变量：底色 `#f4f6f6`，卡片白底、1px `#e3e8e8`、圆角 12px，无渐变和重阴影；文字 `#1b2426` / `#5d6b6e`；主色青绿 `#006c76`、浅青 `#d7ece9`；第二序列色琥珀 `#c98a2e`。
- 侧栏深青 `#0f2426`，当前项浅青底 + 青绿字；窄屏（≤1024px）侧栏收为顶部，导航横向换行。
- 数字一律 `tabular-nums` + `toLocaleString('zh-CN')` 千分位。

## 布局（自上而下）
1. 页头右侧：状态胶囊（统计中 / 补录中 / 延迟 / 不完整，仅异常时出现）、"更新于 HH:mm"、刷新。
2. 关键数字：左侧「今日 · 活跃用户」主卡（较昨日差值、已登录/未登录拆分、14 天走势）；右侧「近 24 小时」三卡：浏览量、成绩上传（来自 N 位玩家）、Bot 指令。小迷你图用内联 SVG（`AdminSparkline`），不用 echarts。
3. 两列网格（<900px 单列）：用户卡 | 访问趋势；新增与上传 | 热门指令；最近操作 | 系统状态。
4. 访问趋势：48 小时 = 浏览量 + IP 访客；30 天 = 活跃用户（左轴）+ 浏览量（右轴）。横轴标签不旋转。
5. 系统状态是唯一放统计口径的地方：其余说明收在折叠的「统计说明」里。

## 指标定义
- 活跃用户（DAU，北京时间自然日）= 以下身份的并集去重：
  - `web_user_daily_activity`：当天有过已登录请求的账号（含 App/API 用户），身份 `u+user_id`；
  - `web_daily_visitors`：前端信标上报的合格访问（可见 5 秒或首次交互），非可疑设备；已关联账号记为 `u+user_id`，否则 `d+visitor_key`。
  - 已登录 = `u` 身份数；未登录 = 其余。近 7/30 天活跃用同一并集，窗口内任一天关联过账号的设备记为该账号。
- `dauSince` = 信标上线首日（`web_daily_visitors` 最早一天）；此前显示为未统计而非 0。
- 浏览量 = 有效页面打开次数（日志口径，已排除机器访问）。IP 访客 = 按网络地址去重，只在系统状态与 48 小时趋势中出现。
- 成绩上传 = userdata 快照文件数；上传玩家 = 有上传的不同游戏 ID 数。
- 已拦截可疑设备 = 同一网络地址当天超过 20 台设备后新增的设备（`is_suspect = 1`，不计入活跃）。

## 已知局限
- 同一人用多个浏览器、无痕窗口或清除存储会被算成多个设备，略有高估。
- 能执行 JS 的无头机器人可能漏网（已过滤 webdriver 与已知自动化 UA）。
- 信标上线前没有历史数据；账号活跃表的回填只覆盖会话最后访问日，历史天数不完整。
- "较昨日"是今天截至当前与昨天全天的比较，白天通常为负数。

## 数据与隐私
- 设备 ID 与 IP 只以 HMAC（复用访问统计盐值）存储，不存明文设备 ID、IP、UA；访客表保留 90 天。
- 网络地址取 Nginx 写入的 X-Real-IP（仅信任本机反代），不使用客户端可伪造的 X-Forwarded-For。两张表都不带外键（同 `web_player_goals`；测试库账号无 REFERENCES 权限）。
- 两张新表不在运行时必需表清单中：需执行 `scripts/migrate_user_activity_schema.ts --apply` 创建；未建表时写入静默失败，工作台显示「—」。

## 文案规则
- 只写名词、数据和动作；不出现字段名、表名、英文术语或实现说明，不加解释性副标题。
- 口径解释只放在 (?) 提示或「统计说明」折叠区。
- 最近操作用人话："{操作者} {动作}{对象}「名称」" + 相对时间（悬停显示绝对时间），不显示文件路径或原始键；查看类记录不出现在这里。
