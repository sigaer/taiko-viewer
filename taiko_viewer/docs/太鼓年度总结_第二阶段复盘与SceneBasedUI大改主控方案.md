# 太鼓年度总结第二阶段复盘与 Scene-Based UI 大改主控方案

> 本文档基于当前“第二阶段优化”成品视频、此前两版 Markdown 改造方案、以及关于 Codex、Figma、Rive、frontend-design / ui-ux-pro-max-skill 的讨论整理。  
> 目标是作为下一轮 Codex 改造的主控文档：明确第二阶段成品的问题边界、保留价值、UI 大改方向、Design Skill 接入方式、页面重构规范与验收标准。

---

## 0. 结论先行

当前第二阶段成品已经明显优于初版 demo，但它仍然没有达到“年度总结演出”的效果。

它现在更接近：

```text
经过美化的统计报告 H5
```

而不是：

```text
场景式、叙事式、带有游戏结算和音乐年度总结仪式感的太鼓年度总结
```

下一轮不应继续在现有页面上做“小修小补”，而应进行表现层范式重构：

```text
从 Card-based / Dashboard-like Layout
  ↓
到 Scene-based / Annual Recap Performance Layout
```

需要强调的是：这不是重做整个项目。

应保留：

```text
数据层
summary JSON
页面业务含义
后端统计逻辑
快照 diff 逻辑
已有资产路径
```

需要大改：

```text
页面 UI 范式
通用页面容器
卡片式布局
转场方式
核心页面视觉
动画时序
文案呈现方式
分享海报表现
```

## 1. 第二阶段成品复盘

### 1.1 第二阶段已经变好的部分

从第二阶段视频看，当前版本相比最初 demo 已经有以下进步。

#### 1.1.1 开屏页已经有年度入口气质

开屏页出现了：

```text
“敲响的 2026 仍在回声之中”
封面墙
谱面轨道
太鼓图标
开始按钮
generated by sakurabot
```

这说明 Codex 已经开始理解“年度总结封面”的方向。

可保留的部分：

```text
年度标题方向
封面墙元素
谱面轨道元素
太鼓图标入口
深蓝 / 彩虹氛围
```

但当前开屏页仍偏“静态海报 + 按钮”，还没有成为“舞台开演”。

---

#### 1.1.2 玩家身份页已经形成个人卡片

第二页展示了：

```text
“这一年的主角，是 ☆星乃一歌☆”
玩家头像 / 装扮截图
称号
段位
地区
```

这已经比普通信息页更接近“玩家登场”。

可保留的部分：

```text
玩家名作为主角
装扮 / 头像作为身份核心
称号和段位信息
个人登场的文案方向
```

不足是：它仍然是“资料卡”，不是“舞台登场”。

---

#### 1.1.3 总览页开始有大数字冲击

总览页中已经出现了：

```text
“一锤一锤，敲成现在的你”
大号游玩次数
歌曲数 / 谱面数
时长
太鼓图标
漂浮封面 / 谱面层
```

可保留的部分：

```text
超大数字方向
中央太鼓图标
辅助数据分层
“一锤一锤，敲成现在的你”的文案方向
```

不足是：视觉仍然像“有主数字的统计页”，而不是一个完整的数字爆发场景。

---

#### 1.1.4 圆形仪表语言已经出现

例如：

```text
倍速页 1.2x
每日/时间相关页面的圆形轨道
关键词页的圆形雷达
```

这说明项目已经开始脱离单纯矩形卡片。

可保留的部分：

```text
圆形仪表
鼓面 / 圆盘隐喻
雷达图
环形时间视觉
```

但需要进一步强化为“主视觉”，而不是卡片里的图表。

---

#### 1.1.5 最终称号页方向正确

最终称号页出现了深色背景、金色光感、年度称号“十星连击者”等。

这部分方向非常正确，应作为后续 Award Scene 的基础。

可保留的部分：

```text
深色背景
金色光晕
年度称号
颁奖感
分享按钮
```

不足是：最终页仍然有“卡片叠信息”的痕迹，称号还没有真正成为全屏主角。

---

### 1.2 第二阶段仍然存在的核心问题

#### 1.2.1 仍然没有摆脱卡片式报告范式

大量页面仍然是：

```text
浅蓝背景
标题
一个或多个卡片 / 信息块
局部图表
说明文案
淡入淡出
```

这会让用户感觉是在看：

```text
数据报告
统计面板
轻量 dashboard
```

而不是：

```text
年度总结演出
音乐回忆
游戏赛季结算
个人太鼓故事
```

---

#### 1.2.2 动效仍然偏“元素出现”，不是“场景演出”

当前动画大多仍属于：

```text
元素淡入
卡片上浮
数字出现
页面普通切换
```

年度总结需要的是：

```text
主视觉驱动转场
数据爆点
场景继承
封面聚合
鼓面扩散
称号颁奖
日历点亮
夜色沉入
```

也就是说，动效不应只是让元素“动一下”，而应当回答：

```text
这一页为什么这样出现？
它和上一页有什么关系？
这个数据为什么是这一幕的高潮？
这一页如何自然转入下一页？
```

---

#### 1.2.3 每页主视觉焦点不够唯一

例如某些页面中：

```text
标题很大
卡片很大
数字也大
图表也大
背景也有元素
```

导致视觉焦点不稳定。

年度总结页面应当遵循：

```text
一页只有一个主角
其他信息都围绕主角服务
```

例如：

```text
OverviewPage 的主角只能是“游玩次数”
FavoriteSongPage 的主角只能是“歌曲封面”
FinalTitlePage 的主角只能是“年度称号”
SpeedPage 的主角只能是“倍速仪表盘”
CalendarPage 的主角只能是“被点亮的日期”
```

---

#### 1.2.4 文案已经改善，但仍没有完全融入演出

第二阶段文案比初版更好，例如：

```text
一锤一锤，敲成现在的你
敲响的 2026 仍在回声之中
这一年的主角，是 ☆星乃一歌☆
```

这些方向值得保留。

但很多页面仍然像：

```text
标题 + 数据说明 + 简短补充
```

而不是：

```text
情绪铺垫
数据揭示
记忆点收束
```

文案需要与动画时序结合，例如：

```text
先出现情绪句
再出现核心数字
最后落下记忆点
```

---

#### 1.2.5 最终分享页仍然不够“年度名片”

视频末尾的分享页已经具备结构，但仍像总结页面截图，而不是一个可以单独传播的正式年度海报。

分享页应当是：

```text
独立视觉作品
玩家年度名片
可保存、可转发、可截图传播
```

而不仅是：

```text
最后一页 + 按钮
```

## 3. frontend-design / ui-ux-pro-max-skill 的接入定位

### 3.1 为什么要接入 skill

当前 Codex 的问题不是不会写 CSS 或 Vue，而是容易退回通用 UI 范式：

```text
卡片
dashboard
浅色背景
统计模块
信息块
普通 landing page
```

因此需要用 frontend-design / ui-ux-pro-max-skill 来补充：

```text
设计系统生成
色彩 / 字体 / 间距规范
移动端 H5 规范
UX 审查
反模式检查
可访问性检查
动效合理性检查
```

### 3.2 Skill 的正确角色

frontend-design / ui-ux-pro-max-skill 应当作为：

```text
通用 UI/UX 设计系统工具
```

而不是：

```text
太鼓年度总结的最终审美裁判
```

项目专用规则优先级更高：

```text
本项目不是 dashboard。
本项目不是 SaaS。
本项目不是后台。
本项目不是普通报告。
本项目是太鼓年度总结 H5 演出。
```

### 3.3 建议生成的设计系统文档

Codex 应先生成并保存：

```text
docs/design-system/annual-summary-master.md
docs/design-system/annual-summary-scenes.md
docs/design-system/annual-summary-motion.md
docs/design-system/annual-summary-tokens.md
docs/design-system/annual-summary-anti-patterns.md
docs/codex/annual-scene-ui-refactor-task.md
```

这些文档不是摆设，而应成为后续自查依据。

## 6. 新场景模板系统

### 6.1 Hero Scene：登场型

适用：

```text
OpeningPage
ProfilePage
FinalTitlePage
PosterPage
```

核心：

```text
舞台感
主视觉居中
强氛围背景
按钮或称号最后出现
```

禁止：

```text
卡片网格
信息块堆叠
多焦点布局
```

---

### 6.2 Impact Number Scene：大数字型

适用：

```text
OverviewPage
PlayCountPage
TimePage
AchievementCountPage
```

核心：

```text
一个超大数字
最多 2-3 个辅助数据
数据爆发反馈
文案收束
```

当前第二阶段中的总览页已具备这个方向，但仍需去掉 dashboard 残留。

---

### 6.3 Song Memory Scene：歌曲回忆型

适用：

```text
FavoriteSongPage
ObsessionSongPage
MonthlyFavoritePage
HighScorePage
ChallengePage
NearDondafulPage
```

核心：

```text
歌曲封面是绝对主视觉
背景来自封面主色或模糊封面
歌名围绕封面出现
次数 / 日期 / 成就作为数据爆点
```

当前第二阶段中的 FavoriteSongPage 仍偏歌曲信息卡，需要重做。

---

### 6.4 Pattern Scene：习惯型

适用：

```text
CalendarPage
WeekdayPage
TimePatternPage
SpeedPreferencePage
RT / Rating Coordinate Page
```

核心：

```text
图形本体就是主视觉
日历、时钟、仪表盘、坐标系、环形轨道
数据嵌入图形，而不是放入卡片
```

当前第二阶段中的倍速页已经有圆形仪表，可以保留并强化。

---

### 6.5 Award Scene：成就型

适用：

```text
AchievementPage
FirstFullComboPage
FirstDondafulPage
KiwamiPage
FinalTitlePage
SharePoster
```

核心：

```text
暗场
金色 / 紫色 / 彩虹高光
成就印章
徽章
称号
颁奖式文案
```

当前第二阶段最终称号页已接近这个方向，应继续保留并强化。

## 7.1 OpeningPage

### 当前状态

第二阶段开屏页已经有：

```text
深蓝背景
年度标题
封面墙
谱面轨道
太鼓入口按钮
```

但仍偏静态封面。

### 新目标

改为真正的“太鼓舞台开演”。

### 主视觉焦点

```text
中央太鼓鼓面 / 封面墙
```

### 层级

```text
BackgroundLayer：深蓝 + 彩虹渐变 + 模糊封面墙
AtmosphereLayer：谱面轨道、音符流、咚咔粒子
MainObjectLayer：中央太鼓鼓面
DataFocusLayer：版本年份 / 版本名
CopyLayer：标题、副标题、开始按钮
TransitionLayer：taiko-ripple
```

### Timeline

```text
0.0s 背景从暗场亮起
0.3s 封面墙由远到近漂移
0.6s 谱面轨道开始流动
0.9s 中央太鼓鼓面 scale 0.88 → 1
1.1s 标题逐行出现
1.4s 副标题出现
1.7s 开始按钮出现
点击后 鼓面扩散为全屏白光 / 彩虹光
光效结束后进入 ProfilePage
```

### 文案

```text
鼓点响起的时候，
这一版的回忆也被悄悄记录了下来。

准备好了吗？
```

按钮：

```text
开启我的太鼓回忆
```

## 7.3 OverviewPage

```text
大数字
太鼓图标
辅助数据
漂浮封面 / 谱面层
```

### Timeline


## 11. 数据兜底与文案规则

### 11.1 数据兜底

必须处理：

```text
0
null
undefined
NaN
空数组
缺失封面
缺失称号
缺失段位
长日文歌名
长玩家名
```

规则：

```text
不自然的 0 值不要展示。
没有数据的页面应隐藏或降级。
长日文歌名自动缩放或换行。
缺失封面使用渐变 + 音符占位。
缺失称号时使用“这一版的鼓手”类文案。
```

禁止出现：

```text
0 点亮的日期
undefined 次
NaN h
空白大卡片
只有标题没有内容的页面
```

---

### 11.2 文案规则

文案采用三段式：

```text
情绪铺垫
  ↓
数据揭示
  ↓
记忆点收束
```

不要写：

```text
你的最常游玩歌曲是《xxx》，共计 xx 次。
```

改为：

```text
有些歌不是路过，
是你一次次回头。

这一版，
你打了《xxx》xx 次。

它大概已经很熟悉你的鼓点了。
```

不要写：

```text
你的倍速偏好是 1.2x。
```

改为：

```text
谱面变快的时候，
你的节奏没有乱。

这一版，
你最常停在 1.2x。

这大概就是你看见鼓点的速度。
```

## 12. 动效规范

### 12.1 动效必须有语义

允许：

```text
taiko-ripple：鼓面扩散
number-impact：数字爆发
cover-gather：封面聚合
cover-spin-in：封面旋入
award-reveal：称号颁奖
profile-spotlight：玩家登场
calendar-light-up：日历点亮
speed-gauge-lock：倍速锁定
night-fade：夜色沉入
stamp-burst：印章爆发
```

不应作为主效：

```text
fade in
slide up
scale 1.0 → 1.05
普通卡片 stagger
```

这些只能作为辅助过渡。

---

### 12.2 默认 timeline

```text
0.0s - 0.3s 入场转场
0.3s - 0.8s 标题出现
0.8s - 1.5s 主视觉出现
1.2s - 2.2s 核心数据动画
2.0s - 2.8s 文案出现
2.8s 以后 轻循环动效
```

---

### 12.3 页面间继承

建议逐步实现：

```text
Opening → Profile：
鼓面扩散后露出玩家身份

Overview → FavoriteSong：
大数字碎成封面碎片，聚合成歌曲封面

日历格子熄灭，只留下深夜记录

Achievement → FinalTitle：
成就印章引出年度称号

称号缩小进入海报
```


```text

summary JSON 兼容。
```

## 18. 总结
