# 太鼓年度总结 Demo 改造方案

> 本文档基于此前《太鼓年度总结实现方案（融合版）》(v3)以及当前 demo 的实现效果整理。  
> 当前 demo 的基础数据和页面链路已经基本成立，下一阶段不建议继续堆页面数量，而应将重点转向“年度总结演出感”：动效、视觉层级、文案情绪、页面节奏和分享完成度。

---

## 1. 当前阶段判断

### 1.1 已经成立的部分

当前 demo 已经验证了以下基础能力：

```text
用户数据可以读取
版本周期可以展示
玩家身份可以展示
总览数据可以展示
歌曲相关数据可以展示
月度 / 周度 / 日历 / 时间段等统计页可以出现
成就和分享页已有雏形
页面切换链路基本可用
```

这说明项目已经从“概念方案”进入了“可运行原型”阶段。

因此，下一步的重点不应是继续扩充页面，而是：

```text
把当前统计页原型升级成年度总结式 H5 演出。
```

### 1.2 当前主要问题

当前 demo 的主要问题可以归纳为四类。

#### 1.2.1 动效不足

目前多数页面的动效更接近：

```text
元素出现
卡片切换
简单移动
普通翻页
```

但年度总结需要的是：

```text
入场转场
主视觉登场
核心数字爆发
文案收束
离场衔接
```

也就是说，现在的页面“能展示数据”，但还没有形成“被演出来”的感觉。

#### 1.2.2 页面区分度不足

当前页面之间的视觉差异偏弱，整体更像同一套浅色模板不断替换数据。

年度总结需要明显的章节感：

```text
登场
总览
偏好
习惯
回忆
突破
收束
分享
```

每一章应有不同的背景氛围、主色、动效语法和视觉重心。

#### 1.2.3 文案偏说明式

当前文案更像：

```text
你本版本游玩了 xx 次
你最常游玩的歌曲是 xx
你最常在周日打鼓
```

但年度总结式文案应该是：

```text
情绪铺垫
  ↓
数据揭示
  ↓
一句记忆点
```

例如：

```text
有些歌不是路过，
是你一次次回头。

这一版，你打了《mint tears》41 次。

它大概已经很熟悉你的鼓点了。
```

#### 1.2.4 高光页不够突出

当前所有页面的强度接近，导致真正应该成为爆点的页面没有被拉开。

优先应该强化：

```text
开屏页
玩家身份页
总览页
最爱歌曲页
太鼓关键词页
深夜记录页
年度突破页
最终称号页
分享海报页
```

## 2. 改造总目标

### 2.1 一句话目标

将当前 demo 从：

```text
太鼓数据统计页
```

升级为：

```text
带有太鼓风格、玩家身份感和年度总结仪式感的 H5 小演出。
```

### 2.2 具体目标

下一轮改造需要达成：

1. 每页都有明确的“演出顺序”。
2. 页面之间有章节感，而不是模板轮播感。
3. 关键数据有视觉冲击力。
4. 文案从说明式改为情绪式。
5. 太鼓元素更深入参与动效，而不是只作为装饰。
6. 玩家装扮、称号、段位真正成为身份视觉核心。
7. 分享海报具备保存和传播欲。
8. 保持移动端性能，不因动画过多导致卡顿。

---

## 3. 新的信息架构

### 3.1 章节化结构

建议将年度总结拆成六个章节。

```text
第一章：登场
第二章：这一版，你敲响了多少次
第三章：你喜欢什么
第四章：你的太鼓习惯
第五章：那些被记录下来的瞬间
第六章：最终称号与分享
```

### 3.2 页面顺序建议

```text
01 开屏封面
02 我的太鼓身份
03 版本时间跨度

04 总览数据
05 最爱歌曲
06 念念不忘歌曲

07 太鼓关键词
08 曲风 / 系列偏好
09 倍速偏好

10 月度最爱
11 每周太鼓
12 太鼓日历
13 活跃时段
14 深夜记录

15 最高分诞生
16 离全良最近
17 挑战不放弃
18 年度突破

19 最终称号
20 分享海报
```

### 3.3 动态隐藏规则

如果数据不足，应动态隐藏页面。

```text
没有深夜数据 → 隐藏深夜记录页
没有倍速差异 → 隐藏倍速偏好页
没有接近全良曲目 → 隐藏离全良最近页
没有曲风数据 → 用歌曲分类 / 系列页替代
没有成就事件 → 用“这一版的尝试”鼓励页替代
游玩次数过少 → 启用新人版总结
```

## 4. 页面动效总规范

### 4.1 每页统一演出结构

每一页都按以下节奏设计：

```text
0.0s - 0.3s：入场转场
0.3s - 0.8s：标题出现
0.8s - 1.5s：主视觉出现
1.2s - 2.2s：核心数字动画
2.0s - 2.8s：情绪文案出现
2.8s 以后：轻微循环动效
```

### 4.2 页面层级

每页至少拆成五层：

```text
背景层：渐变、场景、纹理
氛围层：粒子、光带、音符、鼓点波纹
主视觉层：封面、装扮、图表、称号
数据层：大数字、排行、次数、时间
文案层：标题、解释、收束句
```

当前 demo 的问题是很多页只有：

```text
背景层 + 文本层 + 卡片层
```

下一版需要补足氛围层和主视觉层。

### 4.3 页面转场语法

建议建立统一转场库：

```text
taiko-ripple：鼓面扩散转场
cover-shatter：封面碎片转场
rainbow-sweep：彩虹光带横扫
calendar-build：日历格子铺开
night-fade：深夜变暗转场
gold-burst：成就金光爆发
radar-draw：雷达线条绘制
```

章节切换时使用强转场，普通页面切换时使用弱转场。

## 5. 关键页面改造方案

## 5.1 开屏封面页

### 当前问题

开屏页已经有年度总结入口感，但还不够“太鼓”。按钮点击后的反馈和下一页衔接可以更强。

### 改造目标

让用户一开始就感到：

```text
这是一次太鼓舞台开演。
```

### 页面元素

```text
歌曲封面墙
中央太鼓鼓面
彩虹光带
咚 / 咔粒子
开始按钮
弱节奏呼吸动画
```

### 动效设计

```text
1. 背景封面墙从远处缓慢靠近。
2. 中央太鼓鼓面轻微呼吸。
3. 标题逐字出现。
4. 按钮轻微发光。
5. 点击按钮后，鼓面向外扩散一圈白光。
6. 白光覆盖全屏并转入玩家身份页。
```

### 文案建议

```text
鼓点响起的时候，
这一版的回忆也被悄悄记录了下来。

准备好了吗？
```

按钮：

```text
开启我的太鼓回忆
```

## 5.2 我的太鼓身份页

### 当前问题

玩家身份信息可用，但视觉上还可以更像“玩家登场名片”。

### 改造目标

让用户明确感到：

```text
这是我的账号、我的称号、我的装扮、我的段位。
```

### 数据来源

```text
profile.mydon_name
profile.userid
profile.province
gameCostume.title
gameCostume.titleplate_id
gameCostume.costume_1~5
gameCostume.color_limb
gameCostume.color_body
gameCostume.color_face
gameCostume.got_dan_max
gameCostume.dan_name
```

### 动效设计

```text
1. 背景舞台灯光打开。
2. 称号条先滑入。
3. 玩家名从称号条下方浮现。
4. 装扮角色从光圈中登场。
5. 段位徽章最后盖章式出现。
```

### 文案建议

```text
这一版的你，
以「太鼓は生き甲斐」之名登场。

星乃一歌，
欢迎回到属于你的鼓点舞台。
```

### 视觉建议

```text
玩家名片不要做成普通信息卡。
建议做成“游戏资料牌 + 舞台登场”的形式。
```

## 5.3 版本时间跨度页

### 当前问题

时间页容易变成普通日期展示，缺少“时间流逝”的感觉。

### 改造目标

让页面有“转眼过去”的情绪。

### 动效设计

```text
1. 版本开始日期从左侧出现。
2. 版本结束日期从右侧出现。
3. 中间拉出一条时间线。
4. 时间线上的封面碎片快速掠过。
5. 玩家第一次记录日期被高亮标记。
```

### 文案建议

```text
从 2025 年 4 月 1 日，
到 2026 年 3 月 31 日。

虹2025 转眼走过了一整个版本。

而你的第一声鼓点，
出现在 2025 年 x 月 x 日。
```

---

## 5.4 总览数据页

### 当前问题

总览页是第一波高潮，但当前数字冲击力不足。

### 改造目标

做成“三连击”效果。

### 数据

```text
游玩次数
游玩歌曲数
谱面记录数
估算时长
过关次数
全连次数
全良次数
极数量
```

### 动效设计

```text
第一击：游玩次数砸下，鼓面震动。
第二击：歌曲数 / 谱面数从两侧撞入。
第三击：总时长翻牌出现。
最后补充全连 / 全良 / 极等小徽章。
```

### 文案建议

```text
这一版，
你敲响了太鼓 444 次。

487 个成绩记录，
一点点堆成了属于你的 53.3 小时。

这些数字看起来很安静，
但每一个，都是你亲手敲出来的。
```

### 视觉建议

```text
主数字必须足够大。
不要让解释文字和主数字抢视觉中心。
```

## 5.5 最爱歌曲页

### 当前问题

歌曲页容易像普通歌曲卡片，缺少“年度单曲”感。

### 改造目标

把最爱歌曲做成年度单曲揭晓。

### 动效设计

```text
1. 背景先出现模糊封面。
2. 封面从中心旋转放大。
3. 歌曲名延迟出现。
4. 游玩次数以 count-up 方式出现。
5. 最后一行文案淡入。
```

### 文案建议

```text
这一版，
有一首歌被你一次次点亮。

《mint tears》

你打了它 41 次。

也许它不是偶然出现，
而是你在某些时刻，总会回到它身边。
```

### 变体文案

如果歌曲游玩次数明显高于第二名：

```text
它不是刚好第一，
它是遥遥领先地留在了你的这一版里。
```

如果歌曲比较小众：

```text
它未必是所有人的热门，
但显然，是你的宝藏。
```

## 5.6 念念不忘歌曲页

### 当前问题

这页和最爱歌曲页容易重复。

### 改造目标

最爱歌曲强调“次数”，念念不忘强调“反复回到”。

### 数据

```text
active_days_by_song 最高的歌曲
```

### 动效设计

```text
1. 日历格子逐个点亮。
2. 每个点亮格子中出现同一首歌的小封面。
3. 最后封面汇聚成大封面。
```

### 文案建议

```text
有些歌不是一次打很多遍，
而是隔几天又会想起。

这一版，
你在 21 天里都打过《xxx》。

它像一个熟悉的坐标，
总能把你带回鼓面前。
```

---

## 5.7 太鼓关键词页

### 当前问题

关键词展示有潜力，但需要更像“玩家诊断结果”。

### 改造目标

让关键词页成为个性标签爆点。

### 动效设计

```text
1. 六维雷达图从中心绘制。
2. 六个维度依次点亮。
3. 最高维度突然放大。
4. 年度称号印章盖下。
5. 关键词文案浮现。
```

### 文案模板

```text
你的太鼓关键词是：

不熄鼓手

别人是在打一首歌，
你像是在和体力条较劲。

一次次重来之后，
鼓声还没有停。
```

### 六维文案方向

#### 大歌力

```text
你偏爱站在高墙面前，
然后把它敲碎。
```

#### 体力

```text
有些谱面靠技巧，
有些谱面靠意志。

你两个都带上了。
```

#### 高速

```text
别人还在看谱，
你已经穿过去了。
```

#### 精度

```text
你追求的不是打完，
而是每一下都刚好落在该落的位置。
```

#### 节奏

```text
你不是跟着音乐走，
你在和音乐对话。
```

#### 复合

```text
复杂配置越多，
你越像回到主场。
```

## 5.8 倍速偏好页

### 当前问题

倍速是太鼓玩家很有个性的字段，但展示时容易太工具化。

### 数据

```text
option_flg[0]
```

### 改造目标

把倍速做成“读谱习惯”标签，而不是设置项统计。

### 动效设计

```text
1. 谱面线从慢速滚动开始。
2. 页面逐渐加速到玩家最常用倍速。
3. 倍速数字像仪表盘一样锁定。
```

### 文案建议

```text
这一版，
你最常使用 1.5 倍速。

谱面变快了，
但你的节奏没有乱。

这大概就是你看世界的速度。
```

---

## 5.9 太鼓日历页

### 当前问题

日历页适合做年度总结感，但必须避免像普通热力图。

### 改造目标

把日历做成“鼓点存档”。

### 动效设计

```text
1. 日期格子从空白状态铺开。
2. 有记录的日期依次点亮。
3. 最长连续记录用光带连接。
4. 光带最后形成一个鼓面纹样。
```

### 文案建议

```text
这一版，有 74 天，
你的鼓点被记录下来。

最长连续 5 天。

没有太鼓的日子也没关系，
热爱本来就不只存在于打开游戏的瞬间。
```

---

## 5.10 活跃时段页

### 当前问题

时段页容易像简单统计图。

### 改造目标

强调玩家“把什么时间留给了太鼓”。

### 动效设计

```text
1. 24 小时时钟环出现。
2. 各时段光点依次亮起。
3. 最活跃时段扩大。
4. 对应该时段的代表歌曲封面出现。
```

### 文案建议

```text
一天有很多时刻，
但有一个时段，
鼓声出现得格外频繁。

20:00 - 21:00，
是你最常留给太鼓的时间。

人来人往，
但这一小时里，
你把一个又一个 3 分钟留给了自己。
```

---

## 5.11 深夜记录页

### 当前问题

深夜页很有潜力，应作为情绪爆点重点打磨。

### 改造目标

让它有网易云年度总结式的“被说中”的感觉。

### 动效设计

```text
1. 页面从上一页逐渐暗下。
2. 背景变成蓝紫色夜景。
3. 时间数字缓慢亮起。
4. 歌曲封面像月亮一样出现。
5. 小太鼓角色缩在角落，做轻微呼吸动画。
```

### 文案建议

```text
8 月 9 日 00:05，
夜已经很安静了。

但你的鼓声还没有停。

那一刻，
《xxx》陪你留在了今天和明天之间。
```

如果深夜次数较多：

```text
这一版，有 x 个夜晚，
太鼓陪你晚睡。
```

## 5.12 离全良最近页

### 当前问题

这是非常适合音游玩家的情绪页，应强调“差一点”。

### 数据

```text
dondaful_combo_cnt = 0
ng_cnt = 0
ok_cnt 较少
```

### 动效设计

```text
1. 进度条接近 100%。
2. 良、可、不可作为小标签出现。
3. “可”的数量被高亮。
4. 页面最后停在“只差 x 个可”。
```

### 文案建议

```text
这一版，
有一首歌离全良只差一点点。

《xxx》
只差 3 个可。

也许下一次，
它就会变成你的全良回忆。
```

---

## 5.13 挑战不放弃页

### 数据

```text
stage_delta 高
但 full_combo_delta / dondaful_delta 较低
```

### 改造目标

把失败或未完成包装成“坚持”。

### 动效设计

```text
1. 同一首歌封面重复闪现。
2. 每次挑战形成一道轨迹。
3. 轨迹逐渐向终点靠近。
4. 最后停留在歌曲封面和挑战次数上。
```

### 文案建议

```text
这一版，
你最不愿放弃的是《xxx》。

你挑战了它 32 次。

有些谱面不是一次打过的，
但每一次重来，
都在靠近答案。
```

### 当前问题

成就页要从“列出成就”升级为“高光时刻”。

### 选择优先级

```text
段位合格
全良
极
10 星全连
全连
10 星过关
首次过关
最高分刷新
```

### 动效设计

```text
1. 暗屏。
2. 日期先出现。
3. 歌曲封面从暗处翻出。
4. 成就印章盖下。
5. 金色粒子爆发。
```

### 文案建议

```text
2025 年 5 月 12 日 晚上，
你全连了《xxx》。

那一刻，
谱面没有变简单。

是你变强了。
```

## 6. 文案系统改造

### 6.1 从说明式改为三段式

所有页面文案统一采用：

```text
情绪铺垫
  ↓
数据揭示
  ↓
记忆点收束
```

### 6.2 示例改写

#### 原始说明式

```text
你最常游玩的歌曲是《mint tears》，共计 41 次。
```

#### 改造后

```text
有些歌不是路过，
是你一次次回头。

这一版，你打了《mint tears》41 次。

它大概已经很熟悉你的鼓点了。
```

---

#### 原始说明式

```text
你最常在周日打鼓。
```

#### 改造后

```text
一周有七天，
但有一天，鼓声出现得格外频繁。

周日，
是你最常留给太鼓的日子。
```

---

#### 原始说明式

```text
你在 74 天有记录，最长连续 5 天。
```

#### 改造后

```text
这一版，有 74 天，
你的鼓点被记录下来。

最长连续 5 天。

没有太鼓的日子也没关系，
热爱本来就不只存在于打开游戏的瞬间。
```

### 6.3 文案模块建议

建议新增或重构：

```text
copyGenerator.ts
```

包含：

```text
getOpeningCopy()
getProfileCopy()
getPeriodCopy()
getOverviewCopy()
getFavoriteSongCopy()
getObsessionCopy()
getKeywordCopy()
getRankCopy()
getGenreCopy()
getMonthlyCopy()
getWeekdayCopy()
getCalendarCopy()
getTimePatternCopy()
getNightCopy()
getSpeedCopy()
getNearDondafulCopy()

getPosterCopy()
```

### 6.4 文案分支策略

文案不要只有一版。建议按数据强弱分层。

例如最爱歌曲：

```text
play_count 明显高于第二名 → “遥遥领先”
play_count 只略高于第二名 → “刚好被你多看了一眼”
歌曲较小众 → “你的小众宝藏”
歌曲高热度 → “大家都喜欢，而你尤其喜欢”
```

例如深夜：

```text
深夜次数 1-2 次 → “偶尔的晚睡”
深夜次数 3-10 次 → “有几个夜晚”
深夜次数 >10 次 → “很多个夜晚”
最晚时间 < 01:00 → 普通深夜
最晚时间 >= 01:00 → 很晚
最晚时间 >= 03:00 → 极晚
```

## 7. 视觉系统改造

### 7.1 当前视觉问题

当前 demo 的浅蓝风格干净，但年度总结感不足。

问题包括：

```text
背景变化少
主视觉不够突出
页面层次偏平
太鼓元素参与度不够
关键数字缺少冲击力
最终分享页仪式感不足
```

### 7.2 章节视觉建议

#### 第一章：登场

```text
主色：彩虹、亮蓝、白光
元素：封面墙、太鼓鼓面、舞台灯
```

#### 第二章：总览

```text
主色：高亮蓝、红、金
元素：大数字、鼓点波纹、统计徽章
```

#### 第三章：偏好

```text
主色：多彩、封面色提取
元素：唱片卡、封面碎片、标签气泡
```

#### 第四章：习惯

```text
主色：蓝紫、时间渐变
元素：日历、时钟、夜景、光点
```

#### 第五章：突破

```text
主色：金色、紫色、深色背景
元素：成就印章、评级徽章、粒子爆发
```

#### 第六章：分享

```text
主色：年度主色 + 金色
元素：玩家装扮、称号条、核心数据、二维码
```

### 7.3 太鼓元素参与方式

太鼓元素不要只作为装饰，应参与动效：

```text
鼓面 → 页面转场扩散
咚/咔 → 粒子与数字跳动
鼓棒 → 划线、敲击、盖章
音符 → 背景流动
小太鼓角色 → 情绪页轻动画
封面 → 歌曲页主视觉、转场碎片
称号条 → 身份页和最终页主元素
段位徽章 → 成就页和海报高光
```

## 11. 下一版验收标准

下一版 demo 建议按以下标准验收。

### 11.1 体验标准

```text
开屏 3 秒内能建立期待
前 5 页能明显感觉不是普通统计页
至少 3 个页面有记忆点
最终称号页有收束感
分享海报值得保存
```

### 11.2 动效标准

```text
每页有入场动画
核心数字有动画
章节切换有明显转场
至少 5 个页面有专属动效
离屏动画会暂停
移动端无明显卡顿
```

### 11.3 文案标准

```text
不直接使用“你的 xx 是 xx”作为主要句式
每页至少有一句情绪化收束句
最爱歌曲、深夜、年度突破、最终称号必须有定制文案
文案不应过长，单页总字数控制在可读范围内
```

### 11.4 视觉标准

```text
页面之间有章节色彩差异
主数字足够突出
歌曲封面成为主视觉，而不是小缩略图
玩家装扮和称号真正参与身份页 / 分享页
成就页有金色或高亮反馈
```

### 11.5 工程标准

```text
不破坏现有数据计算
summary JSON 尽量兼容
页面配置可维护
动画可降级
分享图可稳定生成
```
