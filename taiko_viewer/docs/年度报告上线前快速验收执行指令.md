# 太鼓年度报告：上线前快速验收执行指令

## 0. 本轮目标

时间紧，本轮直接完成“核实当前链路 → 补齐最小测试 → 在安全环境执行 → 修复阻断问题 → 定向复测 → 输出发布结论”，不要只提交另一份测试计划。

这是发布前风险覆盖，不是无限加压。优先回答：用户能否进入、数据是否正确、集中首次访问是否阻塞、整段报告能否看完、分享能否成功、压力回落后能否恢复。

没有执行证据的项目只能写 NOT_RUN / BLOCKED，不能写 PASS。本轮不默认批准生产部署、生产高负载或破坏性恢复演练。

## 3. 环境安全与测试数据

允许自动开展：本地隔离测试、既有预发布环境内的有界负载、适用规范允许的只读检查。生产入口至多执行少量已缓存测试账户的冒烟访问；默认单并发，最多 10 条访问流程，不刷新缓存，不触发昂贵重算或批量分享。

真正隔离必须同时确认计算资源、缓存、数据写入位置、队列、对象存储、第三方回调与分析上报。不同端口、localhost、不同域名均不能单独证明隔离；连接同一生产 Redis、队列或文件目录时，不得执行冷缓存清理或故障注入。预发布与生产共机且没有可靠资源边界时，不开展自动升压。

禁止清空生产缓存、修改真实用户快照、重启线上服务、发送通知、批量写入真实用户历史或压测不在授权范围内的第三方服务。不以新增公开测试接口、放宽鉴权、绕过限流换取测试通过。对测试通知和统计上报使用隔离接收端或阻断，记录这种环境差异。

使用脱敏测试数据，至少覆盖普通、稀疏、高数据量、缺失素材及长文本情形。数据量必须有记录；高数据量样本优先采用经授权的实际高分位样本的隔离副本。为不同测试身份准备可比对的预期关键字段，不能只看 HTTP 200 或任意非空 JSON。

凭据从受保护的本地配置或环境变量读取，不进入仓库、截图、HAR 或报告。日志中的用户标识脱敏。清理仅针对本轮拥有的 fixture、缓存命名空间和临时文件。

没有可用隔离环境时，继续完成静态检查、脚本和安全冒烟；将容量验证标记 BLOCKED，不花本轮时间搭建大型监控/容器平台，也不强压现网。

## 4. P0：先确保业务流程和既有回归通过

复用现有工具链，先运行契约检查、类型检查及与改动相关的测试。测试目标应是固定生产构建，不把开发服务器结果作为生产容量结论。

浏览器主链路：进入报告 → 获取自己的年度数据 → 正常浏览全部当前页面 → 到达最终页 → 实际完成分享或导出。普通用户全流程完成后，补充稀疏用户与高数据量用户；素材缺失和长文本可采用隔离 fixture。

必须校验用户/版本归属、关键统计正确、加载状态可结束、无未处理异常、无核心资源缺失。数据归属优先通过现有字段或已知 fixture 的独特关键值检查，不为了断言给生产响应新增字段。

分享测试要取得最终有效图片或其他实际产物，检查可解码、尺寸合理、字体/曲绘/装扮加载完成、无明显空白，不以按钮点击成功或任务返回 200/202 作为终点。端内保存、系统分享面板和社交应用行为无法自动验证时，单独列出真机项。

错误注入只发生在单个测试浏览器上下文或隔离服务中：一次 API 超时、一次图片失败、短暂离线再恢复。检查有限重试、明确反馈、恢复后可以继续，不修改生产网络或真实服务。

## 5. P0：最小负载矩阵

优先使用已有工具；已有 k6 则复用，没有时补充小型独立测试脚本，不搭建新的负载平台。工具缺失可以交付可执行脚本及明确阻塞，但不能把另一个工具的简单循环伪装成到达率模型。

### 5.1 流程定义

协议层一次 iteration 定义为一条明确的年度访问事务：按实际入口完成鉴权/数据获取，必要时执行有上限的轮询，直到取得可用 summary 或失败。报告写清包含及未包含的请求。

使用到达率时，rate 表示每个 timeUnit 启动的 iteration 数，并不天然等于 HTTP RPS，更不等于同时在线人数。[R1] 记录目标与实际启动数、完成数、失败数、未完成数、HTTP 请求数及 dropped_iterations；给出真实到达率和请求吞吐量。

静态资源和完整浏览器体验另测，不将一条 JSON 请求标为完整网页访问。采用少量浏览器实测冷/热加载与资源大小；未经授权的 CDN/第三方不加入批量压测。缺少真实出口带宽或 CDN 链路时说明覆盖边界。

### 5.2 必须分别执行的场景

| 场景 | 执行动作 | 必须留下的证据 |
|---|---|---|
| 缓存读取 | 多个已缓存测试身份轮换读取 | 命中依据、身份正确、延迟与实际吞吐量 |
| 不同用户首次访问 | 隔离数据中至少准备 30 个不同的未生成用户；先低速开始，样本用完即停止 | 首次生成次数、耗时、CPU/内存/IO、实际冷请求数量 |
| 同一用户同时首次访问 | 独立未生成 fixture，先 2 个再最多 5 个同步请求 | 真实执行次数、重复计算/排队情况、结果一致性 |
| 突发进入 | 已通过的低负载快速提高，再回落 | 过载反馈、积压和恢复，不只统计高峰 |
| 分享 | 按真实实现测试重复点击、两名不同测试用户；服务端生成须有硬并发上限 | 最终产物、去重/排队行为、任务清理 |

“第一次请求后都命中”的循环不能命名为冷缓存压测。必要时在独立测试缓存/数据根目录准备全新 fixture；不得通过随机查询参数假装后端缓存失效。仅证明缓存命中不等于证明计算执行次数，无法观测时如实写未验证。

### 5.3 建议探测档位

以下是本轮测试配置建议，不是流量预测，也不是已确认容量。只在前述隔离与监控条件满足、低负载健康时执行；允许基于实际耗时和资源约束调低，并写明理由。

| 阶段 | 初始配置 |
|---|---|
| 冒烟 | 1 个虚拟用户，逐个跑通各分支 |
| 热缓存基线 | 1 条数据访问事务/秒，持续 2 分钟 |
| 热缓存升压 | 3 条/秒持续 3 分钟；通过后 5 条/秒持续 5 分钟 |
| 短突发 | 5 条/秒已通过后，最多 10 条/秒持续 1 分钟；随后 1 条/秒观察 3 分钟 |
| 冷路径 | 先串行，再最多 1 条首次生成事务/秒，使用不重复 fixture；不直接套用热缓存最高档 |
| 重复播放 | 浏览器完整播放 3 轮，随后执行约 30 次前后切页 |

每档有独立结果，默认顺序运行，不同时叠加。虚拟用户数、请求超时、轮询次数、分享并发、最长运行时间均设硬上限；到达率所需 VU 根据已测耗时配置，但不能无限扩展。

k6 的 dropped_iterations 表示计划中的部分迭代未执行；在到达率场景中可能因 VU 不足，也可能与被测系统变慢有关。[R2] 出现丢弃时检查负载机和服务端，不能把未施加足够负载后的低错误率写成目标容量通过。

若有既有访问日志，优先从日志估算有依据的发布目标，再调整上述档位。缺少发布目标时，结论只能写“已验证至某档探测负载”，不得宣称足够承受全部上线流量。短测也不代表长时间稳定性已验证。

## 6. P0：移动端与 weekday 专项

复用 Playwright 或现有浏览器回归。不更换页面设计，不删除文案，不以强制 requestFullscreen、强制收起地址栏或全局缩小字体作为默认补丁。

既往用户反馈 weekday 在 iOS 浏览器工具栏占用高度时会遮挡文案，且页面主体的宽度比例必须保持。既往采样出现 innerHeight、visualViewport、documentHeight、sceneHeight 均为 567；这只是已知复现线索，不是当前已测结果，也不能证明所有子元素未溢出。

使用明确的 CSS 视口尺寸，例如 375×567、375×667、390×844，并补充当前项目最小支持宽度。覆盖进入 weekday、前后切页返回、窗口高度收缩再恢复；使用实际长文案 fixture。对最终稳定显示状态检查必读文字、按钮与 footer：元素边界、祖先 overflow 裁剪、重叠遮挡和可点击区域。保留关键截图，不能只断言 scene.height 等于 viewport.height。

对全部场景做基本可达性和异常检查；重点回归 weekday、FavoriteSong/对应当前页面、最终称号页、分享页。检查重播、快速翻页后的动画与事件清理；内存以相同采样方式的趋势及稳定平台分析，不能以任意一次 GC 前后数值断言泄漏。

自动化 WebKit 不等于真实 Safari，Playwright 使用的是经适配的 WebKit 构建。[R3] 真机项目单列：iOS Safari 地址栏/底部栏展开与收起、后台/锁屏恢复、实际分享保存，以及主要内置浏览器。没有设备时写 NOT_RUN，并交付最短复现步骤；不得勾选为已通过。

已知遮挡问题的发布前真机回归属于关键证据；自动化修复通过但没有真机验证，整体不能标为完全通过。

## 7. 门槛、监控与停止规则

以下数值是本轮建议的初始验收门槛，应在测前冻结。可以在首次测试前根据已有项目目标或真实链路声明不同门槛并解释；不得测试失败后为通过而静默放宽。

| 类别 | 建议判据 |
|---|---|
| 正确性 | 身份/版本正确，关键字段及最终产物符合 fixture；出现串用户立即停止并列 P0 |
| 功能冒烟 | 所有必测流程通过；少量样本不声称可估计长期可用性 |
| 热缓存目标档 | P95 ≤ 800 ms，P99 ≤ 2000 ms；有效业务事务观察成功率 ≥ 99.5% |
| 冷生成/服务端分享 | 从当前产品等待上限与基线事先确定独立时限；轮询和排队时间计入端到端耗时 |
| 目标负载有效性 | 无 unexplained dropped iterations；报告样本数及负载是否实际达到 |
| 资源 | 无 OOM、非预期重启、无持续累积且无法回落的队列；不影响共机业务 |
| 恢复 | 降压后延迟和积压回到预先记录的基线范围；采样不足时结论受限 |
| 移动端 | 必读文字/按钮可见可用，无阻断性裁剪、空白或无法继续；真机证据单独登记 |

成功率采用“有效业务事务”的分母，明确重试、错误响应和未完成事务如何计入。负面测试中的预期 404/超时另建场景，不混入正常流量成功率。同时报告首次尝试成功率，避免重试隐藏故障。分位数按场景分开，冷生成、缓存读取、分享不能混合平均。

k6 的 check 失败本身不使整次测试自动失败；把关键 checks/custom metrics 与 thresholds 关联，并验证失败时返回非零退出码。[R4] thresholds 可设置 abortOnFail 和 delayAbortEval；这不是宿主机内存保护，也不要将累计阈值误写成“最近 30 秒滑动窗口”。[R5]

压测前记录负载机和被测机的 CPU、可用内存/容器限额、进程 RSS、Swap 活动、磁盘 IO/空间、网络、重启次数及队列（如存在）。使用现有监控或轻量采样，注明缺失项。

实现以下停止保护：串用户立即停；出现 OOM、非预期重启或其他线上业务健康恶化立即停；正常流量累计错误率超过预设安全线时提前中止，例如预热宽限 30 秒后累计 >5%；请求、轮询与整个测试都有硬超时。宿主机/cgroup 资源危险线在开测前根据实际限制配置，监控进程与负载进程独立，资源告警停止本轮负载生成器，不杀生产服务。

没有可靠服务端可观测性时不继续自动升压。停止后仍观察未完成任务及资源回落，保留失败证据，不自动无限重试。脚本退出和手动中断均清理本轮测试子进程，不能误杀其他会话。

## 8. 修复与发布恢复检查

发现阻断项后采用“最小修复 → 对应用例 → 核心冒烟 → 必要负载档位复测”。不让测试工作演变成整个年度报告改版。

在不部署生产的前提下检查：新构建所需静态资源是否齐全、HTML 与资源版本是否匹配、旧页面是否可能请求已删除的 chunk、实际缓存策略、现有回滚入口与上一版构建可用性。可在隔离环境演练旧页面访问新部署资源、失败后重试与回滚；未实际回滚只能写“回滚步骤已检查”，不能写演练成功。

长时间稳态、全面机型矩阵、极限容量与复杂故障演练列为后续覆盖项。本轮不为这些项目推迟 P0 的执行，也不得声称已经覆盖。

## 9. 最小交付物与最终回复

优先新增或扩展少量现有测试文件，不要求为了命名复制另一套框架。至少交付：

- 可运行的负载脚本、最小配置样例和安全启动入口。必要输入缺失即拒绝高负载启动，默认不得指向生产。鉴权、账户集与 URL 使用实际发现的配置方式。
- 扩展后的浏览器/契约回归及关键失败截图；私密数据和凭据不进入可提交产物。
- `docs/annual-release-readiness.md`：环境、命令、场景、原始结果路径、缺陷与修复、未测项、发布结论。大型原始日志放在被忽略的 artifacts 目录，报告提供相对位置。

最终回复固定包含：

1. **结论**：PASS / LIMITED / BLOCKED。PASS 仅在本轮必测项（含所需真机证据）通过、实际发布目标有依据且达到时使用；LIMITED 表示已验证有边界的范围；BLOCKED 表示存在阻断缺陷或核心验证无法完成。不得把 LIMITED 等同正式上线批准。
2. **已执行证据**：构建、环境、测试账户集、真实命令、日期、各档位实际到达率/请求量/样本数、成功率、P95/P99、资源峰值、恢复情况、dropped iterations 和未完成事务。
3. **修改**：变更文件、修复理由、复测结果；没有修复不伪造提交。
4. **缺口**：NOT_RUN/BLOCKED 项、原因，以及解除阻塞所需的具体条件。缺真机、缺隔离环境、缺发布目标分别列出，不能笼统写“基本通过”。
5. **发布边界**：已经证明的能力、未证明的能力、建议的入口节奏与降级/回滚措施。只有建议，没有权限时不自动变更生产。

现在开始执行：先核实仓库与环境安全，随后跑现有检查和主链路冒烟，边执行边补齐负载和移动端回归。不要停留在计划阶段，不要求用户重新提供可以从工作区自行读到的信息；需要额外权限的项目单独标记，继续完成其余安全部分。
